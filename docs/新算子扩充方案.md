# 新算子扩充方案

文档状态：已实施第一部分 制定日期：2026-07-21

适用范围：当前 O10-O18 无法覆盖的结构性能力边界

前置条件：可信度机制已稳定，现有算子资格实验已可区分 Prompt、Router、数据和模型问题

目标读者：负责 operator 设计、专用数据建设、Prompt、Schema、Router 和资格实验的评测与工程人员 读完后应能完成：分别实现新算子的内容定义与校准/机制契约，并能判断一项改动应归入哪一部分

## 1. 文档边界

本方案拆成两个职责独立的部分：

1. 第一部分：新算子内容设计 定义 O19-O27 各自测什么、保留什么推理负担、题面如何构造、内容如何变换、目标错误是什么，以及与现有算子的语义边界；并完成稳定 operator ID 的基础注册、现有 Router 的规则识别和生成 Prompt 调用接线。该部分不定义事实 Schema、结构化输出、scorer 映射、资格状态、硬拒绝、路由质量或发布决策。
2. 第二部分：校准与机制优化 定义第一部分的内容要求如何转为事实 slot、结构金标、answer contract 和 scorer 映射，以及专用数据、Router 适用性契约与质量校准、forced qualification、shadow routing、natural holdout、启用门槛、发布校验和回滚机制。基础注册、现有 Router 可识别和生成调用不再延后到第二部分。

第一部分可以独立完成 operator spec、Prompt、基础注册和现有 Router 调用。如需人工审核，可保存审核关注点和备注，但这些记录只供后续人工查阅，不作为准入、排序、重试、拒绝、路由、评分、状态迁移或发布的判断依据。结构化产物、机器校验和正式流量启用必须在第二部分实现。第一部分中的"必须"和"不得"只表示算子内容和 Prompt 构造要求，不自动等于程序化 blocking 规则；第一部分的可调用也不表示算子已经通过资格或可以进入正式流量。

## 2. 方案摘要

当前 O10-O18 主要围绕"一个事实如何改变一个命题"设计。通用场景下的多类型测试结果/exp 显示 PoliceQA 场景中还存在一组无法被该范式稳定测量的能力：

1. 多实体身份与角色绑定；
2. 多阶段事件链断点定位；
3. 物品来源和同一性连续追踪；
4. 多摄像头路径拓扑与联合可达性；
5. 观测质量与事实可靠性；
6. 多假设的覆盖、冲突与残差排序；
7. 程序不变量和参照系一致性；
8. 定量阈值、容差和误差传播；
9. 观察事实、证据支持、事实认定和行动门槛的跨层校准。

本方案建议新增 O19-O27 九个 operator family。算子内容可按能力缺口独立设计；校准、分批资格化和启用节奏由第二部分决定。

## 3. 为什么不应继续扩展 O10-O16

将新能力不断写成 O10、O12、O15 的例外会产生三个问题：

1. 错误不可归因：多实体绑定错误被记成"证据增强方向错误"。
2. 语义同构：不同算子最终都变成找唯一差异、判断增强/减弱。
3. 数据契约混乱：路径拓扑、误差传播和物品 provenance 需要完全不同的结构化事实。

新 operator ID 的内容准入原则是：

- 核心错误无法在不丢失归因性的前提下，表达为现有 operator 的 target error taxonomy。

该原则在第一部分用于划定语义边界并保护基础 registry 中的 ID 唯一性；是否具备资格和允许进入正式流量，由第二部分的资格机制决定。

## 4. 目标与非目标

### 4.1 目标

1. 为每个结构性能力建立独立、稳定、可归因的 operator 内容定义。
2. 为每个新算子定义专属的推理对象、内容变换、不变量和目标错误。
3. 在内容层明确新算子与相邻现有算子的语义边界。
4. 在机制层为每个新算子建立专用事实 Schema、结构金标、answer contract、Router 契约和资格报告。
5. 通过能力缺口数据池驱动新算子建设，不用场景名称代替事实前置。

### 4.2 非目标

1. 候选集合的数量不设固定限制。每个候选开始进化时，从可用算子中选取一个 operator；该候选的本次进化只执行这一个 operator，但不强制生成题只包含单一语义轴。
2. 不为了扩充 operator 数量而拆分只有表面差异的新 ID。
3. 不将算子的专用数据前置交给生成模型编造。
4. 不在本阶段进行无限深度树搜索、多 operator 联合执行或多 operator 联合评分。
5. 不通过语义轴、候选项、反事实、事实、节点或任务的固定数量门槛决定准入、排序或重试。

# 第一部分：新算子内容设计

## 5. 通用内容原则

### 5.1 多轴内容要求

每个 operator 生成的题目可包含多个事实、节点、主体、因素、假设、候选项、反事实、推理任务和语义能力轴。算子内容不规定这些对象的固定数量、上限或下限，也不使用数量作为成题条件。

一道题同时涉及多个语义能力轴时，operator spec 应分别说明各轴的推理任务、目标错误、结论边界和轴间的内容依赖。这里只定义算子内容应表达什么，不定义字段映射、分轴评分、契约检查、候选拆分或重新生成机制。

### 5.2 保留结构推理负担

新算子的难度必须来自实体关系、状态转移、来源链、路径拓扑、观测可靠性、假设残差、程序不变量、定量区间或结论层级。题面不得预先给出完整关系结构、目标错误标签或可直接复述的答案链。

### 5.3 竞争性而非格式难度

不使用主体名称长度、列表数量、表格格式、节点数量或多个输出任务制造难度。候选关系、假设、路径、基线或结论层级必须具有真实竞争性。

### 5.4 隐藏控制不泄漏到题面

以下信息可供生成器做内容设计，但不得直接出现在题面：

- operator ID 和能力轴；
- 内部内容设计说明或目标错误标签；
- 预期正确方向；
- "改变的边"、"断点"、"残差最小"等内容构造说明；
- 预期弱模型失败。

是否以及如何结构化保存这些内部信息，由第二部分规定。

最终题面原则上只提出一个自然业务判断和开放式依据要求。实体绑定、图结构、链路断点、路径约束、观测可靠性、覆盖-冲突-残差、程序不变量、误差传播和结论层级都是生成器内部的推理任务与答案结构，不得改写成"逐项说明""分别列出""先……再……"或轴名称清单替回答者预先分解问题。

### 5.5 统一内容定义模板

每个新算子的 operator spec 使用以下内容模板：

1. 能力轴：该 operator family 稳定测量的结构性能力；同一 family 内可定义和承载多个可区分的语义轴。
2. 推理对象：实体关系、事件图、来源链、路径图、观测声明、假设矩阵、程序不变量、数值区间或结论层级。
3. 适用内容场景：能自然承载该推理对象的场景表面。
4. 题面构造：回答者可见的事实、候选关系和任务。
5. 内容变换：生成器在语义上交换、删除、替换、重排或扰动什么。
6. 内容不变量：在内容变换前后必须保持的实体、时间、事件、图结构、规则或目标命题。
7. 目标错误：本算子希望识别的具体错误；多轴题中不同轴的错误不得合并为一个泛化错误标签。
8. 禁止捷径：不得使用的表面线索、显性标签或完整答案链。
9. 相邻边界：与现有或新算子之间的内容分工。
10. 内容控制：正控制、结论不变负控制和表面交换控制如何构造。

## 6. O19 内容设计：多实体角色绑定

### 6.1 能力轴与推理对象

在包含多类实体和观测节点的场景中，稳定维持实体身份、关系方向和事件角色；在实体或角色绑定发生交换后正确更新结论。推理对象是实体-观测节点-关系-角色图。

### 6.2 适用内容场景

- 接应人员与主要行为人；
- 掩护者与实施者；
- 人员、车辆和物品的跨镜头绑定；
- 多场所重复出现中的角色连续性。

### 6.3 题面、变换与不变量

题面同时提供同类实体、观测节点、局部关系和目标关系命题，不规定实体或节点数量。内容变换围绕同类实体的节点绑定或事件角色进行；与目标能力无关的观测时间、事件动作、目标关系类型和题面信息保持不变。

题面只询问现有材料对目标关系或角色能够支持何种判断及依据；节点到实体的绑定、关系方向和局部关系能否扩展到整个事件保留为内部答案结构。

### 6.4 目标错误与边界

- entity_merge：将相似实体错误合并；
- entity_swap_ignored：忽略主体交换；
- role_direction_reversed：将掩护/实施、转出/承接等方向写反；
- local_binding_overgeneralized：将单节点关系扩展到整个事件。

O10 测事实组合的证明力；O19 测多节点事实应绑定到哪个实体和角色。如果不需要维持实体身份就能作答，不属于 O19 的内容边界。

## 7. O20 内容设计：多阶段事件链断点

### 7.1 能力轴与推理对象

在准备、接触、状态变化、转移和结果等多阶段中，找到使完整事件链无法闭合的节点或边。推理对象是带时序、实体绑定和状态前后变化的事件图。

### 7.2 适用内容场景

- 物品取出、转移、承接和查获；
- 行为准备、启动、中断和结果；
- 证据固定链中的缺失状态；
- 交通事件中的前置动作与后果。

### 7.3 题面、变换与不变量

题面呈现有序事件节点、节点前后状态、实体绑定和必需转移边，不规定节点或转移边数量。内容变换可删除、替换或重排与目标推理相关的状态转移节点/边；与目标能力无关的节点、实体绑定和目标链命题保持不变。

题面只询问现有事件材料能否支持目标链路及依据；失效节点或边、仍成立的局部链、后续不可推出的状态，以及证据不完整与反证的区分保留为内部答案结构。

### 7.4 目标错误与边界

- wrong_breakpoint；
- state_transition_skipped；
- temporal_edge_reversed；
- partial_chain_treated_as_complete；
- missing_node_filled_by_assumption。

O13 在多个新增事实中找破坏某个必要连接的最小事实；O20 维护一个显式多阶段状态图，判断哪个节点/边使整条链断裂。

## 8. O21 内容设计：物品来源与同一性追踪

### 8.1 能力轴与推理对象

在相似物品、遮挡、位置变化、多次转移和竞争来源存在时，判断目标物品的同一性连续是否成立。推理对象是物品-属性-位置-转移-竞争来源链。

### 8.2 适用内容场景

- 物品从取出、交接到查获的连续性；
- 多个外观相似包装或容器；
- 遮挡前后物品来源竞争；
- 不同人员之间的多次承接。

### 8.3 题面、变换与不变量

题面提供候选物品、可观察属性、位置时序、转移事件、遮挡区间和竞争来源，不规定候选物品、转移或来源数量。内容变换围绕物品绑定、遮挡后重现对象或竞争来源进行；与目标能力无关的时序、人员动作和目标同一性命题保持不变。

题面只询问目标物品的同一性能够支持到何种程度及依据；连续支持、竞争来源、转移缺口和观测不足之间的比较保留为内部答案结构。

### 8.4 目标错误与边界

- appearance_only_identity：只凭相似外观认定同一；
- transfer_gap_ignored；
- competing_source_ignored；
- person_binding_substituted_for_object_binding；
- occlusion_filled_by_assumption。

O19 主要维护人/车/物的实体与角色绑定；O20 主要定位事件链断点；O21 专门处理物品同一性在多次转移和竞争来源下的连续性。

## 9. O22 内容设计：路径拓扑与联合可达性

### 9.1 能力轴与推理对象

综合入口、出口、路网、时间窗、速度范围和候选路径，判断某个身份或路径连续假设是否在拓扑上可达。推理对象是带时间窗和通行范围的路径图。

### 9.2 适用内容场景

- 多摄像头身份连续；
- 盲区前后候选路径；
- 多入口、多出口楼栋或区域；
- 伙伴车辆伴随和重合路径。

### 9.3 题面、变换与不变量

题面提供图节点、可用边、观测端点、时间窗、通行时间范围和候选路径，不规定节点、边、端点或路径数量。内容变换可调整与目标推理相关的边可用性、端点时间窗或候选路径约束；与目标能力无关的网络结构、端点身份和目标可达性命题保持不变。

题面只询问目标路径或身份连续假设是否成立及依据；拓扑可达性、时间窗和端点身份的联合检查保留为内部答案结构，生成器须避免让某条路径因单一明显差异轻易胜出。

### 9.4 目标错误与边界

- topology_ignored；
- unreachable_path_selected；
- travel_window_violation；
- endpoint_identity_mixed；
- single_path_assumed_without_exclusion。

O11 判断不可见区间假设与端点时序是否一致；O22 要求显式处理路径拓扑和联合可达性。二者的边界由是否必须建立路径图并联合检查拓扑、时间窗和端点身份决定，不由入口、出口或路径数量决定。

## 10. O23 内容设计：观测可靠性冲突

### 10.1 能力轴与推理对象

在清晰度、遮挡、视角、夜间条件和相似物存在时，判断某个所谓"已观察事实"的可见性与可靠性是否足以支持后续推理。推理对象是观测声明-可见特征-质量限制-下游命题关系。

### 10.2 适用内容场景

- 无清晰人脸的身份比对；
- 模糊物品和相似包装；
- 夜间、遮挡、反光或大视角画面；
- 只能看到部分动作的行为性质判断。

### 10.3 题面、变换与不变量

题面提供观测声明、可见特征、画面质量条件、遮挡/视角限制、竞争观测和下游命题，不规定观测或质量因素数量。内容变换可调整与目标推理相关的观测质量或可见特征条件；事件本身和下游命题保持不变。

题面只询问现有观测能够支持何种下游判断及依据；可观察性、可区分性、质量限制和对下游命题的影响保留为内部答案结构。

### 10.4 目标错误与边界

- visibility_assumed；
- similarity_treated_as_identity；
- quality_limit_ignored；
- observation_uncertainty_skipped；
- downstream_claim_overstated。

O10/O15 默认输入事实本身已成立；O23 测量的就是该事实是否真的可从观测中获得。

## 11. O24 内容设计：多假设残差排序

### 11.1 能力轴与推理对象

在能解释部分事实的竞争假设中，按覆盖事实、冲突事实、未解释残差和额外假设成本进行排序。推理对象是假设的覆盖-冲突-残差矩阵，不规定假设、事实、冲突或残差数量。

### 11.2 题面、变换与不变量

题面呈现具有真实竞争力的假设、共享事实集和统一排序原则，不规定假设或区分因素数量。内容变换可增加、替换或调整与目标推理相关的可观察 discriminator；与目标能力无关的假设、共享事实集、排序原则和目标任务保持不变。

题面只询问当前材料下哪个解释更可取或应如何排序及依据；各假设的覆盖、冲突、残差和额外假设成本保留为内部答案结构。竞争假设不得存在语义支配关系，也不得由单一事实或"更正常/更可疑"标签轻易决定排序。

### 11.3 目标错误与边界

- single_fact_dominance；
- coverage_conflict_tradeoff_ignored；
- residuals_not_compared；
- extra_assumption_cost_ignored；
- plausibility_label_substituted_for_evidence。

O16 聚焦目标解释与相近正常解释之间的 discriminator；O24 要求同时维护竞争假设的覆盖-冲突-残差结构，二者的边界不由假设数量决定。

## 12. O25 内容设计：程序不变量与参照系

### 12.1 能力轴与推理对象

在坐标、标注、测量、记录和软件录入等程序中，维持参照系、尺度、角度、命名和步骤依赖不变。推理对象是程序步骤-参照系-单位-记录映射之间的不变关系。

### 12.2 适用内容场景

- 现场坐标原点与尺寸记录；
- 人像标志点和标志线；
- 镜头几何、姿态对齐和尺度归一；
- 原始记录与软件录入的映射。

### 12.3 题面、变换与不变量

题面提供程序步骤、参照系、测量单位、顺序依赖、记录映射和目标可比性命题，不规定步骤、参照系、单位或映射数量。内容变换可调整与目标推理相关的参照系、单位、步骤顺序或记录映射；与目标能力无关的观测、对象和目标比较保持不变。

题面只询问相关测量或记录是否仍可比较及依据；被破坏的不变量及其对可比性的影响保留为内部答案结构。

### 12.4 目标错误与边界

- reference_frame_mixed；
- unit_inconsistency；
- order_dependency_ignored；
- record_mapping_shifted；
- non_comparable_measurements_compared。

O25 不是通过增加证据改变结论，而是判断测量和记录程序的结构不变量是否被破坏，因此不属于 O10/O12 的内容边界。

## 13. O26 内容设计：定量阈值与误差传播

### 13.1 能力轴与推理对象

根据题面明示的区间、容差、误差上界、速度范围和判定阈值，推导结果区间并判断是否跨过门槛。推理对象是带单位、不确定区间、变换规则和决策阈值的定量关系。

### 13.2 适用内容场景

- 车辆反应和通行时间；
- 现场坐标和尺寸测量；
- 摄像头时间偏差；
- 基线范围和异常阈值。

### 13.3 题面、变换与不变量

题面明示观测值、单位、不确定区间、变换公式/规则、决策阈值和目标定量命题，不让回答者从常识补齐公式、参数或阈值，也不规定观测值、区间或因素数量。内容变换可调整与目标推理相关的观测值、不确定区间或门槛距离；与目标能力无关的单位、公式和观测保持不变。

题面只询问目标定量判断是否成立及依据；结果区间、单位换算、不确定性传播和区间与阈值的关系保留为内部答案结构。公式、参数和阈值仍须明示，以避免要求题外常识，但不得把计算步骤写成作答流程。

### 13.4 目标错误与边界

- point_estimate_only；
- uncertainty_not_propagated；
- unit_conversion_error；
- threshold_crossing_overstated；
- interval_overlap_ignored。

O18 判断选择哪个基线口径；O26 在口径已给定后计算或推理误差区间与阈值关系。

## 14. O27 内容设计：跨层结论校准

### 14.1 能力轴与推理对象

区分并正确映射以下层级：

```text
观察事实
→ 证据支持度
→ 事实命题成立度
→ 可写结论范围
→ 行动或处置门槛
```

目标是检测模型是否将下层变化无条件上推为高层结论翻转。

### 14.2 适用内容场景

- 证据减弱与事实不成立的区分；
- 可疑线索、高度怀疑和可写结论的分层；
- 事实判断与处置规则的范围区分；
- 局部推理连接失效与整体命题翻转的区分。

### 14.3 题面、变换与不变量

题面明示相关结论层级、允许的跨层规则或门槛、当前证据状态和目标层级，不规定层级、证据状态或推理连接数量。内容变换可调整与目标推理相关的低层证据状态或局部推理连接；与目标能力无关的跨层规则和证据保持不变。

题面只询问当前变化对目标结论能够产生何种影响及依据；变化层级和是否存在合法向上传导规则保留为内部答案结构。

### 14.4 目标错误与边界

- evidence_drop_treated_as_claim_false；
- local_link_failure_treated_as_global_reversal；
- suspicion_promoted_to_fact；
- fact_support_promoted_to_action_threshold；
- layer_specific_rule_ignored。

O13 定位破坏必要连接的事实；O27 判断该局部变化能否跨层影响更高结论。O15 测同一被比较量的反事实迁移；O27 测不同结论层级之间的合法映射。O17 比较题面明示双规则时的处置和事实范围；O27 更广泛地检测跨层过度上推。

## 15. 第一部分交付物

每个新算子的内容交付物包含：

1. 该算子可承载的语义轴和推理对象；
2. 适用内容场景和题面构造方式；
3. 内容变换和内容不变量；
4. 目标错误、禁止捷径和相邻算子内容边界；
5. 正控制、结论不变负控制和表面交换控制的内容模板；
6. 不泄漏内部内容设计说明和目标错误的生成 Prompt；

## 16. 新 Operator 机制契约

### 16.1 统一契约结构

```json
{
  "operator_id": "O19_multi_entity_role_binding",
  "semantic_version": "1.0",
  "prompt_version": "o19_prompt_v1",
  "applicability_version": "o19_applicability_v1",
  "validation_policy_version": "new_operator_validation_v1",
  "status": "qualification_only",
  "ability_axes": ["entity_binding_under_swap", "role_direction_consistency"],
  "target_error_taxonomy": [],
  "required_fact_slots": [],
  "transformation_contract": {},
  "invariants": [],
  "operator_payload_schema": {},
  "answer_contract_schema": {},
  "scorer_mapping": {},
  "neighbor_operators": [],
  "routing_exclusions": [],
  "release_checks": []
}
```

统一机制规则：

1. 所有 required slots 来自事实账本或可追溯的来源 manifest，不由生成模型补造。
2. 结构金标和 operator payload 在题面外保存，Blind Solver 不可看见。
3. operator_payload_schema 保存算子专属结构，不强行统一为单事实变换。
4. answer contract 由结构金标和 Blind Solver 解算结果一致后冻结。
5. scorer_mapping 只将结构化答案映射到 Rubric 项，不得改变第一部分的能力轴、目标错误或结论边界。
6. 新算子在资格实验通过前不进入主 fallback。
7. 候选集合、语义轴、实体、因素、候选项、反事实、事实、节点和任务不设固定数量上限或下限。如保存数量字段，均为 record_only，不参与准入、排序、重试或拒绝。
8. 人工审核关注点、备注、审核人和时间可写入 manual_review_record，但该记录整体为 record_only，不参与 Router、validator、scorer、资格状态、回滚或发布决策。

### 16.2 通用输出 Envelope

每个新算子候选的公共 envelope 至少包含：

```json
{
  "candidate_group_id": "...",
  "candidate_id": "...",
  "selected_operator_id": "O19_multi_entity_role_binding",
  "semantic_version": "1.0",
  "prompt_version": "o19_prompt_v1",
  "axis_assignments": [
    {
      "axis_id": "axis_entity_binding",
      "semantic_ability_axis": "entity_role_binding_under_swap",
      "source_fact_ids": [],
      "target_claim": "",
      "operator_payload": {},
      "answer_contract_id": "sha256:...",
      "rubric_item_ids": []
    }
  ],
  "axis_interactions": [
    {
      "source_axis_id": "axis_entity_binding",
      "target_axis_id": "axis_role_direction",
      "relation": "constrains_role_direction",
      "interaction_contract_id": "sha256:..."
    }
  ],
  "manual_review_record": {
    "review_targets": [],
    "notes": [],
    "reviewer": null,
    "reviewed_at": null
  },
  "generation_prompt_hash": "sha256:..."
}
```

candidate_group_id 标识同一输入开始时的候选集合。该集合可保存任意有限数量的候选，方案不规定固定数值上限；候选数量仅作运行记录，不作为内容合格性或效果判断依据。

selected_operator_id 是当前候选开始进化时选取的唯一算子。不同候选可以选取不同 operator，但每个候选的一次进化不得混用或切换 operator。整个候选共用该算子的 semantic version 和 prompt version；axis_assignments 只拆分该算子内部的语义轴，不得引用其他 operator ID。每个轴都必须有独立 axis_id、目标命题、payload、answer contract 和 Rubric item 映射。

axis_interactions 只记录题目中实际存在的轴间依赖。每个交互必须指明方向、关系和独立 interaction contract；不得以"综合能力"作为无结构的兜底标签。

operator_payload 必须按 selected_operator_id 的 semantic version 解析、持久化和回放。未知字段不得静默丢弃；缺少任一已声明轴的必需 payload 时，该轴不得进入资格实验。候选级联合总分只可作为补充指标，不得代替分轴结果。

manual_review_record 只保存供后续人工查阅的信息。该字段缺失、为空或包含任何审核意见，都不改变候选的流程状态和机器判定结果。

## 19. Router 机制扩展

Router 先识别事实结构，再选择 operator ID：

```text
单事实-单命题
多实体-角色图
多阶段-状态转移图
物品-来源链
路径-拓扑图
观测-可靠性层
多假设-覆盖矩阵
程序-不变量
定量-区间与阈值
结论-层级映射
```

路由冲突原则：

1. 优先选择能直接表达核心错误的 operator，不选择更泛化的 O10/O15。
2. 候选集合的数量不设固定数值限制。如果样本同时满足多个 family，Router 可为不同候选保留不同的 eligible operator。
3. 每个候选开始进化前，必须从该候选的 eligible operator 中选定一个 selected_operator_id。候选进入生成后不混用、增选或切换其他 operator。
4. 选定 operator 后不强制单主轴；生成内容可以声明该 operator 边界内的多个 semantic_ability_axis，但这些轴不得引用其他 operator ID。
5. 已选 operator 的核心必需 slot 缺失时，当前候选返回 not_applicable，不在该候选的同一次进化中 fallback 或改选其他 operator。某个非核心语义轴的必需 slot 缺失时，只有在移除该轴后题面、核心变换和其他轴契约仍完整时才可继续；否则结束当前候选。
6. 未通过资格的 family 只输出 shadow 结果，不控制主链。

## 20. 资格化、状态与启用

### 20.1 资格流程

```text
能力缺口样本收集
→ 专用事实 Schema 和结构金标
→ operator contract 与 Prompt 原型
→ 调参集迭代
→ forced qualification holdout
   ├── 失败：修改 Prompt/contract 或驳回 operator 假设
   └── 通过：qualification_only → shadow_routing
→ natural routing holdout
   ├── 路由不稳定：保持 shadow
   └── 通过：shadow_routing → enabled
→ 小规模主链实验
→ 满足机制指标后正式纳入
```

### 20.2 状态语义

- draft：契约和数据尚未完成。
- qualification_only：只允许强制资格实验。
- shadow_routing：Router 输出结果，但不控制主链。
- enabled：可被 Router 选为某个候选本次进化的唯一 operator。
- suspended：发现契约或数据问题，停止新实验但保留历史产物。
- retired：能力轴被其他算子完整覆盖或假设被证伪。

## 21. 校准指标与启用决策

### 21.1 生成可信度

- 事实来源完整率；
- 结构金标与 answer contract 一致性；
- Blind Solver 一致率；
- 题外事实和题外规则率；
- 表面泄漏风险；
- 与相邻 operator 的语义同构率。

### 21.2 能力区分度

- 关键 Rubric item 失分率；
- 目标 error taxonomy 命中率；
- 负控制上的误命中率；
- 多 trial 方向稳定性；
- 边界样本上的结构化结果一致率。

### 21.3 路由质量

- applicable precision；
- applicable recall；
- not_applicable 提前拦截准确率；
- 相邻 operator 混淆矩阵；
- 泛化 fallback 到 O10/O15 的比例。

启用决策不由单一总分决定。operator 资格指标是启用的主要依据；对该 operator 产生的多轴候选，必须分别报告每个轴的得分、错误 taxonomy、方向稳定性和归因证据。候选联合总分不得代替分轴结果或 operator 资格结论。

已选 operator 的核心事实契约、结构金标、answer contract 或路由前置任一未通过，该 operator 都不得进入 enabled。非核心语义轴的契约未完成时，不得声明或评分该轴。概率性诊断只作为 shadow/advisory，不直接升级为 blocking。

人工审核关注点和备注可随候选或资格报告保存，但不纳入上述指标，不改变 draft、qualification_only、shadow_routing 或 enabled 状态。

## 22. 实施顺序

### 22.1 第一部分：内容设计

3. 完成结构金标解析、持久化、版本迁移和回放。
4. 为第二批 family 准备路径图、程序参照系、数值阈值和结论层级 Schema。

#### 阶段 M1：第一批资格数据

1. 建设 O19/O20/O21/O23 调参集、qualification holdout 和 natural routing holdout。
2. 完成 Blind Solver、answer contract resolver 和 scorer mapping。
3. 执行 forced qualification，优先驳回无法与相邻算子区分的 family，不急于启用。

#### 阶段 M2：第一批 Shadow Router

1. Router 支持事实结构的 shadow 识别。
2. 使用 natural routing holdout 建立混淆矩阵。
3. 对路由稳定的 family 进入小规模主链；不稳定 family 保持 shadow，不通过放宽前置强行提高选中率。

#### 阶段 M3：第二批资格化

1. 建设 O22/O24/O25/O26/O27 调参集和 holdout。
2. 重复 forced qualification 与 shadow routing 资格流程。
3. 数据不足的 family 保持 draft 或 qualification_only。

#### 阶段 M4：算子边界全量审计

1. 输出 O10-O27 的语义混淆矩阵。
2. 审计是否又出现多个 operator 共用同一事实对、只换名字的现象。
3. 合并、暂停或退役无法稳定区分的 family。
4. 确认候选集合可保存多个候选，但每个候选的一次进化只选取一个 operator；多轴题只在该候选已选 operator 的契约边界内建设。

## 23. 测试策略

### 23.1 内容层测试

- 每个新 operator 的题目需要其独有结构推理才能作答；
- 结论不变负控制不能被"只要变化就改答案"策略命中；
- 主体、候选、路径或版本的表面交换不改变语义答案；
- 题面不泄漏结构金标、断点、路径可达性、残差排序或层级传导结论；
- 不使用实体数、节点数、列表长度或表格格式作为主要难度来源；
- 公开题面只提出自然业务判断和开放式依据，不把内部推理任务、轴名称或答案要点展开成作答清单；
- 多轴题中每个轴的推理任务和目标错误可从内部 spec 独立识别，不依赖其他轴的内部标签；
- O19-O27 均已注册、可被现有 Router 基础识别，并可通过统一入口构造生成 Prompt。

### 23.2 契约与机制测试

- 每个新 operator 的 required slots 与事实 Schema 一致；
- 缺核心 required slot 时整个候选稳定 not_applicable；缺非核心轴的 required slot 时仅该轴 not_applicable；
- 变换只改变 contract 允许的结构单元；
- 不变量在生成前后一致；
- answer contract 可从结构金标确定生成；
- operator payload 可端到端解析、持久化和回放；
- Blind Solver 不接收结构金标和生成器 key；
- 未通过资格的 family 不控制主路由；
- 候选集合数量不作为准入、排序、重试或拒绝条件；
- 每个候选只有一个 selected_operator_id，且所有 axis_assignment 均属于该 operator；同一候选的进化过程不切换 operator；
- 多轴候选中每个 axis_assignment 都有独立 payload、answer contract、Rubric item 和效果归因；
- 增加、删除或重排一个轴时，其他轴的答案契约不被静默改写；
- axis_interactions 中每个依赖都有方向、关系和 interaction contract；
- 某轴 not_applicable 时，其他轴只在题面与契约仍完整时继续；
- manual_review_record 为空、缺失或内容变化时，Router、validator、scorer 和候选状态的输出不受影响。

### 23.3 相邻算子对照测试

- 主体交换与事实增强的区分；
- 事件链断点与最小推翻事实的区分；
- 物品 provenance 与人员角色绑定的区分；
- 单端点时序与多路径拓扑的区分；
- 单一替代解释与多假设排序的区分；
- 基线适用性与误差传播的区分；
- 同层反事实与跨层结论映射的区分。

### 23.4 回归测试

新增 operator 不得改变 O10-O18 历史 ID、语义版本、产物解析和现有回放结果。Router 加入新 family 后，旧样本的任何路由变化必须保存可解释原因和版本。

## 24. 验收条件

### 24.1 第一部分验收

每个新 operator 的内容定义必须同时满足：

1. 能力轴和目标错误无法被现有 operator 无损替代；
2. 题面保留对应的结构推理负担；
3. 内容变换和不变量语义清晰；
4. 负控制上不会因格式、数量或表面标签制造假边界；
5. 与相邻 operator 的内容边界可用具体近邻例说明；
6. 不通过实体、因素、候选项、反事实、事实、节点、假设或语义轴的固定数量定义题型边界；
7. 多轴题的各轴均属于该 operator 的内容边界，并有可识别的推理任务、目标错误、结论边界和内容依赖说明；
8. 如有人工审核关注点或备注，只将其作为后续人工查阅信息记录，不产生流程通过、拒绝或状态判定。
9. O19-O27 的稳定 ID 已完成基础注册，现有 Router 可按主要推理对象识别，并能通过统一生成入口调用。

### 24.2 第二部分验收

每个新 operator 进入 enabled 前必须同时满足：

1. 专用事实 Schema、变换契约、不变量和 operator payload 完整；
2. 事实来源、结构金标、answer contract 和 Rubric 一致；
3. 在 forced qualification holdout 上产生的错误可归因到目标 taxonomy；
4. 结论不变负控制和表面交换控制不产生假边界；
5. Router 在 natural holdout 上能与相邻 operator 区分；
6. 事实金标和具体 Rubric item 可回放结论；如保存人工复核记录，该记录仅供查阅，不参与本验收判定；
7. 状态迁移、版本、失败证据和回滚路径可追溯；
8. 候选集合不设固定数量限制；每个候选仅保存一个 selected_operator_id，且在本次进化中不切换 operator；多轴候选完成分轴 payload、answer contract、Rubric、评分和效果归因，候选总分不代替分轴结论。

## 25. 风险与回滚

暂时无法在飞书文档外展示此内容

每个新 operator 都可独立从 enabled 回滚到 shadow_routing 或 qualification_only。回滚不删除历史产物，必须保留 semantic version、prompt version、applicability version、validation policy version、失败原因和回滚日期。

## 26. 完成定义

### 26.1 第一部分完成

1. O19-O27 均有稳定的能力轴、推理对象、题面构造、内容变换和不变量；
2. 每个新算子的目标错误与相邻旧/新算子边界可用具体内容例说明；
3. Prompt 不泄漏结构金标、预期方向或 Router 原因；
4. 题型难度来自结构推理，不来自实体数、节点数、格式或多任务；
5. 多轴题中每个轴的推理任务、目标错误和结论边界可独立识别；
6. 题型不使用实体、因素、候选项、反事实、事实、节点、假设或语义轴的固定数量作为内容要求；
7. 第一部分只增加现有 Router 的基础规则识别与调用接线，不改动 Router 适用性契约、质量校准、validator、scorer、契约检查、候选分支、重试策略、状态机或正式流量；
8. 人工审核信息如有记录，仅供后续人工查阅，不作为任何流程判断依据。
9. O19-O27 已完成稳定 ID 基础注册，可由现有 Router 识别并通过统一生成入口调用；该可调用性不等于资格通过或正式启用。

### 26.2 第二部分完成

1. 能力缺口样本能稳定进入对应专用数据池；
2. 每个 family 的事实 Schema、结构金标、operator payload、answer contract 和 scorer mapping 可完整回放；
3. 第一批 family 至少完成 forced qualification 和 shadow routing；
4. 新算子与 O10-O18 的语义边界可通过混淆矩阵审计；
5. 每个 enabled operator 都有专用事实 Schema、结构金标、资格报告和回滚开关；
6. 结构化记录能将降分归因到多实体、事件链、物品 provenance、观测可靠性等具体能力错误，而不是泛化的"证据强度判断错误"；人工备注仅供查阅，不参与该归因判定；
7. 候选集合不设固定数量限制，每个候选只回放一个 selected_operator_id；多轴候选可完整回放该 operator 内各轴的 answer contract、Rubric item、评分和效果归因，不使用候选总分替代分轴结论。

两部分均完成后，再通过《扩大实验与受控评测方案》统一比较旧机制、可信度修复、现有算子修复和新 operator family 的独立贡献。
