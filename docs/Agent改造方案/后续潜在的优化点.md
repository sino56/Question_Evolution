最值得补的点
- 真实重规划循环：当前 decide_next_action 最终基本都会 stop_and_report，并明确写着第一版不自动开启额外实验【/home/amax/codex_server/workspaces/7efca38d-9124-47ca-bfd2-200b2f3e3ad6/QA_Evolution_Agent/agent_runtime/decisions.py:107】。后续应增加 continue_search、replan、rollback_and_retry、start_next_round 等正式决策类型。
- 原子工具拆分：当前 Tool Registry 已预留 atomic/composite 类型【/home/amax/codex_server/workspaces/7efca38d-9124-47ca-bfd2-200b2f3e3ad6/QA_Evolution_Agent/agent_runtime/tool_registry.py:11】，但主要工具仍是 run_full_loop 这种大块 composite 工具【/home/amax/codex_server/workspaces/7efca38d-9124-47ca-bfd2-200b2f3e3ad6/QA_Evolution_Agent/agent_runtime/tool_registry.py:71】。要让 Agent 真正自主规划，需要拆成画像、算子选择、候选生成、校验、作答、评分、分析、状态更新等可独立调用工具。
- 计划模拟与可执行性检查：现在 Planner 主要按目标关键词选择搜索模式【/home/amax/codex_server/workspaces/7efca38d-9124-47ca-bfd2-200b2f3e3ad6/QA_Evolution_Agent/agent_runtime/planner.py:25】。后续应在执行前模拟计划：预算够不够、依赖是否完整、是否会跳过评分、是否会重复跑无收益路径。
- Agent 状态模型加强：当前 context_pack 主要是任务、计划、观察、记忆摘要和最后决策【/home/amax/codex_server/workspaces/7efca38d-9124-47ca-bfd2-200b2f3e3ad6/QA_Evolution_Agent/agent_runtime/context.py:22】。后续应加入结构化 world_state：当前父题、候选树、每条分支状态、算子收益、剩余预算、已冻结快照、可回滚点。
- 实验谱系追踪：记录每个候选来自哪个父题、哪个算子、哪轮策略、哪个 prompt/model/judge 版本，以及为什么继续或放弃。这样第二个分析 Agent 才能判断“是算子有效、prompt 有效、还是样本本身容易降分”。
- 自我评估与置信度：每轮实验后，不只输出报告，还要输出结构化判断：本轮是否可信、证据是否充分、是否需要复评、是否可能是 judge 波动、下一步收益是否高。
- 策略回放与回归集：建立固定样本集，任何新策略、记忆、prompt、算子路由调整都先在回归集重放。目标不是单次更好，而是避免整体退化。
- 人工审批队列：现在很多结果会 requires_human_review，但还缺少标准审批对象。后续可以把“发布记忆、启用新算子策略、改 prompt、改预算策略”都变成待审批变更单。
- 失败处理配方库：把 validation_failed、not_applicable、score_increased、模型超时、产物损坏分别绑定固定恢复动作。例如 score_increased 先回滚父题，validation_failed 多则减少该算子预算，模型超时则换备用端点。
- 长期运行调度器：完整 Agent 不只跑一题，还要管理任务队列、并发、取消、暂停、恢复、优先级和成本上限。否则多轮自进化会变成脚本堆叠，不是稳定系统。
优先级建议
先做三件事：原子工具拆分 -> 重规划执行器 -> 实验谱系/回归评估。这三项补齐后，系统才真正具备“Agent 观察结果后继续行动”的能力；后面的多 Agent、Skills、记忆和缓存才能发挥稳定价值。
