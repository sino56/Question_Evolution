# 基于父节点的多算子分支搜索方案

- 文档状态：代码已接入，真实小批量与性能验收待完成；调度效率语义以《树搜索效率优化》为准
- 制定日期：2026-07-20
- 适用范围：Question Evolution 多分支探索阶段
- 目标读者：负责流水线、搜索调度、数据结构和实验验收的工程师

## 1. 方案摘要

> 2026-07-25 实施说明：本文定义父子比较、分支终态、重复重试和 Memory 等业务
> 不变量；其中“自动补齐全部注册算子”“同一样本分支固定串行”和
> `operator_space_exhausted` 的自然搜索语义已由《树搜索效率优化》替换。
> 当前自然搜索只冻结当前候选列表并使用有界动态窗口；候选耗尽写
> `candidate_list_exhausted`。只有显式全覆盖实验使用
> `operator_space_exhausted`。

本次优化的核心目标，是把当前"一个样本每次只保留一条进化路径"的单分支流程，改造成"以当前已评分题目为父节点，同时使用多个适合算子分别建立分支"的搜索流程。

树搜索只负责扩大探索范围和管理分支，不负责重新定义什么是好题、什么是有效边界。每条分支一旦生成出不重复的题目，后续仍完整执行原有闭环：

```text
算子进化题目
→ 生成参考答案
→ 生成 Rubric
→ 生成或更新 Score Prompt
→ 候选模型回答
→ Judge 按原规则评分
→ 与父节点分数比较
→ 记录分支结果
```

本方案不修改现有 Judge、评分口径、Rubric 语义或评分模型，不增加语义相似度、合理降分判断、复杂边界判定等新的自动校验。只要子节点得分低于父节点，就将该分支记录为"边界候选"，并停止该分支；边界是否合理由后续人工审核决定。

采用该搜索方式后，固定 round 轮数不再作为样本的业务终止条件。每个样本在满足以下任一条件时结束搜索：

1. 所有适合该父节点的算子均已完成尝试；
2. 已发现的边界候选数量达到 5 个。

系统仍需保留请求预算、评分预算、超时和致命错误等硬保护，但这些只用于防止任务失控，不属于业务判别依据。

## 2. 优化目的

### 2.1 从单一选择改为多分支探索

当前单分支模式会在候选生成后选择一个候选继续执行，其他算子方向不会分别进入完整的答案、Rubric 和评分闭环。这样容易遗漏同一样本上的其他潜在边界。

优化后，一个父节点有多少个适合算子，就最多建立多少条独立算子分支。每个算子只生成一个有效候选，每条分支都获得完整评价机会，不再因为另一个算子分支被选中而提前丢弃。

### 2.2 在同一个父节点上覆盖不同算子方向

每个算子代表一种不同的题目进化方向。搜索调度器应记录哪些适合当前父节点的算子已经尝试、哪些尚未尝试，并从未尝试的适合算子中持续创建新分支，直到适合算子全部完成或边界候选数量达到 5 个。

初始路由只决定算子尝试顺序，不能永久排除未进入首批候选的算子。只要算子具备题目生成功能，且没有明确返回不适用，就应保留在后续待尝试集合中。算子一旦明确返回 not_applicable，必须永久移出该样本的适合算子集合，后续开启新分支时不能再次尝试。

### 2.3 为每个样本发现多个边界候选

一个样本可能同时存在多个不同的能力薄弱点。搜索结果不再只输出一个最终叶节点，而是保存该样本在不同算子、不同候选分支上发现的全部降分结果，供后续人工审核和实验分析。

### 2.4 保持现有评测契约稳定

多分支搜索不能改变以下内容：

- 候选模型的回答方式；
- Rubric 的生成与使用方式；
- Score Prompt 的生成与使用方式；
- Judge 模型、重复次数和评分聚合方式；
- 原有复杂度、可回答性等候选校验；
- 原有 Memory 的准入条件、写入时机和数据结构；
- 原始评分结果和实验追踪数据。

同一个候选题在单分支模式和多分支模式下，应得到相同的后续处理和评分结果。两种模式的差异只在于：单分支模式只让一个算子候选进入闭环，多分支模式让每个适合算子的候选分别进入闭环。

## 3. 非目标与设计边界

本方案明确不做以下事情：

1. 不新增自动判断"降分是否合理"的模型或规则；
2. 不把任意降分直接标记为已确认有效边界；
3. 不新增语义相似度模型判断题目是否近似重复；
4. 不修改现有 Judge 的决策地位；
5. 不为树搜索创建新的综合质量分；
6. 不根据搜索分支数量改变原始样本权重；
7. 不改变原有 Memory 的准入、写入和更新机制；
8. 不在本阶段实现从子节点继续向更深层递归扩展。

根据当前分支规则，所有完成评分的子节点都会终止：降分节点记录为边界候选，不变或上升节点记录为失败探索。因此，本方案实际采用的是"以父节点为中心的多算子横向分支搜索"，而不是无限向下生长的深层树。

如果未来需要多层搜索，必须另行定义哪些子节点可以成为下一层父节点；该问题不属于本次优化范围。

## 4. 核心概念

### 4.1 父节点

父节点是当前样本进入多分支搜索前已经完成评分的题目记录。它提供：

- 父题文本；
- 父题参考答案；
- 父题 Rubric 和 Score Prompt；
- 父题候选模型答案；
- 父题评分结果和 score_rate；
- 样本画像、历史状态和算子路由所需上下文。

同一父节点下的所有子分支都必须与该父节点比较分数，兄弟节点之间不能互相作为评分基线。

### 4.2 算子尝试

算子尝试表示在一个父节点上，使用一个指定算子建立一条分支，并最多生成一个有效候选题。第一次生成重复时允许使用同一算子重试一次；这次重试仍属于同一分支，不会形成第二个候选。

搜索开始时建立一份按路由优先级排序的 operator_plan。计划只包含当前启用且具备题目生成功能的算子；静态禁用或仅承担校验职责的算子不进入计划，并记录排除原因。

```text
primary / backup operators
→ 其他具备生成功能的算子
→ avoid_operators（仅降低优先级，不等于不适用）
```

初始路由只提供尝试顺序，不负责永久排除算子。未进入首批候选的适合算子仍应追加到计划中；只有静态不可生成或运行时明确返回 not_applicable 的算子不再尝试。运行时明确不适用的算子保留在 operator_plan 中并将状态改为 not_applicable，用于审计和恢复。

每个适合算子只尝试一条分支。该分支出现以下任一结果后，算子的单次生成预算视为已经消耗：

- 生成不重复题目并完成评分；
- 连续两次生成重复题目；
- 算子明确不适用；
- 候选未通过原有校验。

网络超时、限流、临时 API 错误或不可恢复的系统错误不能算作算子已正常完成尝试。临时错误应继续使用原有请求重试机制处理，不可恢复错误应记录为异常终止。

operator_space_exhausted 表示所有适合算子的单次分支预算均已结束，不保证每个算子都产生通过校验并完成评分的候选。搜索摘要必须分别报告算子调用覆盖率、校验通过率和完成评分率。

### 4.3 分支

一个适合算子对应一条分支。分支由以下信息唯一确定：

`父节点 ID + 算子 ID`

重复生成只是同一算子分支内的第二次生成尝试，不创建新分支。只有生成出不重复题目后，才为该分支建立有效子节点并进入答案、Rubric 和评分闭环。

### 4.4 边界候选

只要满足：

`child_score_rate < parent_score_rate`

该分支就记录为边界候选并停止，不再由系统自动判断降分是否合理。

边界候选必须保留：

- 父题与子题；
- 父分数、子分数和分数变化；
- 使用的算子；
- 完整回答、Rubric、Score Prompt 和 Judge 结果；
- 原有校验结果；
- 人工审核状态，初始值为 pending。

"边界候选"不等于"确认有效边界"。全部实验运行完成后，再由人工逐条审核每个分数下降分支的具体情况，判断其是否属于合理下降以及是否进入正式有效边界集合。人工审核不作为原有 Memory 写入的前置条件，原有 Memory 的准入和写入机制保持不变。

## 5. 分支执行规则

### 5.1 首次生成不重复

候选题与直接父节点和已有兄弟题目均不重复时，立即创建分支节点，并执行完整闭环。

### 5.2 首次生成重复

第一次生成重复时，不关闭分支，也不切换算子。搜索调度器应在同一个父节点、同一个算子分支下再给一次生成机会。

第二次生成时，需要把第一次生成的题目和重复原因反馈给题目生成模型，例如：

上一次生成结果与父节点或已有分支重复：
<上一次生成的题目>

请继续使用当前算子重新生成，但不得复用上述题目。

这只是生成反馈，不是新的题目质量校验规则。

### 5.3 第二次生成仍重复

同一算子分支连续两次生成重复题目后：

- 当前算子标记为 duplicate_exhausted；
- 当前算子分支停止；
- 保存两次生成轨迹；
- 该算子视为已经完成尝试，后续不再使用；
- 回到父节点；
- 切换下一个适合且未尝试的算子。

### 5.4 分数下降

子节点分数低于父节点时：

- 分支结果标记为 boundary_candidate；
- 保存完整评价产物；
- 边界候选计数加一；
- 当前分支停止；
- 返回父节点继续探索其他适合算子；
- 如果边界候选数量达到 5 个，立即停止为该样本调度新的分支。

同一个样本内的算子分支按路由顺序串行执行。每条分支结束后立即更新边界候选数量，再决定是否启动下一个算子分支。不同样本之间可以并发执行。这样不需要并发抢占或在途名额计算，也能保证边界候选数量不会超过 5。

### 5.5 分数不变

子节点分数等于父节点时：

- 分支结果标记为 no_score_change；
- 当前分支停止；
- 不从该子节点继续向下扩展；
- 回到父节点，使用下一个适合且未尝试的算子建立新分支。

### 5.6 分数上升

子节点分数高于父节点时：

- 分支结果标记为 score_increased；
- 当前分支停止；
- 子节点不能成为新的评分基线；
- 回到父节点，使用下一个适合且未尝试的算子建立新分支。

禁止从分数上升节点继续扩展。否则后续节点可能只相对这个更容易的子节点出现下降，却仍然没有优于原父节点，从而形成误导性的局部降分。

### 5.7 原有校验失败或算子不适用

候选未通过原有校验时：

- 保留原有校验结果；
- 继续执行原流程已有的 VALIDATION_RETRIES，使用同一算子和原拒绝原因重新生成；
- 原有校验重试耗尽后仍未通过，当前算子分支结束，并将该算子标记为已经完成尝试；
- 不增加原流程之外的新校验或二次判断；
- 回到父节点处理下一个适合且未尝试的算子。

算子明确返回不适用时：

- 保存不适用原因；
- 将算子状态永久标记为 not_applicable；
- 将算子从 suitable_operators 和后续待尝试集合中移除；
- 后续从同一父节点开启任何新分支时，都不能再次选择该算子。

not_applicable 必须来自题目生成模块的结构化结果，并同时包含非空原因。网络错误、超时、空响应、模型响应解析失败或搜索层推断都不等于算子不适用，不能据此将算子标记为 not_applicable。

三类重试必须分别记录，不能共用一个计数器：

1. API 重试：沿用原有网络和模型调用重试；
2. 原有校验重试：沿用 VALIDATION_RETRIES；
3. 精确重复重试：本方案新增，每个算子分支最多使用一次。

每次生成结果都先执行精确重复检查，再执行原有校验。精确重复重试不会消耗原有校验重试次数；原有校验触发的重新生成结果仍须再次经过精确重复检查。算子覆盖统计应分别记录 generation_attempted、validation_passed 和 scored，避免把"调用过算子"误报为"完成过评分"。

## 6. 重复题目判定

本方案只进行简单、可解释的精确重复检查，不进行语义相似度判断。

题目比较前只做以下规范化：

1. 去除首尾空白；
2. 将连续空格、换行和制表符合并为一个空格。

规范化后的题目文本完全相同时，视为重复。检查范围包括：

- 与直接父节点重复；
- 与同一父节点下已经接受的兄弟节点重复。

同一父节点上，每个适合算子只建立一条分支。首次生成重复时，同一算子的第二次调用只是原分支内的生成重试，不创建新分支，也不算再次尝试该算子。

题目是否重复只根据规范化后的文本判断，与生成题目的算子来源无关。不同算子生成了相同题目时，后生成的算子分支仍视为重复，并在原分支内获得一次同算子重试机会；第二次仍与直接父节点或已有兄弟题目重复时，该算子标记为 duplicate_exhausted。

"已有兄弟题目"指同一父节点下此前算子分支生成并完成唯一登记的所有不重复题目，包括后来未通过原有校验的题目。候选通过精确重复检查后，立即将规范化文本哈希写入父节点的 seen_prompt_hashes，后续算子分支据此判断重复。由于同一样本内算子串行执行，不存在两个兄弟分支同时登记相同题目的竞态。

语义接近但文本不同的题目仍然进入原有完整闭环，并由后续人工审核判断是否属于相同边界。

跨算子文本去重成立的前提是：算子 ID、算子意图和生成过程元数据只作为生成来源与审计信息，不进入后续答案生成、Rubric、Score Prompt 或 Judge 输入。候选一旦生成，后续闭环只依据候选题及原流程已有业务字段执行。若未来算子上下文开始影响评价输入，必须重新定义重复键，本方案的纯文本跨算子去重不再适用。

## 7. 全局搜索状态

每个样本维护独立的搜索状态。建议结构如下：

operator_plan 是算子状态的唯一持久化来源，按初始路由优先级排序。适合、已完成、不适用和剩余算子集合都在运行时根据该列表派生，不重复持久化。

原有 round 字段继续记录多分支模式的执行批次，用于日志和断点恢复，但不再设置最大值，也不参与业务终止判断。

### 7.1 算子状态

每个算子建议维护：

```json
{
  "operator_id": "O12",
  "status": "running",
  "branch_id": "sample-001::O12",
  "generation_attempt_count": 1,
  "failure_reasons": []
}
```

推荐状态包括：

- pending：尚未开始；
- running：当前算子分支正在处理；
- completed：当前算子分支已经生成有效候选并完成评分，或已因校验失败结束；
- duplicate_exhausted：同一算子连续两次生成重复题目，分支结束且后续不再使用；
- not_applicable：算子已明确不适用于该父节点，永久禁止在后续分支中再次尝试；
- failed：发生不可恢复的算子级错误；这是异常状态，不能满足"适合算子全部尝试"的正常终止条件。

### 7.2 分支状态

每条分支建议维护：

```json
{
  "branch_id": "sample-001::O12",
  "parent_node_id": "sample-001::root",
  "operator_id": "O12",
  "generation_attempt_count": 1,
  "parent_score_rate": 1.0,
  "child_score_rate": 0.72,
  "delta_score_rate": -0.28,
  "branch_status": "boundary_candidate",
  "review_status": "pending"
}
```

推荐分支终态包括：

- boundary_candidate；
- no_score_change；
- score_increased；
- duplicate_exhausted；
- validation_failed；
- branch_error。

not_applicable 是算子级终态，不是普通分支终态。某个候选生成响应一旦明确表示算子不适用，应直接关闭整个算子，而不是只关闭当前分支。

## 8. 全局终止条件

### 8.1 业务终止条件

每个样本只使用以下两个业务终止条件：

条件一：所有适合算子均已尝试

当 operator_plan 中不存在 pending 或 running 的适合算子，且所有适合算子均以 completed、duplicate_exhausted 或 not_applicable 结束时，样本终止：

`termination_reason = operator_space_exhausted`

条件二：边界候选数量达到 5 个

当该样本累计发现 5 个降分分支时，立即停止，不再调度新的算子分支：

```text
termination_reason = boundary_target_reached
boundary_target = 5
```

边界数量按降分分支计数。由于合理性将在后续人工审核，本阶段不进行语义去重或有效性扣减。样本因 boundary_target_reached 终止时，boundary_candidate_count 等于 5；样本因 operator_space_exhausted 终止时，输出实际发现数量，该数量可以小于 5。任何正常终止场景下都不能超过 5。

边界目标表示按照既有路由优先级依次执行后得到的前 5 个降分候选，不额外增加边界多样性排序或二次选择。达到 5 个时，搜索摘要必须列出尚未尝试的算子，明确本次结果是"达到数量目标后提前停止"，而不是"已覆盖全部适合算子"。

### 8.2 取消固定 Round 限制

多分支搜索模式下取消 MAX_ROUNDS 和"达到最大轮数"这一业务终止逻辑。原有 round 字段继续表示执行批次，每完成一批调度后递增，但不再参与业务终止判断。

同时禁用原有基于轮次聚合结果的提前停止条件，包括平均分阈值停止、连续无新信息停止及其他同类全局判断。这些条件只保留给 single_branch 模式。多分支模式正常结束只能由"适合算子全部尝试"或"边界候选达到 5 个"触发。

新的推进依据是：

未完成的适合算子集合
→ 每个算子建立一条分支
→ 每条分支最多生成一个有效候选并执行完整闭环
→ 更新算子完成状态和边界候选数量
→ 检查两个全局终止条件

### 8.3 系统硬保护

即使业务终止条件只有两个，系统仍必须保留以下保护：

- 单样本最大 API 请求数；
- 单样本最大评分次数；
- 单样本最大运行时间；
- 全局并发限制；
- 不可恢复错误终止；
- 断点恢复和幂等写入。

系统保护触发时应使用独立终止原因，例如：

- evaluation_budget_exhausted；
- request_budget_exhausted；
- timeout；
- fatal_error。

这些原因表示搜索未按业务目标自然完成，不能伪装成"算子已全部尝试"或"已找到 5 个边界"。系统级 fatal_error、超时和预算耗尽不应把尚未执行的算子标记为已尝试。

## 10. 分阶段实施细节

### 10.1 新增搜索协调层

新增独立的 Search Coordinator，负责：

- 在原有画像和候选准入之后接管多分支模式，只有原流程判定需要进化的样本才进入搜索；
- 初始化父节点搜索状态；
- 初始化按路由优先级排序的 operator_plan；
- 将未进入首批候选但具备生成功能的算子追加到计划尾部；原路由中的 avoid_operators 只降低顺序，不等于明确不适用；
- 排除静态不可生成的算子；
- 永久排除已经明确返回不适用的算子；
- 为每个适合算子建立一条独立分支；
- 调用现有题目进化模块；
- 管理重复生成重试；
- 将不重复候选送入现有完整闭环；
- 维护算子和分支状态；
- 检查边界数量和算子完成度；
- 生成搜索摘要和断点恢复数据。

Search Coordinator 替代多分支模式下原有的固定轮次编排，但继续调用现有各阶段模块，不形成第二套生成、评分或 Memory 实现。它不参与题目质量判断，也不构造新的评分结果。

### 10.2 调整候选输出策略

多分支模式下，不再从同一父节点的合法算子候选中只选一个进入闭环。每个适合算子最多产生一个不重复且通过原有校验的有效候选，并分别进入答案、Rubric、Score Prompt 和评分阶段。

原有单分支模式可以继续保留，以便回归比较和兼容已有实验。

### 10.3 保持每条分支的数据隔离

每条分支必须具有独立 ID，并单独保存：

- 生成轨迹；
- 参考答案；
- Rubric；
- Score Prompt；
- 候选模型答案；
- Judge 结果；
- 分数变化；
- 原有校验结果；
- 分支终态。

所有子分支都从同一父节点复制业务输入，但不能共享或覆盖兄弟分支的评分产物。

分支进入现有阶段前必须设置：

candidate_group_id = parent_node_id
candidate_id = branch_id

所有阶段必须原样保留这两个字段，并优先使用 candidate_id 作为断点恢复和幂等写入键。branch_id 由父节点 ID 与算子 ID 稳定生成，不得按执行批次重新编号。

答案、Rubric 或评分阶段的单分支重试耗尽时，Search Coordinator 将该分支标记为 branch_error，保留已有证据并继续下一个适合算子。只有阶段产物损坏、搜索状态不可恢复等协调器级错误才触发样本级 fatal_error。

### 10.4 父子分数比较

分数比较必须通过显式 parent_node_id 找到父节点。不能仅依赖样本 ID，因为同一样本会同时存在多个分支记录。

分支只比较：

当前子节点分数 vs 直接父节点分数

不能使用当前批次平均分、兄弟节点分数或搜索历史最低分作为分支停止依据。

### 10.5 保留原有 Memory 写入机制

多分支搜索不修改现有 Memory 的业务准入、内容和触发时机。每条分支完成原有闭环后，继续按照原有规则处理正向 Memory、失败 Memory 和其他已有记忆产物。

搜索层不得增加以下约束：

- 不得要求人工审核通过后才允许写入 Memory；
- 不得因为分支属于边界候选而改变原有 Memory 准入条件；
- 不得使用 review_status 控制 Memory 写入。

为支持分支级断点恢复，Memory 写入层可以使用 branch_id + memory_type 作为技术幂等键，恢复时补齐尚未提交的记录并跳过已提交记录。该幂等保护只防止重复追加，不改变原有 Memory 的业务字段、准入条件或触发时机。

同一样本内算子分支按固定路由顺序串行执行，因此原有 Memory 写入可能按既有机制影响后续算子分支；这是保留原 Memory 机制后的明确顺序效应。每次实验必须保存最终算子顺序和 Memory 版本，以保证结果可复现。

人工审核是全部实验完成后的离线工作。审核对象是所有 boundary_candidate 分支及其完整产物，审核内容包括具体降分原因、题目变化、Rubric、Score Prompt、候选答案和 Judge 结果。审核结论只用于标记边界候选是否属于合理下降，以及是否进入正式有效边界集合，不改变实验运行期间已经按原机制产生的 Memory 记录。

### 10.6 并发与批处理

搜索可以按 round 批量调度多个样本。不同样本之间可以并发，同一样本内的算子分支必须按照 operator_plan 串行执行。批处理只用于提高吞吐，不改变每个样本的独立状态和终止条件。

当某个样本达到 5 个边界候选时：

- 不再为该样本创建新任务；
- 其他样本继续运行；
- 由于同一样本内算子串行执行，不存在尚未收敛的兄弟分支；
- 因 boundary_target_reached 终止时边界候选数量等于 5；
- 因 operator_space_exhausted 终止时输出实际发现数量，可以少于 5。

## 11. 输出产物

建议新增以下逻辑产物：

暂时无法在飞书文档外展示此内容

搜索状态与分支结果是规范化持久化数据。算子尝试记录、生成尝试轨迹、边界候选集合和搜索摘要应优先由这两类记录派生，不要求分别维护多份可相互冲突的独立状态。

边界候选集合应保留完整分支记录，不能只保存题目和分数，否则人工审核时无法检查 Rubric 漂移、Judge 偏差或题目本身的问题。

## 12. 兼容策略

建议通过搜索模式开关区分两种执行方式：

```text
single_branch
multi_operator_branch
```

- single_branch：保持当前单候选主链行为；
- multi_operator_branch：启用本方案，不再使用固定 Round 作为业务终止条件；
- 两种模式共享相同的生成、回答、Rubric、Score Prompt、评分和原有校验模块；
- 原有画像、候选准入和非进化样本的透传/停止行为在两种模式下保持一致；
- 原有平均分提前停止、无新信息提前停止和最大轮数停止只适用于 single_branch；
- 多分支模式新增的状态和产物不得改变单分支模式的数据含义。

## 13. 验收标准

### 13.1 功能验收

1. 父节点有 N 个适合算子时，最多创建 N 条独立算子分支；
2. 只有通过原有画像和候选准入的样本进入多分支搜索，其他样本继续按原流程透传或停止；
3. 每条不重复且通过原有校验的分支都完成答案、Rubric、Score Prompt 和评分；
4. 每条分支都与同一直接父节点比较分数；
5. 分数下降时记录边界候选并停止当前分支；
6. 分数不变或上升时停止当前分支并返回父节点；
7. 首次精确重复时使用同一算子重试一次；
8. API 重试、原有校验重试和精确重复重试分别计数并按文档顺序执行；
9. 第二次仍重复时标记 duplicate_exhausted；
10. 明确返回不适用的算子永久移出后续待尝试集合；
11. 所有适合算子的单次分支预算结束后，样本以 operator_space_exhausted 终止；
12. 边界候选达到 5 个后停止该样本，数量目标终止时等于 5，算子耗尽终止时可以少于 5；
13. 多分支模式不再因为最大 Round、平均分阈值或连续无新信息停止。

### 13.2 判别一致性验收

1. 同一个候选题在单分支和多分支模式下使用相同的回答、Rubric、Score Prompt 和评分流程；
2. 多分支模式不修改 Judge 输出；
3. 多分支模式不新增复杂校验结果；
4. 搜索状态不能覆盖原有评分和校验字段；
5. 降分结果只能自动标记为边界候选，不能自动标记为人工确认有效；
6. 原有 Memory 的准入条件、写入时机和数据结构在单分支与多分支模式下保持一致；
7. review_status 不参与 Memory 写入决策。
8. 算子 ID 和算子意图不进入答案、Rubric、Score Prompt 或 Judge 输入，跨算子精确重复只执行一次完整评价。

### 13.3 数据与恢复验收

1. 每个父节点和算子分支均有稳定 ID；
2. candidate_group_id 和 candidate_id 分别稳定映射父节点与分支，重启后不会重复执行已经完成的算子分支；
3. 重复生成的两次原始结果都可追踪；
4. 达到边界目标后不再创建新任务，单样本边界候选数量不超过 5；
5. 单个算子分支失败不会中止同一样本后续算子或其他样本；
6. Memory 通过分支级幂等键避免恢复时重复追加；
7. 系统保护触发时能够区分业务完成和异常中止。

## 14. 建议实施顺序

1. 定义父节点、算子分支、生成尝试和搜索状态数据结构；
2. 实现稳定 ID 与断点恢复；
3. 实现同一算子重复生成一次的机制；
4. 分离 API、原有校验和精确重复三类重试状态；
5. 实现每个适合算子的唯一有效候选分别进入原有完整闭环；
6. 将稳定分支 ID 接入原有阶段恢复键；
7. 实现显式父子分数比较和分支终态；
8. 实现适合算子覆盖状态和 not_applicable 永久排除；
9. 实现边界候选数量达到 5 的停止调度；
10. 禁用多分支模式下原有的轮数与聚合提前停止；
11. 实现搜索产物、Memory 幂等提交和边界候选汇总；
12. 完成单分支与多分支判别一致性回归测试。

## 15. 最终原则

本次优化只改变搜索形态，不改变评测契约：

- 原来：多个算子候选中选择一条主分支执行完整闭环
- 现在：每个适合算子分别形成一条分支，每条分支最多生成一个有效候选并执行同一个完整闭环

搜索层只负责：

- 创建和调度分支；
- 管理算子覆盖；
- 处理精确重复和一次重试；
- 根据父子分数关系结束分支；
- 根据适合算子耗尽或 5 个边界候选结束样本。

原有模块继续负责：

- 生成题目；
- 生成答案；
- 生成 Rubric 和 Score Prompt；
- 候选模型回答；
- Judge 评分；
- 原有候选校验；
- 保存完整实验证据。

只有保持这条边界，才能确保多分支搜索提升的是边界发现覆盖率，而不是通过改变判别机制制造新的实验结论。
