## 1. 文档边界

本方案拆成两个独立部分：

1. **第一部分：算子内容修复** 定义每个算子"测什么"、"保留什么推理负担"、"题面如何呈现"和"生成器应如何构造竞争性题目"，并完成 operator ID 注册、现有 Router 的基础分派和生成调用接线，使内容实现可以被正常选择和调用。该部分不定义结构化输出接口、评分映射、审核校验规则、硬拒绝、资格状态或发布决策。
2. **第二部分：算子校验规则** 定义第一部分内容要求如何转成结构化数据契约、如何落盘和评分，候选什么时候可以发布、哪些问题只记录诊断、哪些问题必须硬拒绝，以及 not_applicable、reject_candidate 和算子耗尽时的流程行为。基础注册、路由可识别和生成调用不再延后到第二部分。

第一部分可以独立完成内容设计、Prompt 修改、基础注册和现有 Router 调用，并通过内容测试检查题型是否符合目标能力。结构化推理结果、算子专属 payload、持久化、scorer 映射、审核校验、资格实验、启用条件和发布校验仍在第二部分实现。第一部分的可调用只表示能被现有流水线选择和执行，不表示已经通过资格或新增了发布保障。

## 2. 方案摘要

通用场景下的多类型测试结果/exp 不能证明任何现有算子已稳定有效，但也不能简单得出"O10-O18 全部无效"。实验结果分为三类：

1. **值得优先修复**：O13、O15 已产生接近目标能力的探针，主要被金标、结论层级和比较量问题污染。
2. **需要重写竞争结构**：O10、O12、O16 生成成功率高，但大量退化为"识别唯一显性差异"。
3. **尚未被有效测试**：O11、O17、O18 缺少结构化前置数据，应先建专用数据，不应根据本轮质疑其能力假设。

O14 不是独立生成算子。它的内容定位是信息闭包检查，不设计独立题面；其运行状态、路由和 validator 实现全部在第二部分规定。

## 4. 目标与非目标

### 4.1 目标

1. 每个 operator ID 对应一个稳定的能力轴和错误 taxonomy。
2. 分开 operator 内容定义与校验策略，避免将 Prompt 指令误当为确定性校验。
3. 用机器可读事实 slot 表达适用性，不再依赖宽泛词面匹配。
4. 减少显性唯一差异、方向标签泄漏和表面排除。
5. 建立独立资格实验，分离算子 Prompt 能力和 Router 能力。
6. 每次内容修改只升级 operator Prompt 版本；实质能力轴变更时升级 semantic version 或新建 ID。

### 4.2 非目标

1. 不在本方案中新增多实体、事件链、物品 provenance 等新 family。
2. 不通过题长、任务数、选项数或反事实数的固定门槛约束算子。
3. 不要求所有算子产生相同题型或相同数量的候选。
4. 不因一次未降分就删除算子，也不因一次降分就宣称算子有效。

# 第一部分：算子内容修复

## 5. 通用内容原则

### 5.1 隐藏控制，不泄漏到题面

以下内部设计信息不得直接写入题面；是否以及如何结构化保存由第二部分规定：

- operator 名称和能力轴；
- 目标命题的内部标识；
- "唯一改变的事实"等执行说明；
- 预期正确方向；
- 决定性事实角色；

题面只呈现完整业务问题，不呈现算子执行手册。

### 5.2 竞争性而非显性错误

干扰项、替代解释或对照版本必须能解释部分事实。不得用主体不同、时段不同、语气强弱、标签对立或信息量差距制造正确答案。

### 5.3 保留题型差异

统一的是能力轴和语义契约，不是表面形式。题长、任务数、选项数和反事实数按实际内容决定，不用固定数量门槛塑造难度。

### 5.4 推理负担不得降级

进化题不得仅通过隐藏方向标签，就把开放的事实组织任务改造成封闭的判向任务。每个算子的内容定义必须说明：

1. 父题中需要保留的核心推理义务；
2. 回答者必须自行构造的事实连接、必要条件、覆盖关系或规则映射；
3. 生成器内部可以使用、但不得在题面预填的内容结构；
4. 允许的回答形态和禁止退化的封闭题形态。

题面不得直接提示"目标命题固定""只有一个事实变化"或完整推理分解。事实连接、必要条件集、假设覆盖关系和规则映射应由回答者根据题面自行构造。若父题要求组织事实和控制结论边界，进化题也必须保留相应义务；仅增加题长或事实数量不代表推理负担得到保留。

required_reasoning_tasks、目标错误、内容轴、消融结构和答案要点都是生成器内部控制，不是题面作答提纲。最终题面原则上只提出一个自然业务判断和开放式依据要求，不得使用"逐项说明""分别列出""先……再……"或内部维度名称替回答者完成问题分解。

### 5.5 统一内容定义模板

每个生成算子都按同一内容模板描述：

1. **能力定义**：算子测量的唯一能力轴。
2. **推理对象**：事实集合、端点约束、必要连接、比较量、竞争解释、规则或基线。
3. **题面构造**：题面必须提供哪些内容，以及哪些内部设计信息不得直接出现。
4. **内容变换**：生成器在语义上增加、删除、替换或对照什么。
5. **内容不变量**：主体、时段、目标命题、结论层级或观测值中哪些必须保持不变。
6. **竞争结构**：错误解释为什么具有部分解释力，正确答案为什么不能由表面特征直接排除。
7. **目标错误与排除错误**：本算子要测试什么错误，哪些错误应由其他算子或新 family 处理。
8. **禁止捷径**：不得出现的方向标签、权威性标签、信息量差距、显性否定或完整答案链。
9. **相邻边界**：与最容易同构的相邻算子如何区分。
10. **内容控制**：正控制、结论不变负控制和表面交换控制如何构造。

### 5.6 正负控制与表面控制

每个算子的内容设计至少包含以下控制类型，但不规定固定题量：

- 目标能力正控制：必须使用该算子的独有推理结构才能作答；
- 结论不变负控制：不能形成"出现变化就必然改变结论"的固定策略；
- 相邻算子近邻：表面相似但应归入相邻算子或判为不适用；
- 表面交换控制：交换版本顺序、候选位置、来源名称或等价措辞不改变语义答案；
- 隐藏角色平衡控制：正确项不独占否定词、极端词、完整因果链或明显更高信息量。

### 5.7 相邻算子内容边界

暂时无法在飞书文档外展示此内容

同一隐藏事实结构若无需改变求解过程即可同时满足多个算子，应只保留最具体的算子归因；无法确定时不应通过换 operator ID 重复生成。

### 5.8 目标错误与排除错误

暂时无法在飞书文档外展示此内容

实际错误 taxonomy 可以继续细分，但必须保持与算子的能力轴和相邻边界一致。

## 6. O10 内容修复：从显性增益改为最小充分集

### 6.1 能力定义

固定同一目标命题，从多个互不蕴含的可观察事实中识别形成证明力跃迁的最小充分集合，而不是看到"多一条强线索"就回答增强。

### 6.2 题型内容

1. 题面围绕同一目标命题展开，同时呈现最小充分集合的成员、具有部分解释力但不属于该集合的相关事实，以及必须保持的不变事实。
2. 最小充分集合中的事实彼此不构成改写或直接蕴含；任一成员单独出现都不能直接决定答案。
3. 移除集合中任一必要成员后，原闭合关系不能保持；但不得把某个成员写成唯一显眼的"决定性事实"。
4. 不再默认展示"保持/增强/减弱/翻转"四方向标签。
5. 题面只询问现有材料能否支持自然业务判断及依据；最小事实集合和内部连接由回答者自行发现，不写成题面步骤。
6. 同一事实结构可随机交换版本顺序和表面位置，但不改变语义关系。

O10 的目标错误至少区分：遗漏必要集合成员、将相关事实误当充分事实、无法说明集合内部连接。单事实反事实方向错误归 O15，预设 X/Y 的共同必要关系归 O12。

## 7. O11 内容修复：端点时序契约

### 7.1 能力定义

基于可见端点、时间窗和路径约束，判断不可见区间候选假设是否与时序一致。

### 7.2 题型内容

- 比较两个都能解释部分端点事实的假设；
- 可使用区间重叠、多出口或速度范围，避免整数大小直接决定答案；
- 不要求推测盲区内真实发生的未见事件；
- 只评估候选假设与已给端点是否一致。

题面只询问现有材料对不可见区间能够支持什么结论及依据；候选假设与端点、时间窗或路径约束的逐项映射保留为内部答案结构。

## 8. O12 内容修复：独立性与共同必要性

### 8.1 能力定义

判断 X 和 Y 是否各自独立，又共同闭合同一目标命题的必要条件。

### 8.2 题型内容

生成器在内部构造三个语义对照：

```text
Vx  = 只有 X
Vy  = 只有 Y
Vxy = X + Y
```

题面以未标注的可比业务场景呈现这些事实组合，不出现 X/Y、Vx/Vy/Vxy、共同必要或联合闭合标签。只询问各场景能否支持目标判断及依据；X、Y 的独立贡献和 Vxy 的闭合关系保留为内部答案结构。

三个版本应保持主体、时间范围、目标命题、信息粒度和表面结构可比。内容控制同时包含联合闭合成立与不成立的样本，避免模型学习"X+Y 必然增强"。O12 的目标错误是把单调增益误当共同必要性；一般最小充分集发现归 O10。

## 9. O13 内容修复：必要连接与推翻层级

### 9.1 能力定义

在多个与同一推理链相关的候选事实中，识别唯一会破坏必要连接的事实，并区分它对局部连接和整体结论的影响。

### 9.2 题型内容

生成器在内容设计中区分以下语义角色：

- 保持必要连接
- 仅降低置信度
- 破坏必要连接
- 连接失效但整体命题仍由其他路径支持

题面不显示这些角色，也不声明原必要连接或存在唯一破坏项。各候选事实应保持同一观察类别、同一证据类型、同主体、同时段、相近信息粒度和相近语法结构，但在内容设计上承担不同逻辑角色。题面只询问复核后目标业务判断是否仍成立及依据；失效连接、其他支持路径和整体结论层级保留为内部答案结构。

O13 只定位必要连接破坏及其局部/整体后果。一般置信度变化归 O15，多阶段状态链断点归新事件链 family。

## 10. O14 内容定位：不再生成独立题型

O14 不设计独立题面。其内容原则是题面只能使用已给事实，不得补造中间状态、统计口径或业务阈值。

## 11. O15 内容修复：比较量与结论门槛

### 11.1 能力定义

在其他事实不变时，判断一个核心事实变化如何影响同一被比较的量。

### 11.2 题型内容

每道题围绕且只围绕以下一种语义量：

- 事件发生可能性
- 证据支持度
- 命题成立度
- 距离行动门槛的程度
- 距离事实认定门槛的程度

给定门槛本身保持不变，事实变化影响的是门槛满足状态或门槛裕量，不得写成事实变化导致规则阈值本身改变。被改变的事实、被比较的语义量和题目要求判断的结论必须处于同一声明层级。

有明确逻辑必要条件或给定阈值时，题目可比较保持、减弱或翻转。没有阈值时，只表达"支持不增/支持减少/支持增加"等偏序，不把局部解释力变化写成整体结论必然翻转。涉及两套明示规则时归 O17；涉及证据支持、事实认定和行动处置之间的跨层映射时转跨层校准 family。

## 12. O16 内容修复：相近解释的覆盖与残差

### 12.1 能力定义

判断一个相近正常解释能否覆盖核心异常，还是只解释外围事实。

### 12.2 题型内容

题面只引入一个相近正常解释。该解释必须覆盖足够多的共享事实而具有真实竞争力，与目标解释的决定性分歧集中在一个可观察 discriminator 上。删除 discriminator 后，两个解释都应保持可行且无法稳定排序。discriminator 不得直接重述目标命题、使用"正常/异常"等评价标签或构成某一解释的显性否定。多个假设的排序不继续堆入 O16，而应进入新算子 family。

内容构造时必须在内部分析目标解释和替代解释各自覆盖哪些事实、冲突哪些事实、留下哪些残差，以及双方在哪个可观察事实上分叉。题面只询问现有材料最支持什么结论及依据，不点名覆盖、冲突、残差或 discriminator；决定性观察与多个同粒度观察自然混合，不能成为唯一显眼答案。

内容控制同时包含"正常解释覆盖核心异常"和"只覆盖外围事实"两类结果，避免固定答案方向。

## 13. O17 内容修复：双规则边界判断

### 13.1 能力定义

基于题面明示的两套业务规则，区分处置触发条件和事实定性条件的适用范围。

### 13.2 题型内容

- 不做明显的规则-条件查表；
- 优先使用边界值、两规则同时部分匹配或事实/行动层级交叉；
- 要求回答指出规则适用对象与当前事实之间的具体映射；
- 两套规则必须在题面中明确给出，不由模型使用警务常识补齐。

题面只询问当前材料下应作出何种业务判断及依据，不分别点名事实判断和处置子任务；规则映射、适用范围和各结论层级保留为内部答案结构。单一规则层级内的事实前后迁移归 O15。

## 14. O18 内容修复：基线口径和异常性

### 14.1 能力定义

在候选基线同域但纳入口径不同时，选择与当前事件可比的基线，并判断同一观测值的异常性是否改变。

### 14.2 题型内容

- 两个候选基线属于同一领域，但样本纳入口径不同；
- 异常性差异来自纳入口径，不来自"更专业"或"更权威"的来源标签；
- 观测值在基线比较中保持不变；
- 题面提供判断所需的基线摘要，不能只提供来源名称和口径标签；
- 内容控制同时覆盖"更换适用基线后异常性改变"和"更换后结论仍不变"，避免固定方向策略；
- O18 只测基线适用性。多步误差传播、置信区间和阈值附近的定量计算应进入定量阈值新 family。

题面只询问当前观测应如何解释及依据，不提示口径错配、正确基线或"先比较再判断"的顺序；可比性关系和异常性后果保留为内部答案结构。

## 15. 第一部分交付物

每个生成算子交付：

1. 按统一内容定义模板完成能力轴、推理对象、题面构造、内容变换和内容不变量；
2. 明确父题中必须保留的推理义务，以及题目要求回答者自行完成的推理任务；
3. 不泄漏内部控制信息的 Prompt；
4. 与相邻算子的判别条件、禁止退化形态和近邻反例；
5. 正控制、结论不变负控制和表面交换控制的内容模板；
6. 目标错误和排除错误的语义说明；
7. 稳定 operator ID 的基础注册、现有 Router 的规则分派和生成 Prompt 调用接线。

第一部分的完成标准是 operator spec 和 Prompt 已完整表达目标能力、题面构造、竞争结构和算子语义边界，并能通过现有流水线按 operator ID 选择和调用。这里的可调用不代表完成资格验证、正式启用或新增机制级保障。

# 第二部分：算子校验规则

## 16. 机制级 Operator Contract

### 16.1 证据与资格状态

证据状态、资格结论和启用决策属于机制层，不写入第一部分的内容定义：

暂时无法在飞书文档外展示此内容

qualification_hypothesis 不得直接映射为 enabled。若专用数据上无法稳定形成目标推理结构，资格结果应记录为内容假设被证伪或证据不足，不得只继续调 Prompt 后自动启用。

### 16.2 统一契约结构

每个算子在代码和产物中保存统一契约：

```json
{
  "operator_id": "O13_minimal_disqualifier",
  "semantic_version": "2.0",
  "prompt_version": "o13_prompt_v3",
  "applicability_version": "o13_applicability_v2",
  "validation_policy_version": "operator_validation_v2",
  "evidence_status": "experiment_driven_revision",
  "ability_axis": "minimal_required_link_failure",
  "reasoning_object": "required_link",
  "preserved_parent_obligations": [],
  "required_reasoning_output": [
    "selected_fact_id",
    "broken_link_id",
    "claim_level_effect"
  ],
  "target_error_taxonomy": [
    "missed_link_break",
    "confidence_drop_vs_link_failure_confusion",
    "unsupported_full_reversal"
  ],
  "excluded_error_taxonomy": [],
  "required_fact_slots": [],
  "forbidden_fact_types": ["example", "suggestion", "external_knowledge"],
  "transformation_contract": {},
  "invariants": [],
  "answer_space": {},
  "operator_payload_schema": {},
  "scorer_mapping": {},
  "release_checks": [],
  "status": "enabled | disabled | validation_only"
}
```

统一规则：

1. ability_axis 与 target_error_taxonomy 在同一 semantic version 内不变。
2. required_fact_slots 在调用生成模型前检查，全部满足后才可生成。
3. transformation_contract 只规定语义变换，不规定题长、任务数或选项数的固定上限。
4. release_checks 明确区分 deterministic contract 和 probabilistic diagnostics。
5. 只有确定性契约错误可直接硬拒绝。
6. operator 结果必须绑定 answer contract，不能只输出自然语言的预期 focus。
7. 公共 contract 只保存所有算子共享的身份、版本、能力轴、错误分类和发布规则；算子专属结构进入 operator_payload_schema，不得因统一 schema 丢失。
8. 第一部分定义字段的语义，第二部分负责字段解析、持久化、版本迁移和校验；新增内容字段必须先完成端到端落盘测试。
9. required_reasoning_output 将第一部分描述的推理任务转成可观察的结构化结果，但不得要求保存模型的完整思维过程。
10. scorer_mapping 只把结构化结果映射到 answer contract 和 Rubric 项，不得反向改变第一部分定义的正确内容、目标错误或结论边界。

## 17. 校验状态与流程语义

### 17.1 算子状态

- enabled：通过资格实验，可进入 natural routing。
- disabled：不进入主路由、fallback 或 recommended_next_methods。
- validation_only：不产生题、不占候选数、不占轮次，只输出 validation findings。

### 17.2 运行时结果

- eligible：前置 slot 完整，允许调用生成模型。
- not_applicable：前置 slot 缺失或语义不符；不调用生成模型，不消耗候选预算，继续尝试下一个未测试算子。
- reject_candidate：已生成候选违反确定性契约；保留拒绝证据，继续尝试下一算子。
- diagnostic_risk：命中概率性风险；默认记录为 shadow 或 advisory，不直接拒绝。
- operator_space_exhausted：所有可用算子均不适用或候选被拒绝；保留父节点和既有评分，不强制选择 fallback。

## 20. 全局 O14 信息闭包 Validator

O14 固定为 validation_only，对所有算子候选检查：

1. 题面事实是否全部映射到可用 fact ID；
2. 是否增加未给中间状态；
3. 是否增加未给统计口径或业务阈值；
4. 是否把 derived、example 或 suggestion 写成已发生事实；
5. 反事实变换是否只使用授权的 allowed_transform。

O14 只输出 validation findings，不产生候选题记录。

## 21. 发布校验

### 21.1 确定性契约错误

以下问题证据充分时直接 reject_candidate：

- 公共 envelope 或当前 semantic version 的必需 operator_payload 缺失；
- contract 标记的决定性事实或决定性结构无法映射到可用 fact ID；
- 使用禁止事实类型或未授权变换；
- 缺失必需不变量；
- 答案不唯一且可由确定性规则或双独立 verifier 证明；
- answer contract 与 Rubric 的正确答案、目标命题、比较量、结论方向或决定性事实冲突；
- 在没有给定阈值时强制生成整体结论翻转。

### 21.2 概率性诊断

以下问题默认只记录 diagnostic，不直接硬拒绝：

- option-only 风险；
- fact-ablated 表现不稳定；
- surface-swapped 或版本顺序交换敏感；
- 候选长度、语气或信息量仍存在非决定性差异；
- 与相邻算子共享同一隐藏事实结构和求解过程，疑似换名同构；
- 父题核心推理义务在进化题中被预填或删除；
- 单个 verifier 不确定或 verifier 之间存在无法确定归因的分歧。

概率性诊断只有在资格实验中完成人工校准、证明高精度且误拒绝率可接受后，才可通过新的 policy version 升级为 blocking。

### 21.4 历史回放用例

以下已知问题作为通用回归 fixture：

- O13 金标与 Rubric 冲突时必须阻断发布；
- O13 模型选中破坏连接的事实，但将"减弱"写成"翻转"时，必须归因为结论层级校准错误；
- O15 同一题同时涉及事件发生机会与视频证据强度时，必须拦截比较量混用；

## 22. Answer Contract 与 Verifier

1. 生成器先输出目标命题、结论层级、算子专属答案对象、答案键、方向或关系、决定性结构和不变量。
2. Blind Solver 不接收生成器 key、operator ID、决定性 fact ID 或预期失败信息。
3. Contract Resolver 比较生成器假设、Blind Solver 结果和确定性规则检查。
4. 一致后冻结 answer contract；Rubric 必须消费冻结契约。
5. 金标与 Rubric 冲突时，Rubric 不发布、不生成 score prompt、不进入评分。
6. 模型选中破坏必要连接的事实，但将"减弱"写成"翻转"时，归因为结论层级校准错误，不归因为决定性事实识别错误。
7. Rubric 只能把 required_reasoning_output 展开为评分项，不得改变算子专属答案对象、目标错误 taxonomy 或结论上限。
8. Scorer 只能消费 contract 中声明的结构化结果；方向、标签或分值映射不得写回题面，也不得成为第一部分的内容约束。

## 23. 算子资格实验

### 23.1 Forced Qualification

目标是评估算子 Prompt 本身，不评估 Router。

1. 使用人工确认满足前置的专用 manifest。
2. 强制指定 operator，同时保存 Router shadow 结果。
3. 使用隔离 Memory。
4. 保持事实账本、answer contract、模型配置和 Judge 配置固定。
5. 同一 operator 覆盖不同场景表面，验证语义轴是否稳定。

### 23.2 Natural Routing Validation

只在 forced qualification 证明算子可用后开始：

1. 使用未参与 Prompt 调整的 holdout。
2. Router 根据事实 slot 生成算子计划。
3. 统计正确适用、错路由、遗漏路由和不适用提前拦截。

### 23.3 成功判定

不使用单一"平均降分"作为算子资格指标。至少同时检查：

- 事实契约合格率；
- 答案唯一性与 Rubric 一致性；
- 题面泄漏风险；
- 父题核心推理义务保留率；
- required reasoning output 的可观察完成率；
- 与相邻算子的语义同构率；
- 相邻算子近邻的正确归属或不适用率；
- 目标错误 taxonomy 命中率；
- 人工确认边界率；
- 不同场景中的方向稳定性。

## 24. 实施顺序

### 24.1 第一部分：算子内容

**阶段 C0：内容模板与语义轴**

1. 为 O10-O18 按统一内容模板明确能力轴、推理对象、题面构造、目标错误和排除错误。
2. 落实相邻算子内容边界、禁止退化形态和近邻反例。
3. 明确父题必须保留的推理义务和各算子的内容正负控制。

**阶段 C1：优先修复 O13/O15**

1. O13 完成候选隐藏角色和推翻层级内容。
2. O15 完成单一比较量、单一结论层级、固定门槛和无阈值偏序表达。

**阶段 C2：修复 O10/O12/O16**

1. O10 引入真正的集合级最小充分关系和成员消融结构。
2. O12 生成 X/Y/X+Y 语义对照。
3. O16 生成单一替代解释、双假设覆盖矩阵和 discriminator 消融控制。

**阶段 C3：准备 O11/O17/O18 内容**

1. O11 完成端点时序一致性题型内容。
2. O17 完成双规则边界映射题型内容。
3. O18 完成双基线纳入口径比较题型内容。

**阶段 C4：基础注册与调用接线**

1. 保持 O10-O18 的稳定 operator ID，为 O10-O13、O15-O18 生成规格完成基础注册；O14 只保留既有验证型身份，不新增生成题面。
2. 让现有 Router 能按各算子的主要推理对象完成基础规则分派。
3. 验证各生成算子可通过统一 Prompt 构造入口被调用；不在本阶段增加前置门控、资格状态、发布校验或路由质量机制。

### 24.2 第二部分：校验与流程

**阶段 V0：事实与答案契约**

1. 确认事实账本、answer contract 和结构化归因可用。
2. 为内容修改建立新 prompt version，不覆盖历史 spec。
3. 扩展公共 contract envelope，并为 O10-O18 注册和持久化 operator_payload_schema。
4. 为 O10-O18 补齐 required_fact_slots、forbidden_fact_types 和 release_checks。
5. 增加 semantic、prompt、applicability、validation policy 版本和 recipe hash。
6. 增加端到端落盘测试，未知 payload 字段不得静默丢失。

**阶段 V1：路由状态与生成前门控**

1. O14 移出生成 registry、fallback 和 recommended_next_methods。
2. O17 保持 disabled。
3. O11、O17、O18 缺硬前置时在生成调用前返回 not_applicable。
4. not_applicable 不占候选预算，继续下一未测试算子。
5. 算子耗尽时写入 operator_space_exhausted，保留父节点。

**阶段 V2：发布校验**

1. 实施 O14 全局信息闭包 validator。
2. 实施 answer contract 冲突、比较量混用、阈值缺失、结论层级和必需 payload 缺失的确定性检查。
3. 为 option-only、fact-ablated、surface-swapped、推理负担漂移和跨算子同构建立 shadow 诊断。
4. 数量字段保持 record_only，不影响准入、排序和重试。

**阶段 V3：资格实验与路由启用**

1. 对每个算子运行 forced qualification。
2. O11、O17、O18 建设专用数据并通过资格实验后，再逐个启用 natural routing。
3. 使用 holdout 检查路由精度、错路由、遗漏路由和提前拦截。
4. 检查 fallback 是否又集中回 O10/O12。
5. 不同算子使用隔离报告和 Memory，仅将 confirmed result 写入正式算子记忆。

## 25. 测试与验收

### 25.1 算子内容验收

暂时无法在飞书文档外展示此内容

所有生成算子还必须证明：

- 父题核心推理义务没有被题面预填或删除；
- required reasoning output 可从回答中观察和评分；
- 结论不变负控制不会被固定判向策略误答；
- 相邻算子近邻能够正确转交或判为不适用；
- 表面交换不改变语义答案和算子归因。

### 25.2 校验规则验收

- 每个 operator 有完整 version、required slots 和 release checks；
- 每个 operator 的专属 payload 能端到端解析、持久化和回放，未知字段不静默丢失；
- 当前禁用和 validation-only 算子不进入生成路由；
- O11、O17、O18 缺任一硬前置时不调用生成模型；
- not_applicable 不消耗候选预算，且继续尝试下一算子；
- 数量字段只记录，不决定准入、排序和重试；
- 每个候选可追溯公共 envelope、算子专属 payload、target claim 和 answer contract；
- O14 只输出信息闭包 findings，不产生题；
- answer contract 与 Rubric 冲突的候选不进入答题和评分。

### 25.3 系统级验收

1. 同一事实对不再在 O10/O12/O13/O15/O16 之间反复换名生成。
2. Router 不再将"提到盲区"等同于"满足 O11"。
3. 现有算子的资格结论可分别归因于 Prompt、数据、Router、validator 或模型能力。
4. 所有降分候选都有具体错误 taxonomy，不再使用通用词面对齐作为主要命中依据。
5. 所有算子耗尽时保留父节点和历史产物，不强制 fallback 或静默丢失搜索机会。
6. 开放事实组织任务不会因进化而稳定退化为只判断方向的封闭题。
7. O11/O17/O18 的报告明确区分"设计假设被确认、被证伪或证据不足"，不使用笼统的已修复结论。

## 27. 完成定义

### 27.1 第一部分完成

1. O10-O18 均按统一内容模板明确能力轴、推理对象、题面构造、内容变换、不变量、竞争结构和禁止捷径；
2. O10-O18 的目标与排除错误、相邻算子边界、禁止退化形态和近邻反例已明确；
3. O10 使用集合级最小充分关系，O13 分开连接失效与整体结论，O15 固定比较量、结论层级和门槛；
4. O10/O12/O16 的题型内容不再依靠显性唯一差异；
5. 开放任务的核心推理义务没有因方向标签隐藏而被删除或预填；
6. O11/O17/O18 的内容定义不依赖题外事实或常识补全。
7. O10-O18 的生成算子已完成基础注册，现有 Router 能识别其主要推理对象，并可通过统一生成入口构造 Prompt。

### 27.2 第二部分完成

1. O10-O18 的事实前置、公共 envelope、算子专属 payload、答案契约和发布检查均机器可读且可完整回放；

4. O11/O17/O18 只在专用前置数据上调用生成；
5. 答案契约冲突、事实越界、必需 payload 缺失、比较量混用和确定阈值缺失被正确拦截；
