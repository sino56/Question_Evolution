# 题面信息职责隔离与全算子语义泄漏治理优化方案

## 文档状态

- 状态：待实施；
- 范围：O10–O33、公共生成上下文、题面校验、候选分流、效果确认和算子资格；
- 前置决策：允许受控假设事实，但只允许新增观察级事实；
- 主流程影响：不改变现有 pipeline 阶段顺序，仅改造 `question_evolution.py` 内部生成职责和后续校验契约；
- 历史兼容：新增字段均为可选嵌套字段，旧数据继续走 fallback。

## 摘要

本方案针对 Question Evolution 当前最主要的生成失效：进化题通过补足事实链、直接解释规则边界、提前排除竞争解释、预先绑定实体角色，使弱模型不再需要完成目标推理，最终出现进化后得分升高或保持满分。

本方案不把问题归结为题目过长，也不继续依赖追加禁词。核心改造是建立严格的信息职责边界：隐藏结构规划器负责设计目标推理负担，题面编写器只能看到原子事实和中性问题意图，独立校验器同时检查信息闭包、答案泄漏、竞争关系和算子专属推理负担。只有通过全部硬门禁的候选才能进入主链评分。

方案覆盖全部 O10–O33。O14 不再作为生成算子，而是升级为全局信息闭包校验。其他算子均需重写生成要求和专属校验，不允许只修复 O27、O28、O31 等已暴露问题的算子。

本方案允许在父题缺少竞争实体、替代解释或必要结构时构造受控假设案例，但新增内容只能是可观察事实，不得冒充原始事实，不得补造法规、阈值、业务结论或答案边界。

## 1. 问题背景

外部实验结果显示，大量候选并未增加目标推理负担，反而把原题中需要回答者完成的推理写进了题面。典型表现包括：

1. 补足装载、运输、交付、卸载等事实链，使原本存在的链路缺口消失。
2. 直接说明材料“只能支持什么”“尚不能确认什么”或“需要补充什么”。
3. 给竞争解释增加显性排除事实，使回答者无需比较覆盖、冲突和残差。
4. 把实施者、协助者、控制者、受益者等角色关系整理成完整叙述。
5. 把规则、规则适用对象、当前事实映射和结论上限一起交给模型。
6. 用题面总结句复述正确答案，即使没有使用现有禁词也形成语义等价泄漏。

这类问题会造成：

- 弱模型通过复述题面获得高分；
- 进化题比父题更容易；
- `score_increased` 大量出现；
- 自动效果标签将题面泄漏误认为能力边界；
- operator memory 记录错误成功经验；
- 后续轮次继续强化同一种失败形态。

## 2. 当前实现的根因

### 2.1 生成模型同时承担结构设计和题面表达

当前生成模型既知道算子目标、目标错误、竞争结构和正确判断，又负责把这些内容写成自然题面。即使 Prompt 要求“不要泄漏答案”，模型仍然倾向于把内部结构转换成更委婉的答案提示。

例如，内部控制是“当前事实只能支持关联，不能支持稳定运输关系”。模型可能避开“不能支持”，但改写为：

```text
这些行为尚不足以形成稳定运输链条，仍需观察是否存在持续交付。
```

表面禁词发生变化，答案内容没有变化。

### 2.2 父题整段文本被当作可观察材料

父题中的问题措辞可能已经包含结论方向，例如“为什么不能直接认定”“现有材料最多能说明什么”。如果生成阶段直接接收父题全文，即使参考答案和 Rubric 已隔离，答案方向仍会从原始问题进入新题。

因此，父题必须先拆分为：

- 可观察事实；
- 原始规则或定义；
- 中性业务目标；
- 结论性问题措辞；
- 答案提示或边界提示。

只有前三类经过校验后可以进入后续生成。

### 2.3 当前校验器偏向词面检查

现有检测更容易发现“不能推出”“最高支持”“不足以认定”等显式词语，但不能稳定发现语义等价表达，也不能判断题面是否已经完成目标链条、角色绑定或竞争解释淘汰。

### 2.4 部分算子定义内部存在冲突

当前部分算子的 `required_question_shape`、`goal` 和 `semantic_economy` 同时包含相反要求。例如：

- O27 要求形成结论并说明边界，同时要求题面不询问边界；
- O31 要求回答“能支持到什么程度”，等于直接暴露证据校准任务；
- O33 要求说明材料共同支持的边界，容易引导模型复述来源上限；
- O28 要求每个必要跳转都有题面事实，负例容易被补成完整链；
- O17 要求完整规则和适用对象，容易退化为规则查表。

这类冲突必须从算子定义层消除，不能只靠公共 Prompt 补救。

## 3. 目标与非目标

### 3.1 目标

本方案必须实现以下目标：

1. 题面只呈现原子观察、必要的原始规则和中性问题意图。
2. 目标链条、事实角色、竞争解释排序、规则适用结论和答案边界不得进入题面编写上下文。
3. 所有 O10–O33 均具有明确的题面允许项、禁止项和专属控制测试。
4. O14 成为所有生成候选共同使用的信息闭包校验器。
5. 校验器能够识别语义等价泄漏，而不是只识别固定禁词。
6. 硬泄漏候选不得进入主链评分；结构弱风险可按预算进入 exploration。
7. `effective_boundary_probe` 必须由真实目标错误命中支持，不能只依赖降分或关键词匹配。
8. 保留当前主流程顺序、已有 JSONL 字段和历史数据 fallback。

### 3.2 非目标

本方案不做以下工作：

- 不重写完整 pipeline；
- 不引入完整树搜索、BFS、DFS、UCB 或深层回溯；
- 不修改 Rubric 和 scoring Prompt 的核心评分语义；
- 不把 validator 改成拒绝所有不确定候选的 candidate rejection system；
- 不要求历史实验数据强制迁移；
- 不通过简单缩短题目代替语义泄漏治理；
- 不允许 Global Judge 或 Memory 自动修改正式算子 Prompt。

## 4. 核心设计决策

### 4.1 采用三段隔离架构

生成过程拆为三个职责单一的阶段：

```text
父题事实解析
-> 隐藏结构规划
-> 题面事实编译
-> 盲题面编写
-> 独立语义校验
-> 通过 / 定向重试 / 拒绝或探索
```

各阶段的信息权限如下：

| 阶段 | 可以看到 | 不可以看到 |
|---|---|---|
| 父题事实解析 | 父题、允许的上下文 | 无 |
| 隐藏结构规划 | 算子完整契约、父题事实、目标错误 | 无 |
| 题面事实编译 | 规划器产生的事实候选和来源 | 最终自然题面 |
| 盲题面编写 | 原子事实池、中性问题意图、写作约束 | 正确答案、事实角色、正确解释、规则适用结论 |
| 独立语义校验 | 候选题面、隐藏控制、来源映射 | 不参与题面生成 |

同一个 LLM 调用不得同时输出隐藏答案结构和最终题面。否则模型仍然可以把隐藏结构转写到题面。

### 4.2 区分问题意图和答案目标

题面编写器可以知道问题类型，例如：

```text
根据材料判断当前业务主张是否成立，并说明依据。
```

题面编写器不得知道：

```text
正确答案是不能成立，因为第三跳缺失。
正确角色是 B，A 只能解释外围行为。
当前证据只能支持关联，不能支持稳定运输关系。
```

算子的能力轴、目标错误和正确结构只用于隐藏规划和校验。

### 4.3 允许受控假设事实

当父题缺少竞争实体、替代解释或关键断点时，允许构造明确的假设案例。受控假设事实必须满足：

1. `origin` 标记为 `controlled_hypothetical_observation`；
2. 只能描述可观察行为、时间、位置、记录或数值；
3. 不得新增现实法规、行业规则、专业阈值或外部知识；
4. 不得新增“因此、足以、只能、应当”等结论；
5. 不得冒充原样本中真实发生的事实；
6. 必须保留父题的核心业务判断和能力义务；
7. 无法在这些限制内构造可答题目时，应返回 `not_applicable` 或透传。

### 4.4 原始规则可以出现，规则应用答案不得出现

O17、O18、O25、O26 等算子必须提供规则、口径、流程或公式。方案不禁止这些原始输入，但必须分离：

允许：

- 原始规则文本；
- 规则版本和对象字段；
- 纳入标准；
- 程序步骤和记录映射；
- 公式、单位、误差和阈值。

禁止：

- 当前事实满足哪条规则；
- 哪条规则只支持行动、不支持事实认定；
- 当前结果是否跨过阈值；
- 当前流程破坏了哪个不变量；
- 当前材料最多允许形成什么结论。

### 4.5 保持 validator 的分流职责

硬泄漏、事实补造和不可回答属于确定性失败。竞争不足、信息显著性偏差和推理负担偏弱属于结构风险，应先定向重试，重试后仍不理想时进入 exploration 或透传，而不是一律 hard reject。

## 5. 统一数据契约

### 5.1 原子事实契约

每项可进入题面的事实必须具有稳定来源：

```json
{
  "fact_id": "F03",
  "origin": "source_observation",
  "content": "18时42分，车辆甲从北门驶出。",
  "source_ref": "parent_prompt:sentence_4"
}
```

受控假设事实示例：

```json
{
  "fact_id": "H02",
  "origin": "controlled_hypothetical_observation",
  "content": "假设案例中，19时06分，人员乙在南门附近接触车辆甲。",
  "source_ref": null
}
```

原始规则示例：

```json
{
  "fact_id": "R01",
  "origin": "provided_rule_primitive",
  "content": "规则要求结果区间整体高于阈值 T 时才进入下一处理状态。",
  "source_ref": "parent_prompt:rule_1"
}
```

### 5.2 隐藏结构契约

隐藏结构只供规划器和校验器使用：

```json
{
  "target_claim": "当前材料是否支持目标业务主张",
  "answer_mode": "binary | calibrated | ranking | selection | quantitative",
  "required_inference_obligations": [
    "跨实体绑定时间连续性",
    "检查第三跳是否指向同一对象"
  ],
  "competing_interpretations": [
    {"id": "C1", "status": "target"},
    {"id": "C2", "status": "live_competitor"}
  ],
  "decisive_fact_ids": ["F03", "H02"],
  "irrelevant_control_fact_ids": ["F07"],
  "forbidden_surface_propositions": [
    "第三跳缺失",
    "现有材料不能支持完整运输关系"
  ]
}
```

`status`、`decisive_fact_ids` 和 `forbidden_surface_propositions` 不得进入题面编写器上下文。

### 5.3 持久化位置

为兼容现有字段，不新增临时顶层字段。建议将非答案型审计信息写入：

```text
meta_info.question_evolution_metadata.generation_contract
validation_result.semantic_leak_checks
candidate_selection
effect_analysis
```

完整隐藏答案控制优先在 `question_evolution.py` 与 `validate_evolved_question.py` 之间以内存或临时候选 sidecar 传递。若必须持久化，必须由显式白名单保证其不进入题面编写、作答和评分模型上下文。

历史记录缺少新字段时走旧数据 fallback，不要求迁移。

## 6. 统一题面内容规则

### 6.1 允许进入题面的语义角色

- 可直接观察的事实；
- 假设案例中的可观察事实；
- 题目作答不可缺少的原始规则；
- 公式、单位、阈值和统计摘要；
- 中性的业务问题。

### 6.2 禁止进入题面的语义角色

| 类型 | 定义 | 例子 |
|---|---|---|
| `derived_fact_summary` | 必须组合多条事实才能得到的总结 | “多次行为已经形成稳定分工” |
| `target_chain_disclosure` | 已按答案顺序连接的事实链 | “甲装载、乙运输、丙卸货，形成完整链条” |
| `fact_role_disclosure` | 标明事实在答案中的作用 | “关键事实是第三次交付” |
| `rule_ceiling_disclosure` | 解释当前事实可适用到的规则上限 | “这些材料只能支持继续追踪” |
| `role_binding_disclosure` | 预先绑定行为和角色 | “乙是运输者，丙负责接应” |
| `competitor_elimination` | 直接说明竞争解释不成立 | “偶然同行无法解释连续等待” |
| `answer_direction_disclosure` | 直接或委婉预告结论方向 | “目前仍不能形成确定判断” |
| `answer_template_disclosure` | 把内部推理步骤变成题面作答模板 | “分别说明事实层和行动层结论” |

### 6.3 原子事实编写要求

1. 一句话只表达一项观察或一项原始规则。
2. 不用“因此、表明、意味着、足以、仅能、由此可见”等推导连接词。
3. 不把行为、角色和结论写在同一句中。
4. 不在题尾重复或总结全部事实。
5. 正确项不得独占数字精度、完整路径、专业来源或更长描述。
6. 除算子专属计算外，正确答案不得由单独一句话决定。
7. 问题结尾使用中性问法，不询问“上限、边界、不能推出什么”。

## 7. O10–O18 全量修改要求

### 7.1 O10 最小充分事实集

生成要求：

- 题面只给同粒度原子事实；
- 最小集合成员、相关事实和冗余事实只在隐藏控制中标记；
- 题面只询问业务主张是否成立及依据；
- 正确集合不得独占完整因果叙述。

禁止：

- 提示哪些事实共同构成闭环；
- 把最小集合写成连续事实链；
- 要求回答者选择“必要事实集合”；
- 用信息量差异暗示正确组合。

专属控制：删除任一必要成员后结论应减弱；删除相关干扰事实后结论保持不变。

### 7.2 O11 端点时序一致性

生成要求：完整提供可见端点、时间窗、方向、路径或速度范围；候选假设均需解释部分端点事实。

禁止：补造盲区内事件；给出预计算路径；用单个明显超时数字直接排除错误项。

专属控制：交换候选名称不改变答案；每个候选至少满足一个局部约束；正确判断必须依赖联合约束。

### 7.3 O12 独立性与共同必要性

生成要求：X、Y、X+Y 仅存在于隐藏控制，题面呈现为未标注、信息量可比的自然案例。

禁止：联合版本更长、更完整、更肯定；公开 X/Y 标签；提示两个条件必须共同满足。

专属控制：覆盖仅 X、仅 Y、X+Y、X+Y 仍不足和单项冗余五种情况；交换 X/Y 后语义答案不变。

### 7.4 O13 必要连接破坏

生成要求：混合呈现多个同观察类别、同证据类型的复核事实；是否存在替代支持路径只保存在隐藏控制。

禁止：点名断点、必要连接、替代路径或整体翻转；让破坏事实独占否定词。

专属控制：删除破坏事实后局部连接恢复；存在替代路径时不得将局部失效升级为整体翻转。

### 7.5 O14 信息闭包

O14 不生成独立题面，正式承担全局事实来源校验：

- 每条事实映射到父题事实、受控假设事实或原始规则；
- 拒绝补造中间状态、统计口径、业务阈值和外部知识；
- 拒绝把经验判断写成已发生事实；
- 输出精确的无来源句子和来源缺口。

### 7.6 O15 单变量门槛变化

生成要求：只新增、删除或替换一个核心事实；其他事实、比较量、结论层级和规则保持不变。

禁止：同时改变事实和阈值；用正负措辞预告方向；无明确阈值时预告整体翻转。

专属控制：前后版本差异严格限制为一个决定性变量；交换前后呈现顺序不改变语义关系。

### 7.7 O16 相近解释覆盖与残差

生成要求：两个解释均覆盖部分事实并各自留下残差；区分事实自然混入其他同粒度观察。

禁止：一句话直接否定替代解释；目标解释形成无残差完整闭环；公开覆盖、冲突和残差字段。

专属控制：删除区分事实后两个解释重新接近；交换解释名称和顺序不改变答案。

### 7.8 O17 双规则边界映射

生成要求：保留不可缺少的原始规则、版本、对象字段和阈值；当前事实独立呈现。

禁止：解释哪条规则适用于当前事实；标注动作层和事实层；把规则重写成当前答案；生成规则查表步骤。

专属控制：交换规则名称和顺序不改变答案；规则版本、适用对象和边界值分别制作单变量控制。

### 7.9 O18 基线纳入口径

生成要求：两个基线均给出原始纳入条件和完成判断所需的统计摘要，当前观测保持不变。

禁止：说明哪个基线更合适；正确基线拥有更权威来源或更完整摘要；提示先比较口径再判断异常。

专属控制：交换来源名称不改变答案；改变不参与纳入口径的统计项不改变答案。

## 8. O19–O27 全量修改要求

### 8.1 O19 多实体角色绑定

生成要求：分散呈现实体在不同时间的局部动作，实体描述保持对称，角色关系由回答者恢复。

禁止：形成装载、运输、接应、卸载的完整角色表；直接命名实施者、协助者或受益者；用出场顺序提示角色。

专属控制：交换实体名称不改变逻辑；只有改变决定性行为归属时答案才改变。

### 8.2 O20 多阶段事件链断点

生成要求：自然呈现事件和状态变化，保留局部成立但整体可能失效的结构。

禁止：编号阶段、标记断点、在结尾总结完整状态链、把最后出现的异常写成显然断点。

专属控制：修复真正断点后整体结论改变；修改旁支事件不改变结论。

### 8.3 O21 对象来源与同一性

生成要求：提供对象转移、出现、遮挡、重现和竞争来源的原始记录。

禁止：输出完整来源链；使用唯一编号直接给答案；把外观相似总结成同一对象。

专属控制：补足关键转移记录后同一性结论增强；改变颜色、名称等无识别力特征不改变答案。

### 8.4 O22 路径拓扑联合可达

生成要求：提供原始方向边、开放窗口、端点和耗时，候选路径各自满足部分约束。

禁止：提供预计算路径、路线总结、唯一可行提示；用路径数量制造难度。

专属控制：反转决定性边或改变窗口后答案改变；修改候选路径外的旁支边不改变答案。

### 8.5 O23 观测可靠性冲突

生成要求：提供距离、遮挡、采样时段、来源生成关系和实际可见字段。

禁止：直接写“画面不清所以不能确认”；将来源标为可靠或不可靠；用来源权威性替代质量事实。

专属控制：改善决定性采集条件后答案可以增强；复制同一受限来源不增强答案。

### 8.6 O24 多假设残差排序

生成要求：共同事实独立呈现，各解释保持交叉覆盖；解释名称、顺序和复杂度保持平衡。

禁止：按解释分组罗列支持事实；给出覆盖矩阵、残差清单或排名步骤；正确解释独占事实并集。

专属控制：增加各解释共同覆盖的事实不改变排序；加入真正区分关键残差的事实时排序才改变。

### 8.7 O25 程序不变量与参照系

生成要求：提供流程步骤、字段、单位、参照变化和记录映射，不解释哪项是不变量。

禁止：标记错误步骤；说明结果不可比较；将格式整齐与程序有效绑定。

专属控制：恢复关键映射或参照转换后有效性改变；只改变记录格式不改变结论。

### 8.8 O26 定量阈值与误差传播

生成要求：完整提供公式、单位、输入区间、误差关系和业务阈值，保证无需外部公式。

禁止：给出中间计算、结果区间、阈值比较结果；加入不参与计算的装饰数字。

专属控制：重算结果唯一；无关数字变化不影响答案；覆盖跨阈值、不跨阈值和刚好接触阈值三类样本。

### 8.9 O27 跨层结论校准

生成要求：父题已有规则时只保留原始条款和事实；父题没有规则时不得补造业务结论边界。

禁止：询问最高支持、结论边界、不能推出什么；提前完成观察到事实、事实到表述、表述到行动的映射。

专属控制：删除局部证据只影响依赖该证据的下游结论；不得自动翻转所有层级。

## 9. O28–O33 全量修改要求

### 9.1 O28 多跳链路闭合

生成要求：只呈现跨节点原始观察；每个已声称的跳转必须有事实，但负例允许必要跳转缺失。

禁止：按答案顺序补足完整链；给出链路总结；从终点反推并补写缺失跳转。

专属控制：补足唯一缺失承接后答案改变；改变不在主链上的旁支节点不改变答案。

### 9.2 O29 实体同一性冲突消解

生成要求：支持线索、连续线索和冲突线索混合呈现，保持信息粒度一致。

禁止：标记排他冲突；正确身份拥有更多细节；将同位置或外观相似直接总结成同一实体。

专属控制：翻转决定性冲突后归属改变；增加普通相似特征不自动增强归属。

### 9.3 O30 主动判别观测选择

生成要求：给出当前竞争解释和可执行观测条件，可以提供自然候选观测，但不提供结果预测。

禁止：给出观测结果分支表；说明哪项最有判别力；把最低成本或信息最多直接等同最佳。

专属控制：无论结果如何都不改变解释排序的观测必须判为低价值；交换候选顺序不改变答案。

### 9.4 O31 观测累积校准

生成要求：提供观察的原始来源和生成关系，例如转录、截取、同一片段、不同点位。

禁止：将观察总结为独立、同源或可累计；询问“能支持到什么程度”；按观察条数暗示强度。

专属控制：复制、转述和同源派生不增加结论强度；真正独立的新特征才允许增强。

### 9.5 O32 角色关系图关键边

生成要求：只描述局部方向性行为，实体身份保持清晰，关系边由回答者恢复。

禁止：把行为整理成文字关系图；标关键边、控制者或协助者；用节点中心度提示答案。

专属控制：删除或反转必要边时结论改变；改变冗余边时结论不变。

### 9.6 O33 跨模态支持边界

生成要求：每个来源只给实际字段、时间、对象和采集范围；对齐和融合由回答者完成。

禁止：总结各模态能支持什么；询问共同支持边界；按来源数量或技术名称暗示证据更强。

专属控制：未对齐材料不能叠加；加入不能观察目标属性的来源不得增强结论；完成关键时间或实体对齐后才允许增强。

## 10. 校验器设计

### 10.1 第一层：事实来源与信息闭包

确定性检查：

- 每项事实是否具有 `fact_id`；
- `origin` 是否属于允许枚举；
- 原始规则是否来自父题或明确的题内定义；
- 是否存在无来源中间状态、阈值或业务规则；
- 受控假设事实是否被明确写成假设案例。

以下情况 hard reject：

- 无来源事实；
- 外部知识被写成已发生事实；
- 新增业务规则或阈值；
- 假设事实冒充原事实。

### 10.2 第二层：语义泄漏检查

在 `validation_result.semantic_leak_checks` 中记录：

```text
target_chain_disclosure
derived_fact_summary
rule_ceiling_disclosure
role_binding_disclosure
competitor_elimination
answer_direction_disclosure
answer_template_disclosure
salience_imbalance
```

校验器需要比较题面命题与隐藏控制命题的语义关系，不能只做字符串匹配。

### 10.3 第三层：单句直达答案检查

独立 Judge 需要回答：

1. 是否存在一句话在不组合其他事实时就基本决定答案；
2. 该句对应隐藏答案中的哪个命题；
3. 删除该句后是否仍能完成算子目标推理。

除原始规则和专属定量输入外，单句直达答案进入定向重试。

### 10.4 第四层：竞争关系存活检查

校验器必须验证：

- 至少两个竞争判断在组合推理前均有事实支持；
- 错误竞争项不能由单句直接排除；
- 正确项不能独占完整解释；
- 区分依赖多事实组合或算子规定的专属计算；
- 删除区分事实后竞争关系应重新接近。

竞争偏弱属于结构风险，不直接永久拒绝算子。

### 10.5 第五层：角色和表面偏差检查

针对实体、解释、路径、规则和候选观察执行：

- 名称交换；
- 呈现顺序交换；
- 描述长度交换；
- 专业来源名称替换；
- 精确数字位置交换。

交换后语义答案必须保持不变。如果答案随表面特征变化，标记 `salience_imbalance`。

### 10.6 第六层：链条预闭合检查

针对 O10、O13、O20、O21、O22、O28 检查：

- 是否存在完整的起点到终点顺序总结；
- 是否每一跳已经被题面解释；
- 是否在结尾重复全部链条；
- 是否只需复述题面便可作答；
- 是否仍需进行实体、时间、状态或路径绑定。

### 10.7 第七层：可回答性和专属负担

通过前述检查后，还必须验证：

- 不依赖题外知识；
- 不存在事实矛盾；
- 题面足以得到唯一答案或有依据的校准答案；
- 隐藏控制要求的推理义务确实在题面中存在；
- 难度来自目标能力轴，而不是格式、篇幅或计算繁琐度。

## 11. 重试和候选分流

### 11.1 定向重试映射

| 失败标签 | 重试动作 |
|---|---|
| `target_chain_disclosure` | 删除链路总结，将其拆回原子观察，不删除必要事实 |
| `derived_fact_summary` | 删除总结命题，恢复其来源观察，禁止同义改写总结 |
| `rule_ceiling_disclosure` | 保留原始规则，删除规则对当前事实的适用结论 |
| `role_binding_disclosure` | 删除角色名称，只保留带时间和方向的行为 |
| `competitor_elimination` | 删除直接反驳句，为竞争解释保留局部支持 |
| `answer_direction_disclosure` | 将问题和事实改为中性表达，不得用谨慎措辞替代答案 |
| `answer_template_disclosure` | 删除分层、逐项和边界作答要求，恢复自然业务问题 |
| `salience_imbalance` | 平衡信息量、句式和精度，不得增加答案解释 |
| `unanswerable_after_cleanup` | 补回缺失原子事实，不得补回答案总结 |

每种失败最多执行一次针对性重试。第二次仍存在同类硬泄漏时，该候选 hard reject；结构风险则按 exploration 预算或透传处理。

### 11.2 分流语义

`hard_reject`：

- 信息闭包失败；
- 直接或语义等价答案泄漏；
- 明确角色绑定；
- 明确竞争解释排除；
- 不可回答或事实矛盾；
- 新增无来源规则和阈值。

`main_chain_candidate`：

- 信息闭包通过；
- 无硬泄漏；
- 专属推理义务存在；
- 可回答；
- 竞争关系和表面交换检查通过。

`exploration_candidate`：

- 无硬风险；
- 竞争性、显著性或推理负担存在轻度不确定；
- 已经过一次定向重试；
- 每组和每轮均受现有 exploration 预算限制。

`pass_through_candidate`：

- 无法在不补造规则、不补答案链的前提下完成算子改写；
- 题面已无可用进化空间；
- 算子虽适用主题，但无法形成目标能力负担。

## 12. 效果分析和成功记忆修正

`effective_boundary_probe` 必须同时满足：

1. `score_delta < 0`；
2. 弱模型答案命中该算子的目标错误；
3. 强答案或参考答案通过同一 Rubric；
4. 题面无硬泄漏、不可答和事实冲突；
5. 降分不是由格式、题面异常、Judge 波动或 Rubric 偏移造成；
6. effect evidence 明确指出目标错误与算子能力轴的对应关系。

只满足降分、关键词焦点或模型答案变短时，不扩展现有主效果枚举，而是在 `effect_analysis.effect_confirmation_status` 中标记为 `ambiguous_effect`，不得写 operator success memory。

`score_increased` 保持现有负收益语义：

- 写入 failure memory；
- 不进入成功终止态；
- 不写 operator success memory；
- 下一轮切换 operator 或策略。

## 13. 具体实施阶段

### 阶段 0：失败基线和回放集

目标：在修改代码前固定当前失败形态，避免优化后只改变表现形式。

实施内容：

1. 从外部报告整理以下泄漏夹具：事实链补全、规则上限、竞争解释淘汰、角色预绑定、谨慎答案措辞、显式判别条件。
2. 为每类泄漏准备直接表达和语义等价表达。
3. 为所有 O10–O33 建立最小正例、负例、泄漏反例、消融例和交换例。
4. 记录当前 validator 对每类夹具的命中和漏检情况。

建议新增测试文件：

```text
tests/test_surface_fact_contract.py
tests/test_generation_context_isolation.py
tests/test_semantic_leak_replay.py
tests/test_operator_counterfactual_controls.py
```

退出条件：现有失败能够在固定夹具中重现，所有预期失败均有明确标签，不使用自由文本代替断言。

### 阶段 1：父题事实解析和上下文净化

目标：阻止父题的问题措辞和答案方向继续进入题面编写上下文。

涉及文件：

```text
semantic_budget.py
question_evolution.py
prompts/operators/base.py
```

实施内容：

1. 将父题拆分为观察事实、原始规则、中性问题意图和禁止传播的结论性措辞。
2. `observable_fact_ledger` 不再保存未解析的完整父题作为单一事实。
3. 对无法可靠拆分的输入采用保守 fallback：保留原题或进入 exploration，不允许自由补写。
4. 为每项事实生成 `fact_id` 和 `origin`。
5. 保持历史字段不变，新契约放入 `meta_info.question_evolution_metadata`。

测试重点：

- 父题中的“不能直接认定”不进入 surface writer；
- 原始时间、行为和位置事实仍完整保留；
- 原始规则与规则解释被正确分开；
- 历史样本缺少新字段时仍能运行。

退出条件：surface writer 输入快照中不存在参考答案、Rubric、结论性父题问法和隐藏目标错误。

### 阶段 2：隐藏规划与盲题面编写分离

目标：从调用结构上阻止同一模型同时掌握答案结构和最终题面。

涉及文件：

```text
question_evolution.py
prompts/operators/base.py
prompts/operators/new_operator_support.py
```

实施内容：

1. 新增隐藏结构规划步骤，输出事实池、竞争解释、决定性事实和控制关系。
2. 新增题面事实编译步骤，只筛选允许公开的原子事实和原始规则。
3. surface writer 只接收编译后的事实池、中性问题意图和写作要求。
4. 规划器和 surface writer 使用独立调用上下文；禁止通过完整 sample dict 隐式传递隐藏字段。
5. 生成失败写入 `*.failed` 时保持非零退出语义。

测试重点：

- surface writer 的实际请求体不含 hidden control；
- 相同 prompt 的不同 `sample_id` 分别保留；
- 受控假设事实具有明确来源；
- 规划失败和题面编写失败不会产生不完整正式输出。

退出条件：上下文隔离测试通过，运行日志能够分别审计 planner 和 writer 的输入字段白名单。

### 阶段 3：全部算子内容重写

目标：修复 O10–O33 的算子级语义冲突和泄漏倾向。

实施顺序：

1. O10–O18：修复既有算子，O14 转全局 validator；
2. O19–O27：修复实体、事件、路径、观测、规则和跨层算子；
3. O28–O33：修复多跳、身份、主动观测、累积、角色图和跨模态算子；
4. 统一审查公共 `base.py`，确保没有重新注入完整目标链。

每个算子文件必须修改或确认：

- `goal` 只描述隐藏能力目标；
- `required_question_shape` 使用中性任务，不直接询问答案边界；
- `content_transformation` 不要求补足完整链；
- `invariants` 区分正例与负例，不预设结论成立；
- `competition_structure` 确保竞争项真实存活；
- `semantic_economy` 删除答案总结而不是删除必要事实；
- `forbidden_shortcuts` 覆盖命题级泄漏；
- 专属 positive、negative、ablation、swap controls 可执行。

禁止只修改 O27、O28、O31。所有生成算子必须逐个进入审查清单，并在测试中具有独立用例。

退出条件：全部算子通过内容契约测试，O14 不再进入生成路由，任何一个未审查算子都会阻止阶段完成。

### 阶段 4：语义校验器 Shadow 接入

目标：先测量新校验器的召回和误报，再启用硬门禁。

涉及文件：

```text
prompts/validation_prompt.py
validate_evolved_question.py
validate_difficulty_gain.py
candidate_selection.py
```

实施内容：

1. 接入信息闭包、语义泄漏、单句直达答案、竞争存活、表面交换和专属负担检查。
2. 新标签先只写入 `validation_result`，不改变正式候选分流。
3. 对人工标注回放集统计每个标签的真阳性、假阳性和漏检。
4. 校准 hard risk 与 soft risk 的边界。
5. 不扩展 difficulty gain validator 的既有 enum；新诊断放入嵌套字段。

退出条件：硬泄漏夹具召回率达到 100%，人工确认的干净题面误报率不高于 5%，所有误报均能溯源到具体句子和命题。

### 阶段 5：硬门禁、定向重试和候选分流启用

目标：阻止确定性泄漏进入主链，同时保留结构不确定候选的探索机会。

实施内容：

1. 信息闭包失败和硬语义泄漏进入定向重试。
2. 每种错误最多重试一次，避免无限改写。
3. 重试失败的硬风险候选进入 `hard_reject`。
4. 仅有竞争偏弱、显著性偏差的候选可按预算进入 exploration。
5. 保持每组最多一个 exploration candidate 和每轮总预算限制。
6. `candidate_selection` 继续兼容历史数据和现有四类分流。

退出条件：主链中硬泄漏数量为 0；weak risk 不被错误全量拒绝；现有 exploration 和 hard risk 覆盖测试全部通过。

### 阶段 6：效果确认和 Memory 写入修正

目标：只把真实目标错误命中记录为算子成功。

涉及文件：

```text
analyze_evolution_effect.py
update_sample_state.py
```

实施内容：

1. `effective_boundary_probe` 增加目标错误证据、可回答性和无泄漏前置条件。
2. 仅有分数下降或关键词命中时，在可选嵌套字段 `effect_analysis.effect_confirmation_status` 写 `ambiguous_effect`，不改变现有主效果枚举。
3. `score_increased` 继续作为负收益写入 failure memory。
4. operator success memory 必须保存目标错误证据摘要，而不是只保存算子 ID 和分数变化。
5. 不修改现有 `score_increased` 终止语义。

退出条件：泄漏题、不可答题和格式性降分不能写入 operator success memory；相关回归测试通过。

### 阶段 7：Forced Qualification 和发布

目标：在正式自然路由前确认每个算子的内容质量和真实效果。

每个生成算子至少准备：

- 2 个正常正例；
- 2 个结论不变负例；
- 2 个决定性事实消融例；
- 2 个无关事实消融例；
- 2 个名称或顺序交换例；
- 2 个答案泄漏注入反例；
- 2 个受控假设事实案例。

每个算子至少执行 20 个 forced generation 候选。建议资格门禁：

- 硬泄漏进入主链数量为 0；
- 信息闭包通过率不低于 95%；
- 表面交换一致率为 100%；
- 无关事实消融一致率不低于 95%；
- 决定性事实消融有效率不低于 90%；
- 竞争解释存活率不低于 90%；
- 至少两个独立样本经人工复核命中目标错误；
- `score_delta` 中位数小于 0；
- `score_increased` 不计入任何成功指标。

未通过资格的算子不得进入自然主路由，只能继续 forced qualification 或保持 suspended。

## 14. 测试计划

### 14.1 公共契约测试

- 无关事实消融；

## 16. 风险与缓解

### 16.1 生成调用成本增加

风险：planner、writer 和 semantic validator 分离后调用次数增加。

缓解：

- 先做确定性来源和表层检查，只有通过后才调用语义 Judge；
- 缓存父题事实解析结果；
- 同一候选只允许一次同类定向重试；
- 资格未通过的算子不进入自然路由，避免低价值调用。

### 16.2 validator 过严

风险：自然且有探索价值的问题被大量拒绝。

缓解：

- 硬风险与结构弱风险分开；
- 新标签先 shadow；
- `competition_weak`、`salience_imbalance` 不直接 hard reject；
- 保留 exploration 预算。

### 16.3 为避免泄漏而删掉必要事实

风险：题面变得不可回答。

缓解：

- 删除的是派生结论，不是来源事实；
- 清理后重新运行可回答性校验；
- `unanswerable_after_cleanup` 只能补原子事实，不能恢复总结句。

### 16.4 受控假设事实变成外部事实补造

风险：生成器借“假设案例”引入现实规则或专业结论。

缓解：

- 只允许观察级事实；
- 每项假设事实有独立来源标签；
- 规则、阈值必须来自父题或题内明确给定；
- O14 对新增事实逐项审核。

### 16.5 问题换一种表达继续存在

风险：模型避开禁词，用语义等价句继续泄漏。

缓解：

- 校验题面命题与隐藏答案命题的蕴含关系；
- 使用单句直达答案检查；
- 对每类失败维护多种改写夹具；
- 失败重试要求删除命题，不允许只换措辞。

## 17. 回滚策略

1. 新校验器先 shadow，不直接改变历史流程。
2. 通过环境开关分别控制上下文净化、planner/writer 隔离和语义硬门禁。
3. 回滚时恢复旧生成路径，但保留新审计字段，不删除实验记录。
4. 单个算子出现质量下降时只暂停该算子，不回滚其他已资格算子。
5. 不修改历史 JSONL，不重写既有实验目录。

## 18. 完成定义

只有同时满足以下条件，本方案才算完成：

1. 父题事实、问题意图和答案方向已经分离。
2. planner、surface writer 和 validator 的上下文权限通过测试。
3. O10–O33 已全部逐项审查和修改，O14 已接入全局信息闭包校验。
4. 所有算子均有正例、负例、消融、交换和泄漏注入测试。
5. 硬语义泄漏不会进入主链。
6. 结构弱风险仍可在预算内进入 exploration。
7. `score_increased` 保持负收益语义。
8. `effective_boundary_probe` 由目标错误证据支持。
9. 全量 pytest 通过。
10. forced qualification 满足发布门禁，未通过算子不进入自然主路由。

本方案的最终判断标准不是题目是否更长、禁词是否更少或表达是否更谨慎，而是回答者是否仍需自行完成目标链条、规则适用、角色绑定和竞争解释比较，并且真实评分能够确认这种推理负担暴露了弱模型的能力边界。
