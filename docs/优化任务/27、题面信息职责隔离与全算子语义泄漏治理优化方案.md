### 阅读约定

本方案中的“题面”指最终交给被测模型的完整问题文本；“隐藏”指不得进入题面 Writer、弱模型回答和普通下游日志的内部设计信息；“公开”指经过白名单投影、允许写入题面的材料。公开不等于真实世界公开，也不等于可以进入所有模型上下文，而是专指“可以被最终回答者看到”。

为避免职责名称被理解成同一个“大Prompt”的不同段落，四个核心角色定义如下：

| 角色 | 核心问题 | 产物 | 不能做什么 |
|---|---|---|---|
| Hidden Planner | 这道题要让模型完成什么推理 | hidden plan、竞争结构、结论契约、控制计划 | 直接写最终题面 |
| Public Fact Compiler | hidden plan 中哪些材料可以公开 | public projection | 创作新事实或输出答案角色 |
| Surface Writer | 如何把公开事实写成自然、完整的题目 | evolved prompt、used fact IDs | 接触正确答案、Rubric、决定性标签 |
| Independent Validator | 候选是否合规、可答且无泄漏 | 三态检查、证据、处置建议 | 参与同一次题面生成调用 |

“独立”至少表示独立请求和独立输入白名单；仅在同一个Prompt中增加“现在请忘记答案再写题面”不构成职责隔离。

## 摘要

本方案针对 Question Evolution 当前最主要的生成失效：进化题通过补足事实链、直接解释规则边界、提前排除竞争解释、预先绑定实体角色，使弱模型不再需要完成目标推理，最终出现进化后得分升高或保持满分。

本方案不把问题归结为题目过长，也不继续依赖追加禁词。核心改造是建立严格的信息职责边界：隐藏结构规划器负责设计目标推理负担，题面编写器只能看到原子事实和中性问题意图，独立校验器同时检查信息闭包、答案泄漏、竞争关系和算子专属推理负担。只有通过全部硬门禁的候选才能进入主链评分。

方案覆盖全部 O10–O33。O14 不再作为生成算子，而是升级为全局信息闭包校验。其他算子均需重写生成要求和专属校验，不允许只修复 O27、O28、O31 等已暴露问题的算子。

本方案仅在任务显式授权且样本资格通过时，允许在父题缺少竞争实体、替代解释或必要结构时构造受控假设案例。新增内容只能是可观察事实，不得冒充原始事实，不得补造法规、阈值、业务结论或答案边界。未授权时只能使用 `source_faithful` 或 `pass_through`。

## 1. 问题背景

外部实验结果显示，大量候选并未增加目标推理负担，反而把原题中需要回答者完成的推理写进了题面。典型表现包括：

1. 补足装载、运输、交付、卸载等事实链，使原本存在的链路缺口消失。
2. 直接说明材料“只能支持什么”“尚不能确认什么”或“需要补充什么”。
3. 给竞争解释增加显性排除事实，使回答者无需比较覆盖、冲突和残差。
4. 把实施者、协助者、控制者、受益者等角色关系整理成完整叙述。
5. 把规则、规则适用对象、当前事实映射和结论上限一起交给模型。
6. 用题面总结句复述正确答案，即使没有使用现有禁词也形成语义等价泄漏。

这类问题会造成：

- 弱模型通过复述题面获得高分；
- 进化题比父题更容易；
- `score_increased` 大量出现；
- 自动效果标签将题面泄漏误认为能力边界；
- operator memory 记录错误成功经验；
- 后续轮次继续强化同一种失败形态。

## 2. 当前实现的根因

### 2.1 生成模型同时承担结构设计和题面表达

当前生成模型既知道算子目标、目标错误、竞争结构和正确判断，又负责把这些内容写成自然题面。即使 Prompt 要求“不要泄漏答案”，模型仍然倾向于把内部结构转换成更委婉的答案提示。

例如，内部控制是“当前事实只能支持关联，不能支持稳定运输关系”。模型可能避开“不能支持”，但改写为：

```text
这些行为尚不足以形成稳定运输链条，仍需观察是否存在持续交付。
```

表面禁词发生变化，答案内容没有变化。

### 2.2 父题整段文本被当作可观察材料

父题中的问题措辞可能已经包含结论方向，例如“为什么不能直接认定”“现有材料最多能说明什么”。如果生成阶段直接接收父题全文，即使参考答案和 Rubric 已隔离，答案方向仍会从原始问题进入新题。

因此，父题必须先拆分为：

- 可观察事实；
- 原始规则或定义；
- 中性业务目标；
- 结论性问题措辞；
- 答案提示或边界提示。

只有前三类经过校验后可以进入后续生成。

### 2.3 当前校验器偏向词面检查

现有检测更容易发现“不能推出”“最高支持”“不足以认定”等显式词语，但不能稳定发现语义等价表达，也不能判断题面是否已经完成目标链条、角色绑定或竞争解释淘汰。

### 2.4 部分算子定义内部存在冲突

当前部分算子的 `required_question_shape`、`goal` 和 `semantic_economy` 同时包含相反要求。例如：

- O27 要求形成结论并说明边界，同时要求题面不询问边界；
- O31 要求回答“能支持到什么程度”，等于直接暴露证据校准任务；
- O33 要求说明材料共同支持的边界，容易引导模型复述来源上限；
- O28 要求每个必要跳转都有题面事实，负例容易被补成完整链；
- O17 要求完整规则和适用对象，容易退化为规则查表。

这类冲突必须从算子定义层消除，不能只靠公共 Prompt 补救。

## 3. 目标与非目标

### 3.1 目标

本方案必须实现以下目标：

1. 题面只呈现原子观察、必要的原始规则和中性问题意图。
2. 目标链条、事实角色、竞争解释排序、规则适用结论和答案边界不得进入题面编写上下文。
3. 所有 O10–O33 均具有明确的题面允许项、禁止项和专属控制测试。
4. O14 成为所有生成候选共同使用的信息闭包校验器。
5. 校验器能够识别语义等价泄漏，而不是只识别固定禁词。
6. 硬泄漏候选不得进入主链评分；结构弱风险可按预算进入 exploration。
7. `effective_boundary_probe` 必须由真实目标错误命中支持，不能只依赖降分或关键词匹配。
8. 保留问题进化前半段主链主体、已有 JSONL 字段和历史数据 fallback；候选选中后的评分准备顺序按第 29 号 v2.2 方案增量调整。

### 3.2 非目标

本方案不做以下工作：

- 不重写完整 pipeline；允许为评分材料隔离增量新增参考答案重建阶段，并调整候选选中后的评分准备顺序；
- 不引入完整树搜索、BFS、DFS、UCB 或深层回溯；
- 不修改 Rubric 和 scoring Prompt 的核心评分语义；
- 不把 validator 改成拒绝所有不确定候选的 candidate rejection system；
- 不要求历史实验数据强制迁移；
- 不通过简单缩短题目代替语义泄漏治理；
- 不允许 Global Judge 或 Memory 自动修改正式算子 Prompt。

## 4. 核心设计决策

### 4.1 采用三段隔离架构

生成过程拆为三个职责单一的阶段：

```text
父题事实解析
-> 隐藏结构规划
-> 题面事实编译
-> 盲题面编写
-> 独立语义校验
-> 通过 / 定向重试 / 拒绝或探索
```

各阶段的信息权限如下：

| 阶段 | 可以看到 | 不可以看到 |
|---|---|---|
| 父题事实解析 | 父题、允许的上下文 | 无 |
| 隐藏结构规划 | 算子完整契约、父题事实、目标错误 | 无 |
| 题面事实编译 | 规划器产生的事实候选和来源 | 最终自然题面 |
| 盲题面编写 | 原子事实池、中性问题意图、写作约束 | 正确答案、事实角色、正确解释、规则适用结论 |
| 独立语义校验 | 候选题面、隐藏控制、来源映射 | 不参与题面生成 |

同一个 LLM 调用不得同时输出隐藏答案结构和最终题面。否则模型仍然可以把隐藏结构转写到题面。

这里的“职责隔离”指输入权限和调用边界隔离，不要求一定使用不同厂商或不同模型。可以使用同一模型名称，但必须是独立请求，并分别构造字段白名单：

```text
Planner请求：公开事实 + 算子契约 + 目标错误
Writer请求：公开事实投影 + 中性任务 + 表面写作要求
Validator请求：最终题面 + 隐藏控制 + 来源映射
```

错误实现是先生成一个包含 `correct_answer`、`decisive_fact_ids` 和 `evolved_prompt` 的大 JSON，再在代码中取出 `evolved_prompt`。虽然最终保存时删除了隐藏字段，但同一次生成调用已经看见答案，仍可能把答案语义写进题面。

“题面事实编译”或 Public Fact Compiler 也不是自然语言摘要器。它只执行白名单投影：保留允许公开的原子事实文本和必要的原始规则，删除 `answer_role`、正确竞争解释、决定性标记、目标错误和 Rubric 意图。例如：

```json
{
  "完整账本项": {
    "surface_text": "车辆甲20:10离开东门",
    "answer_role": "decisive_fact"
  },
  "Writer可见投影": {
    "surface_text": "车辆甲20:10离开东门"
  }
}
```

编译器不能把 `decisive_fact` 改写成“关键记录显示……”，因为这仍然泄漏了事实角色。

以车辆连续性题为例，职责隔离后的信息应当是：

```text
Hidden Planner知道：
- 正确结论不能仅凭两段记录确认同一车辆；
- 决定性组合是7分钟间隔、最快8分钟、存在相似车辆；
- 目标错误是忽略时间不可达并过早闭合身份链。

Public Fact Compiler输出：
- 20:10车辆A离开东门；
- 20:17一辆同型号车辆进入北门，车牌不可见；
- 两门最快需要8分钟；
- 同时段存在另一辆同型号车辆。

Surface Writer只写：
- 根据这些记录，能否确认两段记录属于同一车辆？说明依据。
```

Writer 不应收到“时间不可达”“正确结论不能确认”“决定性事实是最快8分钟”等隐藏解释。否则即使最终没有逐字复制答案，也可能写出“考虑到时间不足”等语义提示。

### 4.2 区分问题意图和答案目标

题面编写器可以知道问题类型，例如：

```text
根据材料判断当前业务主张是否成立，并说明依据。
```

题面编写器不得知道：

```text
正确答案是不能成立，因为第三跳缺失。
正确角色是 B，A 只能解释外围行为。
当前证据只能支持关联，不能支持稳定运输关系。
```

算子的能力轴、目标错误和正确结构只用于隐藏规划和校验。

“中性问题意图”不等于把问题写得含糊。Writer仍然可以知道回答者要完成什么业务任务，但不能知道答案方向：

| 可公开的任务意图 | 不可公开的答案目标 |
|---|---|
| 判断两段记录是否属于同一车辆并说明依据 | 正确答案是无法确认 |
| 判断现有观察是否满足题内R3规则 | 当前事实缺少R3的第三个条件 |
| 比较解释A与B对全部记录的解释力 | B是正确解释，A应被排除 |

如果中性化后只剩“请分析上述材料”，任务过于模糊；如果写成“说明为何不能确认”，又泄漏答案。合格表达应同时保留明确任务对象和开放结论方向。

### 4.3 允许受控假设事实

当父题缺少竞争实体、替代解释或关键断点时，只有同时满足任务授权与样本资格，才允许构造明确的假设案例。Source Analyzer 只能判断 `eligible`，不能自行授权。

默认授权配置为：

```json
{
  "evolution_authorization": {
    "allowed_evolution_modes": ["source_faithful"],
    "controlled_synthesis_authorized": false,
    "hypothetical_adaptation_authorized": false
  }
}
```

缺失配置、配置解析失败或授权来源不可审计时，按默认关闭处理。Memory、Router 命中、算子资格和槽位缺失均不能绕过授权门禁。未授权时只能使用 `source_faithful` 或 `pass_through`；`pass_through` 是始终允许的安全退出，不要求列入生成模式白名单。

获得授权后的受控假设事实还必须满足：

1. `origin_type` 标记为 `controlled_hypothetical_observation`；
2. 只能描述可观察行为、时间、位置、记录或数值；
3. 不得新增现实法规、行业规则、专业阈值或外部知识；
4. 不得新增“因此、足以、只能、应当”等结论；
5. 不得冒充原样本中真实发生的事实；
6. 必须保留父题的核心业务判断和能力义务；
7. 无法在这些限制内构造可答题目时，应返回 `not_applicable` 或透传。

### 4.4 原始规则可以出现，规则应用答案不得出现

O17、O18、O25、O26 等算子必须提供规则、口径、流程或公式。方案不禁止这些原始输入，但必须分离：

允许：

- 原始规则文本；
- 规则版本和对象字段；
- 纳入标准；
- 程序步骤和记录映射；
- 公式、单位、误差和阈值。

禁止：

- 当前事实满足哪条规则；
- 哪条规则只支持行动、不支持事实认定；
- 当前结果是否跨过阈值；
- 当前流程破坏了哪个不变量；
- 当前材料最多允许形成什么结论。

真实规则还必须进入 `rule_ledger`，并具有 `rule_id`、可验证来源定位、适用对象、适用场景、版本、生效时间、失效时间和 `validity_status`。无来源、版本或适用范围不明的规则不得作为 `provided_rule_primitive` 自动进入题面；只能在明确声明为当前假设题内部条件时作为 `task_local_parameter`，且不得冒充真实法律、行业或专业规范。`validity_status=unresolved/expired/superseded` 的规则不能被当作当前有效规则使用。

### 4.5 保持 validator 的分流职责

硬泄漏、事实补造和不可回答属于确定性失败。竞争不足、信息显著性偏差和推理负担偏弱属于结构风险，应先定向重试，重试后仍不理想时进入 exploration 或透传，而不是一律 hard reject。

## 5. 统一数据契约

### 5.1 原子事实契约

每项可进入题面的事实必须具有稳定来源：

“原子事实”是能够直接观察或读取、且没有把多个观察之间的推理关系一起写出的最小陈述单位。它不要求机械地“一句只能有一个字段”，而要求拆分后每项内容都不包含答案性关系。

例如：

```text
合格：车辆甲20:10离开东门。
合格：车辆乙20:17进入北门。
不合格：车辆甲离开东门后仅用7分钟到达北门，形成连续轨迹。
```

最后一句同时完成了实体同一性、时间连接和链条总结，应拆回观察事实；“是否为同一车辆”“7分钟是否可达”留给回答者判断。

```json
{
  "fact_id": "F03",
  "world_id": "source_case_01",
  "global_fact_key": "source_case_01::F03",
  "origin_type": "source_observation",
  "content": "18时42分，车辆甲从北门驶出。",
  "source_ref": "parent_prompt:sentence_4",
  "source_locator": {
    "source_file": "...",
    "source_record_id": "record_018",
    "json_pointer": "/prompt",
    "source_span": "18时42分，车辆甲从北门驶出。",
    "page_index": null,
    "line_start": null,
    "line_end": null,
    "source_hash": "sha256:..."
  }
}
```

受控假设事实示例：

```json
{
  "fact_id": "H02",
  "world_id": "hyp_case_01",
  "global_fact_key": "hyp_case_01::H02",
  "origin_type": "controlled_hypothetical_observation",
  "content": "假设案例中，19时06分，人员乙在南门附近接触车辆甲。",
  "source_ref": null
}
```

原始规则示例：

```json
{
  "fact_id": "R01",
  "world_id": "source_case_01",
  "global_fact_key": "source_case_01::R01",
  "origin_type": "provided_rule_primitive",
  "content": "规则要求结果区间整体高于阈值 T 时才进入下一处理状态。",
  "source_ref": "parent_prompt:rule_1",

```

来源事实至少具有一个可验证定位器；新契约不能只依赖 `prompt:sentence_2` 之类的不稳定 `source_ref`。不同来源介质可使用文件、记录 ID、JSON Pointer、逐字 span、页码、行号或内容哈希中的合适组合。`fact_id` 只在单个 world 内唯一，跨 world 稳定引用必须使用 `global_fact_key = world_id::fact_id`。受控假设事实没有外部来源时 locator 可为空，但必须保留 world、`origin_type`、design basis 和任务授权证据。历史字段 `origin` 只作为兼容 alias 读取，新契约统一写 `origin_type`。

### 5.2 隐藏结构契约

隐藏结构只供规划器和校验器使用：

```json
{
  "target_claim": "当前材料是否支持目标业务主张",
  "answer_mode": "binary | calibrated | ranking | selection | quantitative",
  "conclusion_contract": {
    "admissible_outcomes": ["supports_h1", "supports_h2", "insufficient_evidence", "cannot_distinguish", "candidate_set_expanded"],
    "unique_answer_required": false,
    "uniqueness_basis": []
  },
  "required_inference_obligations": [
    "跨实体绑定时间连续性",
    "检查第三跳是否指向同一对象"
  ],
  "competing_interpretations": [
    {"id": "C1", "status": "target"},
    {"id": "C2", "status": "live_competitor"}
  ],
  "decisive_fact_ids": ["F03", "H02"],
  "irrelevant_control_fact_ids": ["F07"],
  "forbidden_surface_propositions": [
    "第三跳缺失",
    "现有材料不能支持完整运输关系"
  ]
}
```

`status`、`decisive_fact_ids` 和 `forbidden_surface_propositions` 不得进入题面编写器上下文。

这里的“隐藏”是阶段级信息权限，不等于永久删除，也不一定表示安全密级。Planner、Validator 和 Reference Rebuilder可以按白名单读取；Writer、弱模型回答和面向用户的普通日志不得读取。工程上应通过 sidecar 或显式字段投影实现，而不是依赖开发者记住“不要使用这些字段”。

`forbidden_surface_propositions` 保存的是不得出现在题面的语义命题，而不只是禁词。例如禁止命题是“第三跳缺失”，则“现有链条在最后环节尚未闭合”也应被视为同义泄漏，不能因为没有出现“第三跳”三个字而通过。

`conclusion_contract` 必须对每个候选声明允许的结论形态。若要求唯一答案，`uniqueness_basis` 必须引用保证唯一性的公开事实 key 与当前有效规则 ID；否则 Validator、Reference Rebuilder 和 Rubric Builder 不得强行把“证据不足”“无法区分”或“候选集合扩大”压缩成唯一答案。Writer 不得看到正确 outcome。

### 5.3 持久化位置

为兼容现有字段，不新增临时顶层字段。建议将非答案型审计信息写入：

```text
meta_info.question_evolution_metadata.generation_contract
validation_result.semantic_leak_checks
candidate_selection
effect_analysis
```

完整隐藏答案控制优先在 `question_evolution.py` 与 `validate_evolved_question.py` 之间以内存或临时候选 sidecar 传递。若必须持久化，必须由显式白名单保证其不进入题面编写、作答和评分模型上下文。

这里的 `sidecar` 指与主 JSONL 记录分离、通过 candidate identity 或 trace ID 关联的受限审计文件。它的作用是让 Validator 和 Reference Rebuilder 获得必要隐藏控制，同时避免完整答案结构随着普通 sample dict 流经所有阶段。`trace_id` 只是定位符，不包含答案本身；知道 trace ID 的阶段也不自动获得读取 sidecar 的权限。

例如，主记录可以保存：

```json
{
  "hidden_plan_trace_id": "hp_round2_candidate03"
}
```

但不能把 `correct_answer_outline`、`wrong_competitor_id` 和 `decisive_fact_ids` 一并复制进所有阶段共享的 `meta_info`。

历史记录缺少新字段时走旧数据 fallback，不要求迁移。

## 6. 统一题面内容规则

### 6.1 允许进入题面的语义角色

- 可直接观察的事实；
- 假设案例中的可观察事实；
- 题目作答不可缺少的原始规则；
- 公式、单位、阈值和统计摘要；
- 中性的业务问题。

### 6.2 禁止进入题面的语义角色

| 类型 | 定义 | 例子 |
|---|---|---|
| `derived_fact_summary` | 必须组合多条事实才能得到的总结 | “多次行为已经形成稳定分工” |
| `target_chain_disclosure` | 已按答案顺序连接的事实链 | “甲装载、乙运输、丙卸货，形成完整链条” |
| `fact_role_disclosure` | 标明事实在答案中的作用 | “关键事实是第三次交付” |
| `rule_ceiling_disclosure` | 解释当前事实可适用到的规则上限 | “这些材料只能支持继续追踪” |
| `role_binding_disclosure` | 预先绑定行为和角色 | “乙是运输者，丙负责接应” |
| `competitor_elimination` | 直接说明竞争解释不成立 | “偶然同行无法解释连续等待” |
| `answer_direction_disclosure` | 直接或委婉预告结论方向 | “目前仍不能形成确定判断” |
| `answer_template_disclosure` | 把内部推理步骤变成题面作答模板 | “分别说明事实层和行动层结论” |

### 6.3 原子事实编写要求

1. 一句话只表达一项观察或一项原始规则。
2. 不用“因此、表明、意味着、足以、仅能、由此可见”等推导连接词。
3. 不把行为、角色和结论写在同一句中。
4. 不在题尾重复或总结全部事实。
5. 正确项不得独占数字精度、完整路径、专业来源或更长描述。
6. 除算子专属计算外，正确答案不得由单独一句话决定。
7. 问题结尾使用中性问法，不询问“上限、边界、不能推出什么”。

## 7. O10–O18 全量修改要求

### 7.1 O10 最小充分事实集

生成要求：

- 题面只给同粒度原子事实；
- 最小集合成员、相关事实和冗余事实只在隐藏控制中标记；
- 题面只询问业务主张是否成立及依据；
- 正确集合不得独占完整因果叙述。

禁止：

- 提示哪些事实共同构成闭环；
- 把最小集合写成连续事实链；
- 要求回答者选择“必要事实集合”；
- 用信息量差异暗示正确组合。

专属控制：删除任一必要成员后结论应减弱；删除相关干扰事实后结论保持不变。

### 7.2 O11 端点时序一致性

生成要求：完整提供可见端点、时间窗、方向、路径或速度范围；候选假设均需解释部分端点事实。

禁止：补造盲区内事件；给出预计算路径；用单个明显超时数字直接排除错误项。

专属控制：交换候选名称不改变答案；每个候选至少满足一个局部约束；正确判断必须依赖联合约束。

### 7.3 O12 独立性与共同必要性

生成要求：X、Y、X+Y 仅存在于隐藏控制，题面呈现为未标注、信息量可比的自然案例。

禁止：联合版本更长、更完整、更肯定；公开 X/Y 标签；提示两个条件必须共同满足。

专属控制：覆盖仅 X、仅 Y、X+Y、X+Y 仍不足和单项冗余五种情况；交换 X/Y 后语义答案不变。

### 7.4 O13 必要连接破坏

生成要求：混合呈现多个同观察类别、同证据类型的复核事实；是否存在替代支持路径只保存在隐藏控制。

禁止：点名断点、必要连接、替代路径或整体翻转；让破坏事实独占否定词。

专属控制：删除破坏事实后局部连接恢复；存在替代路径时不得将局部失效升级为整体翻转。

### 7.5 O14 信息闭包

O14 不生成独立题面，正式承担全局事实来源校验：

- 每条事实映射到父题事实、受控假设事实或原始规则；
- 拒绝补造中间状态、统计口径、业务阈值和外部知识；
- 拒绝把经验判断写成已发生事实；
- 输出精确的无来源句子和来源缺口。

### 7.6 O15 单变量门槛变化

生成要求：只新增、删除或替换一个核心事实；其他事实、比较量、结论层级和规则保持不变。

禁止：同时改变事实和阈值；用正负措辞预告方向；无明确阈值时预告整体翻转。

专属控制：前后版本差异严格限制为一个决定性变量；交换前后呈现顺序不改变语义关系。

### 7.7 O16 相近解释覆盖与残差

生成要求：两个解释均覆盖部分事实并各自留下残差；区分事实自然混入其他同粒度观察。

禁止：一句话直接否定替代解释；目标解释形成无残差完整闭环；公开覆盖、冲突和残差字段。

专属控制：删除区分事实后两个解释重新接近；交换解释名称和顺序不改变答案。

### 7.8 O17 双规则边界映射

生成要求：保留不可缺少的原始规则、版本、对象字段和阈值；当前事实独立呈现。

禁止：解释哪条规则适用于当前事实；标注动作层和事实层；把规则重写成当前答案；生成规则查表步骤。

专属控制：交换规则名称和顺序不改变答案；规则版本、适用对象和边界值分别制作单变量控制。

### 7.9 O18 基线纳入口径

生成要求：两个基线均给出原始纳入条件和完成判断所需的统计摘要，当前观测保持不变。

禁止：说明哪个基线更合适；正确基线拥有更权威来源或更完整摘要；提示先比较口径再判断异常。

专属控制：交换来源名称不改变答案；改变不参与纳入口径的统计项不改变答案。

## 8. O19–O27 全量修改要求

### 8.1 O19 多实体角色绑定

生成要求：分散呈现实体在不同时间的局部动作，实体描述保持对称，角色关系由回答者恢复。

禁止：形成装载、运输、接应、卸载的完整角色表；直接命名实施者、协助者或受益者；用出场顺序提示角色。

专属控制：交换实体名称不改变逻辑；只有改变决定性行为归属时答案才改变。

### 8.2 O20 多阶段事件链断点

生成要求：自然呈现事件和状态变化，保留局部成立但整体可能失效的结构。

禁止：编号阶段、标记断点、在结尾总结完整状态链、把最后出现的异常写成显然断点。

专属控制：修复真正断点后整体结论改变；修改旁支事件不改变结论。

### 8.3 O21 对象来源与同一性

生成要求：提供对象转移、出现、遮挡、重现和竞争来源的原始记录。

禁止：输出完整来源链；使用唯一编号直接给答案；把外观相似总结成同一对象。

专属控制：补足关键转移记录后同一性结论增强；改变颜色、名称等无识别力特征不改变答案。

### 8.4 O22 路径拓扑联合可达

生成要求：提供原始方向边、开放窗口、端点和耗时，候选路径各自满足部分约束。

禁止：提供预计算路径、路线总结、唯一可行提示；用路径数量制造难度。

专属控制：反转决定性边或改变窗口后答案改变；修改候选路径外的旁支边不改变答案。

### 8.5 O23 观测可靠性冲突

生成要求：提供距离、遮挡、采样时段、来源生成关系和实际可见字段。

禁止：直接写“画面不清所以不能确认”；将来源标为可靠或不可靠；用来源权威性替代质量事实。

专属控制：改善决定性采集条件后答案可以增强；复制同一受限来源不增强答案。

### 8.6 O24 多假设残差排序

生成要求：共同事实独立呈现，各解释保持交叉覆盖；解释名称、顺序和复杂度保持平衡。

禁止：按解释分组罗列支持事实；给出覆盖矩阵、残差清单或排名步骤；正确解释独占事实并集。

专属控制：增加各解释共同覆盖的事实不改变排序；加入真正区分关键残差的事实时排序才改变。

### 8.7 O25 程序不变量与参照系

生成要求：提供流程步骤、字段、单位、参照变化和记录映射，不解释哪项是不变量。

禁止：标记错误步骤；说明结果不可比较；将格式整齐与程序有效绑定。

专属控制：恢复关键映射或参照转换后有效性改变；只改变记录格式不改变结论。

### 8.8 O26 定量阈值与误差传播

生成要求：完整提供公式、单位、输入区间、误差关系和业务阈值，保证无需外部公式。

禁止：给出中间计算、结果区间、阈值比较结果；加入不参与计算的装饰数字。

专属控制：重算结果唯一；无关数字变化不影响答案；覆盖跨阈值、不跨阈值和刚好接触阈值三类样本。

### 8.9 O27 跨层结论校准

生成要求：父题已有规则时只保留原始条款和事实；父题没有规则时不得补造业务结论边界。

禁止：询问最高支持、结论边界、不能推出什么；提前完成观察到事实、事实到表述、表述到行动的映射。

专属控制：删除局部证据只影响依赖该证据的下游结论；不得自动翻转所有层级。

## 9. O28–O33 全量修改要求

### 9.1 O28 多跳链路闭合

生成要求：只呈现跨节点原始观察；每个已声称的跳转必须有事实，但负例允许必要跳转缺失。

禁止：按答案顺序补足完整链；给出链路总结；从终点反推并补写缺失跳转。

专属控制：补足唯一缺失承接后答案改变；改变不在主链上的旁支节点不改变答案。

### 9.2 O29 实体同一性冲突消解

生成要求：支持线索、连续线索和冲突线索混合呈现，保持信息粒度一致。

禁止：标记排他冲突；正确身份拥有更多细节；将同位置或外观相似直接总结成同一实体。

专属控制：翻转决定性冲突后归属改变；增加普通相似特征不自动增强归属。

### 9.3 O30 主动判别观测选择

生成要求：给出当前竞争解释和可执行观测条件，可以提供自然候选观测，但不提供结果预测。

禁止：给出观测结果分支表；说明哪项最有判别力；把最低成本或信息最多直接等同最佳。

专属控制：无论结果如何都不改变解释排序的观测必须判为低价值；交换候选顺序不改变答案。

### 9.4 O31 观测累积校准

生成要求：提供观察的原始来源和生成关系，例如转录、截取、同一片段、不同点位。

禁止：将观察总结为独立、同源或可累计；询问“能支持到什么程度”；按观察条数暗示强度。

专属控制：复制、转述和同源派生不增加结论强度；真正独立的新特征才允许增强。

### 9.5 O32 角色关系图关键边

生成要求：只描述局部方向性行为，实体身份保持清晰，关系边由回答者恢复。

禁止：把行为整理成文字关系图；标关键边、控制者或协助者；用节点中心度提示答案。

专属控制：删除或反转必要边时结论改变；改变冗余边时结论不变。

### 9.6 O33 跨模态支持边界

生成要求：每个来源只给实际字段、时间、对象和采集范围；对齐和融合由回答者完成。

禁止：总结各模态能支持什么；询问共同支持边界；按来源数量或技术名称暗示证据更强。

专属控制：未对齐材料不能叠加；加入不能观察目标属性的来源不得增强结论；完成关键时间或实体对齐后才允许增强。

### 9.7 O10–O33 的直观理解

下表只帮助理解，不替代各算子的正式契约：

| 算子 | 通俗问题 | 简化例子 |
|---|---|---|
| O10 最小充分事实集 | 哪些事实组合刚好够支持判断 | 时间、路径、车牌三项中，少任一项都不能确认身份 |
| O11 端点时序一致性 | 两端记录能否在时间和空间上接起来 | 20:10离开东门，20:17进入北门，但最快需要8分钟 |
| O12 独立性与共同必要性 | 两项信息是否各有独立贡献且必须合用 | 只有时间或只有车牌都不足，二者联合才成立 |
| O13 必要连接破坏 | 一条关键连接被破坏后整体是否仍成立 | 转移链中缺少物品从车辆到接收人的记录 |
| O14 信息闭包 | 题面每项事实是否都有合法来源 | 生成器新增“盲区中完成换牌”但来源和假设账本均没有 |
| O15 单变量门槛变化 | 只改一个变量会不会跨过判断门槛 | 记录间隔从9分钟改成7分钟，其他条件不变 |
| O16 相近解释覆盖与残差 | 两个相近解释谁能解释更多且留下更少冲突 | 同一车辆与相似车辆都解释车型，只有一个解释符合时间记录 |
| O17 双规则边界映射 | 同一事实落入两套规则时结论有何不同 | 业务规则允许继续核查，认定规则仍不允许确认身份 |
| O18 基线纳入口径 | 选择不同合格基线会不会改变异常判断 | 只纳入工作日基线与纳入全部日期得到不同阈值 |
| O19 多实体角色绑定 | 分散行为分别属于谁、形成什么角色关系 | 甲接触物品、乙驾车、丙在另一地点接触相似物品 |
| O20 多阶段事件链断点 | 多阶段流程在哪一步未完成必要状态转移 | 申请、审批、执行、确认中缺少正式审批 |
| O21 对象来源与同一性 | 不同记录中的对象是否真是同一个 | 箱子遮挡后重新出现，但没有唯一标记 |
| O22 路径拓扑联合可达 | 方向、开放时间和耗时联合下是否存在可行路径 | 每条边单独可走，但方向组合后无法从A到D |
| O23 观测可靠性冲突 | 来源声称看到了什么与它实际能看清什么是否一致 | 远距离画面能看车型，不能可靠读车牌 |
| O24 多假设残差排序 | 多个解释分别覆盖哪些事实、还剩哪些解释不了 | H1解释时间，H2解释外观，H3解释来源偏差，再比较残差 |
| O25 程序不变量与参照系 | 流程转换后必须保持的量或映射是否被破坏 | 单位从米变厘米，但阈值没有同步换算 |
| O26 定量阈值与误差传播 | 测量误差传播后是否真的跨过阈值 | 点估计高于阈值，但误差区间仍覆盖阈值 |
| O27 跨层结论校准 | 观察、事实判断和行动建议能支持到哪一层 | 记录支持“需要复核”，但不足以支持“身份已确认” |
| O28 多跳链路闭合 | 多个节点之间的所有必要跳转是否共同闭合 | 人、车、物、地点四段关系中缺少车到物的绑定 |
| O29 实体同一性冲突消解 | 支持同一性的线索与冲突线索如何联合判断 | 外观相同但时间冲突、唯一标记缺失 |
| O30 主动判别观测选择 | 下一步看什么最能区分仍存活的解释 | 与其再看车型，不如补拍能区分两车的贴纸位置 |
| O31 观测累积校准 | 多份材料是否真是独立新增证据 | 同一视频的截图、转录和摘要不能算三份独立证据 |
| O32 角色关系图关键边 | 哪条关系边对整体角色结论不可缺少 | 删除乙向丙交付物品的边后协作关系不再闭合 |
| O33 跨模态支持边界 | 不同模态对齐后能联合支持什么 | 视频给时间、日志给设备ID，但实体未对齐时不能直接叠加 |

这些例子只展示目标推理义务。实际生成时仍必须遵守任务授权、单world、事实来源、结论契约和题面泄漏限制；不能把表中的解释句直接复制进题面。

## 10. 校验器设计

校验器先判断“这项检查是否适用于当前算子”，再判断通过、失败或无法确定。不得因为某个检查存在于公共清单中，就默认所有算子都必须通过。

建议每项检查统一记录：

```json
{
  "check_id": "competition_survival",
  "applicable": true,
  "applicability_reason": "O16依靠两个相近解释形成判断难度",
  "risk_level": "soft",
  "status": "unresolved",
  "evidence": [],
  "disposition": "exploration_candidate"
}
```

其中：

- `applicable=false` 表示不需要这项检查，不能记为失败；
- `risk_level=hard` 只用于来源非法、明确泄漏、不可答、矛盾和安全问题；
- `status=unresolved` 表示当前无法可靠判断，不等于失败；
- 未明确登记为 hard risk 的检查不得自动导致 `hard_reject`。

例如，O26定量题需要检查公式、单位、误差和阈值，但不一定需要两个竞争解释；O16相近解释题则必须检查竞争解释是否存活。

### 10.1 第一层：事实来源与信息闭包

确定性检查：

- 每项事实是否具有 `fact_id`；
- `origin_type` 是否属于允许枚举；
- 原始规则是否来自父题或明确的题内定义；
- 是否存在无来源中间状态、阈值或业务规则；
- 受控假设事实是否被明确写成假设案例。

以下情况 hard reject：

- 无来源事实；
- 外部知识被写成已发生事实；
- 新增业务规则或阈值；
- 假设事实冒充原事实。

### 10.2 第二层：语义泄漏检查

在 `validation_result.semantic_leak_checks` 中记录：

```text
direct_answer_leakage
target_chain_disclosure
derived_summary_leak
rule_ceiling_disclosure
role_binding_disclosure
competitor_elimination
answer_direction_disclosure
answer_template_disclosure
salience_imbalance
hypothesis_status_disclosure
fact_role_disclosure
rule_application_disclosure
missing_link_disclosure
uniqueness_disclosure
forced_conclusion_type
counterfactual_result_disclosure
control_role_disclosure
authority_bias
position_or_naming_bias
metadata_leakage
```

历史字段 `derived_fact_summary` 仅作为兼容 alias 读取，新输出统一写 `derived_summary_leak`。

校验器需要比较题面命题与隐藏控制命题的语义关系，不能只做字符串匹配。

新增标签的精确含义如下：

| 标签 | 必须命中的情形 |
|---|---|
| `hypothesis_status_disclosure` | 题面提前声明某个假设成立、失败或应优先接受，例如“假设A成立，再分析B为何不成立” |
| `fact_role_disclosure` | 公开某事实是决定性、必要、干扰或反驳事实 |
| `rule_application_disclosure` | 公开当前事实落入哪条规则或是否跨过阈值 |
| `missing_link_disclosure` | 点名目标链中缺少的具体连接 |
| `uniqueness_disclosure` | 声明某候选唯一满足或其他候选均被排除 |
| `forced_conclusion_type` | 强制要求本应由推理决定的“证据不足/不能认定”等结论形态 |
| `counterfactual_result_disclosure` | 预先给出变量改变后的结论方向或结果 |
| `control_role_disclosure` | 暴露基准、消融、干扰或控制事实的内部角色 |
| `authority_bias` | 用来源权威、机构等级或专业身份暗示正确项 |
| `position_or_naming_bias` | 用候选位置、顺序、名称或固定符号暗示答案 |
| `metadata_leakage` | Writer 或回答模型输入出现 hidden plan、answer role、Rubric、Judge意图等内部字段 |

一个命题可命中多个标签，但输出必须包含最具体标签和证据句，不能只用宽泛的 `answer_direction_disclosure` 覆盖更精确问题。

可以把泄漏理解成四个层次：

1. **结论层泄漏**：直接答案、假设状态、强制结论类型、唯一性；
2. **推理层泄漏**：完整链条、缺失连接、规则应用、竞争淘汰；
3. **角色层泄漏**：事实角色、实体角色、控制角色；
4. **表面与系统层泄漏**：权威偏置、位置命名偏置、信息量偏差和内部元数据。

近似表达示例：

| 题面句子 | 主要标签 | 为什么不是普通背景 |
|---|---|---|
| “假设车辆A就是目标车辆，再解释另一车辆为何不成立” | `hypothesis_status_disclosure` | 已把A设为成立假设，并要求淘汰对手 |
| “关键的8分钟门槛表明两段记录无法连续” | `fact_role_disclosure` + `rule_application_disclosure` | 同时暴露关键事实角色和应用结果 |
| “唯一缺少的是车牌对齐记录” | `missing_link_disclosure` + `uniqueness_disclosure` | 已点名缺口并暗示其他条件完整 |
| “请得出证据不足的结论” | `forced_conclusion_type` | 结论类型本应由材料决定 |
| 请求体包含`correct_answer_outline`但题面未显示 | `metadata_leakage` | 被测模型仍可能从系统上下文读取答案 |

标签的目的不是增加处罚数量，而是支持最小、可解释的修复。例如命中 `fact_role_disclosure` 时，应删除“关键”标签而保留8分钟这一必要参数；不能把必要参数和泄漏措辞一起删掉。

检查适用时必须统一输出 `passed | failed | unresolved`；检查不适用时输出 `not_applicable`。只有对应校验器经过可靠夹具校准且证据充分时才允许输出 `passed`；调用失败、Judge 不一致、证据不足或控制实验无法执行时必须输出 `unresolved`。`unresolved` 不得默认折算为通过或硬拒绝，还要继续看风险等级：竞争强度、轻微信息差、算子轻微重叠和预测难度属于低风险，优先进入有预算的真实模型实验；事实来源、规则版本、答案矛盾和参考答案是否使用隐藏事实属于高风险，才进入人工复核、透传或停止当前候选。

### 10.3 第三层：单句直达答案检查

独立 Judge 需要回答：

1. 是否存在一句话在不组合其他事实时就基本决定答案；
2. 该句对应隐藏答案中的哪个命题；
3. 删除该句后是否仍能完成算子目标推理。

除原始规则和专属定量输入外，单句直达答案进入定向重试。

“单句直达”不是指一句话字数长，而是指单独读取该句就已经足以确定结论。例如：

```text
车辆甲20:10离开东门。                 # 单独不能决定答案
东门到北门最快需要8分钟。             # 单独不能决定答案
车辆甲不可能在20:17前到达北门。       # 已完成联合计算，可能单句直达
```

前两句需要回答者组合时间和通行参数；第三句已经把组合结果写入题面。删除第三句后题目仍有必要事实并保留推理负担，因此应删除结论句，而不是删除前两项观察。

“一句话很重要”不等于“单句直达答案”。判断重点是该句是否已经包含从输入到结论的关键映射：

* “东门到北门最快需要8分钟”是必要参数，单独看并不能判断两段记录是否同一车辆；
* “两次记录只相隔7分钟，因此不是同一车辆”把参数、比较结果和结论写在同一句中，属于直达答案；
* “第二段清楚拍到与车辆A一致的唯一车牌”若任务就是身份判断，可能通过排他措辞直接决定答案；
* O26中的完整公式可能由一句话给出，但只要题面仍要求结合多个输入计算，它不是答案泄漏。

因此校验不能机械地删除所有高信息量句子，而应检查句子是否独立蕴含目标结论，以及删除后是否仍保留合法可答性。

### 10.4 第四层：竞争关系存活检查

只有算子契约声明 `requires_live_competitor=true` 时，本层才是必做检查。声明为 `false` 时输出 `not_applicable`，不得扣分或拒绝。O16、O24等解释比较型算子通常为true；O26等定量计算型算子通常为false。

校验器必须验证：

- 至少两个竞争判断在组合推理前均有事实支持；
- 错误竞争项不能由单句直接排除；
- 正确项不能独占完整解释；
- 区分依赖多事实组合或算子规定的专属计算；
- 删除区分事实后竞争关系应重新接近。

竞争偏弱属于结构风险，不直接永久拒绝算子。

例如两个候选解释都能覆盖时间事实，但解释B还无法解释对象特征。只要B仍有局部事实支持，竞争可能只是偏弱，应先重试增强合法观察或进入 exploration。若题面直接写“B当天在外地，不可能出现”，则B已经被显式淘汰，属于确定性泄漏。

“竞争解释存活”也不要求两个解释最终同样正确。它要求在应用决定性组合前，错误解释至少能解释一部分核心事实，不能被一个显眼句子立即排除。例如，两辆同型号车辆都可能出现在北门，使“另一辆相似车辆”具有局部合理性；7分钟与8分钟的联合约束最终使两段记录不能直接闭合，但这不等于题面可以提前写“另一车辆解释更合理”。

### 10.5 第五层：角色和表面偏差检查

针对实体、解释、路径、规则和候选观察执行：

- 名称交换；
- 呈现顺序交换；
- 描述长度交换；
- 专业来源名称替换；
- 精确数字位置交换。

交换后语义答案必须保持不变。如果答案随表面特征变化，标记 `salience_imbalance`。

交换检查只改变表面载体，不改变事实语义。例如把“车辆甲/乙”整体重命名为“车辆乙/甲”时，相关记录和参考答案映射也要同步交换；如果只替换题面名称而不更新答案映射，测到的是测试脚本错误，不是模型偏置。

与之相对，改变“20:17进入”到“20:25进入”可能改变时间可达性，这是决定性变量控制，不属于表面交换。两类测试必须分开记录，否则会把真正的因果变化误报为位置偏置。

交换检查不是简单替换字符串，而是保持事实关系不变的等价变换：

* 名称交换：同时交换车辆A/B的全部引用，不能只改题干不改候选；
* 顺序交换：调整事实呈现顺序，但不改变时间值和关系方向；
* 长度交换：将解释性细节在候选间对称重写，检查正确项是否靠篇幅获益；
* 来源名称替换：把“国家级实验室”和“普通摄像头”匿名化为来源1/2，再看答案是否仍由质量事实决定；
* 数字位置交换：在逻辑允许的控制样本中交换显眼数字所在候选，检查模型是否追随数字显著性。

若交换改变了事实含义，就不是表面控制。例如把“车辆A离开东门”改成“车辆B进入东门”同时改变了实体和动作，不能据此判定名称偏置。

如果控制变体没有正确同步全部事实、候选标签和答案映射，应记录 `control_variant_invalid` 或 `unresolved`，不能把控制样本生成错误写成原候选失败。

### 10.6 第六层：链条预闭合检查

针对 O10、O13、O20、O21、O22、O28 检查：

- 是否存在完整的起点到终点顺序总结；
- 是否每一跳已经被题面解释；
- 是否在结尾重复全部链条；
- 是否只需复述题面便可作答；
- 是否仍需进行实体、时间、状态或路径绑定。

### 10.7 第七层：可回答性和专属负担

通过前述检查后，还必须验证：

- 不依赖题外知识；
- 不存在事实矛盾；
- 题面足以得到唯一答案或有依据的校准答案；
- 隐藏控制要求的推理义务确实在题面中存在；
- 难度来自目标能力轴，而不是格式、篇幅或计算繁琐度。

## 11. 重试和候选分流

### 11.1 定向重试映射

“定向重试”是只修复已定位问题的最小改写，不是让模型从头自由生成。重试输入应包含失败标签、证据句、允许保留的事实 ID 和禁止恢复的命题。例如，发现 `role_binding_disclosure` 时应删除“运输者”称谓，但保留该实体在各时间点的行为；如果完全重写所有事实，会破坏来源追溯和消融关系。

| 失败标签 | 重试动作 |
|---|---|
| `direct_answer_leakage` | 删除直接答案命题，保留合法原子事实并恢复中性任务 |
| `target_chain_disclosure` | 删除链路总结，将其拆回原子观察，不删除必要事实 |
| `derived_summary_leak` | 删除总结命题，恢复其来源观察，禁止同义改写总结 |
| `rule_ceiling_disclosure` | 保留原始规则，删除规则对当前事实的适用结论 |
| `role_binding_disclosure` | 删除角色名称，只保留带时间和方向的行为 |
| `competitor_elimination` | 删除直接反驳句，为竞争解释保留局部支持 |
| `answer_direction_disclosure` | 将问题和事实改为中性表达，不得用谨慎措辞替代答案 |
| `answer_template_disclosure` | 删除分层、逐项和边界作答要求，恢复自然业务问题 |
| `salience_imbalance` | 平衡信息量、句式和精度，不得增加答案解释 |
| `hypothesis_status_disclosure` | 删除假设已成立/失败的预设，改为对称中性比较 |
| `fact_role_disclosure` | 删除关键、决定性、无关等角色词，只保留原子观察 |
| `rule_application_disclosure` | 保留原始规则，删除当前事实到规则结论的映射 |
| `missing_link_disclosure` | 删除缺口名称，保留各跳观察让回答者自行检查 |
| `uniqueness_disclosure` | 删除唯一性声明，恢复真实竞争候选与合法原子事实 |
| `forced_conclusion_type` | 改成允许结论契约全部合法 outcome 的中性任务 |
| `counterfactual_result_disclosure` | 保留单变量变化，删除结果预测 |
| `control_role_disclosure` | 删除基准、消融、干扰或控制角色措辞 |
| `authority_bias` | 匿名化或交换来源名称，以质量事实替代权威暗示 |
| `position_or_naming_bias` | 交换并平衡名称、位置和顺序 |
| `metadata_leakage` | 修复请求白名单后重新生成；敏感内部信息真实暴露时 hard reject |
| `unanswerable_after_cleanup` | 补回缺失原子事实，不得补回答案总结 |

标签严重程度必须直接复用第 28 号方案“13.7 统一风险和默认处理”。Validator、Candidate Selection、重试器和 Memory 不得分别给同一个标签另定严重程度。例如 `competition_weak` 默认进入 exploration，不能在 Candidate Selection 中又被改成 hard reject；高风险 `unresolved` 也不能因为 exploration 尚有预算就进入正式评分。

每种失败最多执行一次针对性重试，同时每个候选最多重试两次：

```json
{
  "retry_budget": {
    "max_retries_per_label": 1,
    "max_total_retries_per_candidate": 2
  }
}
```

“每类一次”防止用同一标签反复改写，“候选总计两次”防止不同标签依次触发过多模型调用。例如同一候选先修复 `role_binding_disclosure`，随后可以再修复一次独立的 `position_or_naming_bias`；如果第三次又出现 `salience_imbalance`，不再继续改写，而是根据当前风险进入 exploration、透传或拒绝。不得用近义标签绕过任一上限。

### 11.2 分流语义

`hard_reject`：

- 信息闭包失败；
- 无法通过删除局部总结安全修复的直接或语义等价答案泄漏；
- 重试后仍存在的明确角色绑定、规则应用结果或竞争解释淘汰；
- 不可回答或事实矛盾；
- 新增无来源规则和阈值。

直接金标、敏感内部字段真实暴露、无来源事实和事实矛盾可以立即拒绝。角色称谓、答案总结句、规则应用措辞等可以在保留合法原子事实的前提下删除时，应先定向重试一次。

`main_chain_candidate`：

- 所有适用于当前算子的必做检查均为 `passed`；
- 不适用检查明确为 `not_applicable`，不能要求其通过；
- 不存在关键 `failed` 或高风险 `unresolved`；
- 信息闭包、可答性和专属推理义务检查均满足当前算子的要求。

例如，O26 定量阈值题的 `competition_survival` 可以是 `not_applicable`，只要公式、单位、误差传播、阈值判断等必做检查通过，仍可进入主链。反过来，O16 明确要求竞争解释存活，该检查就必须为 `passed`。低风险 `unresolved` 不进入主链，也不 hard reject，而是进入 `exploration_candidate`。

`exploration_candidate`：

- 无硬风险；
- 竞争性、显著性、算子边界或推理负担存在轻度不确定；
- 已经过一次定向重试；
- 每组和每轮均受现有 exploration 预算限制。

`pass_through_candidate`：

- 无法在不补造规则、不补答案链的前提下完成算子改写；
- 题面已无可用进化空间；
- 算子虽适用主题，但无法形成目标能力负担。

四类分流的直观区别：

| 情况 | 分流 | 原因 |
|---|---|---|
| 题面新增了无来源的真实规则 | `hard_reject` | 存在确定性事实风险 |
| 题面写出“乙负责运输”但可删除称谓保留行为 | `retry_same_operator`，失败后再决定 | 问题明确且可局部修复 |
| 竞争解释有支持但强度略弱 | `exploration_candidate` | 无硬风险，交给真实模型实验判断 |
| source-faithful槽位不足且任务未授权合成 | `pass_through_candidate` | 无安全改写空间，不是系统故障 |

分流判断的是当前候选去向，不是对整个 operator 的永久评价。一个 O19 候选因角色泄漏被拒绝，不表示 O19 应整体停用；只有资格统计和多样本证据才能更新 operator runtime policy。

同一车辆题在不同质量下的分流示例：

| 候选情况 | 分流 | 理由 |
|---|---|---|
| 新增无来源“车辆A在盲区换牌” | `hard_reject` | 来源闭包失败，且改变了案例世界 |
| 写出“唯一缺少车牌记录” | `retry_same_operator` | 缺口泄漏明确且可通过删除总结句修复 |
| 事实均合法，但竞争车辆是否具有足够竞争力无法稳定判断 | `exploration_candidate` | 没有hard risk，用强模型、弱模型和Judge实测 |
| 无法确认通行规则是否为当前有效版本 | `needs_manual_review` / `pass_through_candidate` | 规则错误会改变正确答案，不能直接进入评分 |
| 所有检查通过且推理义务存在 | `main_chain_candidate` | 可进入后续授权范围内的实验 |
| 原题缺少通行时间，任务禁止合成局部参数 | `pass_through_candidate` | 无法安全补齐可答性条件 |

`hard_reject` 拒绝的是当前候选，不等于永久暂停整个算子；`pass_through` 保留的是原题，不等于候选生成发生异常；`exploration_candidate` 也不等于已经证明难度增益。

### 11.3 执行范围门禁

`execution_scope` 只控制这一次运行执行到哪里，不能改变完整系统的目标。正式实验的主路径必须跑到效果确认和下一轮决策；只有开发、调试、Shadow 或局部回放才停在结构检查。

正式实验必须显式读取完整配置：

```json
{
  "execution_profile": "full_iteration",
  "require_full_pipeline": true,
  "on_missing_scope": "fail_configuration",
  "execution_scope": {
    "max_stage": "effect_claim",
    "allow_reference_rebuild": true,
    "allow_model_answering": true,
    "allow_judge_scoring": true,
    "allow_effect_claim": true
  }
}
```

开发工具可以使用：

```json
{
  "execution_profile": "structure_debug",
  "execution_scope": {
    "max_stage": "manual_review_preparation",
    "allow_reference_rebuild": false,
    "allow_model_answering": false,
    "allow_judge_scoring": false,
    "allow_effect_claim": false
  }
}
```

缺失配置时必须区分入口。单独开发工具可以保守按 `structure_debug` 停在复核材料准备；正式迭代入口必须要求 `full_iteration`，缺少强模型、弱模型、Judge、参考答案重建、Rubric 重建或完整 scope 时，在启动前报告配置错误，不能静默生成一个没有真实实验的“成功”结果。只有对应布尔值与 `max_stage` 同时允许时，才执行相关阶段；越权阶段记录 `scope_blocked`，不得伪装为生成失败、算子不适用或模型错误。

本方案治理的前半段保持：

```text
路由 -> 题目生成 -> 题面校验 -> 候选选择
```

候选选中后的正式主流程按第 29 号 v2.2 方案执行：

```text
重建并独立核验新参考答案
-> 生成新Rubric/Score Prompt
-> 弱模型只看最终题面回答
-> 使用新Rubric评分
-> 效果归因与Memory更新
-> 生成下一轮决策并继续运行
```

这不是推翻整个 pipeline，而是为保证新题、新答案、新 Rubric 和新分数属于同一题目版本，对后半段依赖关系做增量调整。

### 11.4 单题门禁与算子资格分开

单题门禁只回答当前候选的去向：通过、重试、探索、人工复核、透传或拒绝。算子资格是在一批样本上统计该算子能否发布，两者不得混用。

例如，“竞争解释存活率不低于90%”是20道以上资格样本的批量指标，不是要求某一道题的Judge置信度必须达到0.90。单题Judge只能输出 `passed/failed/unresolved/not_applicable`，不能用0.88与90%资格线比较后直接拒绝。

算子资格结果建议单独写入 qualification report，不进入单候选 `validation_disposition` 的硬拒绝逻辑。

## 12. 效果分析和成功记忆修正

`effective_boundary_probe` 表示候选通过真实实验暴露了弱模型在目标能力上的边界，而不是“题目分数下降了”这一单一现象。所谓目标错误命中，是指弱模型的错误内容与算子预先声明的能力义务对应，例如O22目标是联合可达性时，弱模型确实忽略了方向边或时间窗，而不是因为漏答附加格式要求而失分。

`effective_boundary_probe` 必须同时满足：

1. `score_delta < 0`；
2. 弱模型答案命中该算子的目标错误；
3. 强答案或参考答案通过同一 Rubric；
4. 题面无硬泄漏、不可答和事实冲突；
5. 降分不是由格式、题面异常、Judge 波动或 Rubric 偏移造成；
6. effect evidence 明确指出目标错误与算子能力轴的对应关系。

只满足降分、关键词焦点或模型答案变短时，不扩展现有主效果枚举，而是在 `effect_analysis.effect_confirmation_status` 中标记为 `ambiguous_effect`，不得写 operator success memory。

`score_increased` 保持现有负收益语义：

- 写入 failure memory；
- 不进入成功终止态；
- 不写 operator success memory；
- 下一轮切换 operator 或策略。

“命中目标错误”要求错误内容与算子能力轴对应，而不是只看总分。例如 O31 目标是观测独立性判断：弱模型把同一视频的截图、转录和裁剪当成三份独立证据，属于目标错误；弱模型因为漏写规定格式而扣分，则不是 O31 的成功证据。即使两种情况都表现为 `score_delta < 0`，只有前者可以支持 `effective_boundary_probe`。

同理，`score_increased` 表示弱模型在新题上得分更高，即题目相对更容易或评分发生偏移。它不能因为“答案更完整”或“模型更自信”而被重新解释成成功。

### 12.1 下一轮决策

每轮效果分析后必须输出机器可以执行的下一步，避免流程停在报告或人工建议：

```json
{
  "next_round_decision": {
    "action": "switch_operator",
    "reason": "score_increased",
    "parent_candidate_id": "C03",
    "retain_as_boundary": false
  }
}
```

允许的主要动作包括 `continue_same_operator`、`switch_operator`、`retry_generation_strategy`、`backtrack_to_parent`、`retain_as_boundary`、`stop_branch_success`、`stop_branch_no_gain`、`pass_through` 和 `manual_review`。

例如：

* 弱模型稳定降分、命中目标错误、强模型答对且 Judge 稳定：保留当前题作为边界样本，并可沿同一算子继续增加一级难度；
* 分数下降但错误原因不清：记为 `ambiguous_effect`，不写成功经验，下一轮更换生成策略；
* 分数上升：写失败经验，回到直接父题并切换算子；
* 题面仍有泄漏：定向修复一次，仍失败就放弃当前候选，不污染成功经验。

`backtrack_to_parent` 这里只表示回到当前候选的直接父题，不要求建设完整树搜索系统。

## 13. 具体实施阶段

### 阶段 0：失败基线和回放集

目标：在修改代码前固定当前失败形态，避免优化后只改变表现形式。

实施内容：

1. 从外部报告整理以下泄漏夹具：事实链补全、规则上限、竞争解释淘汰、角色预绑定、谨慎答案措辞、显式判别条件，以及 `hypothesis_status_disclosure`、`fact_role_disclosure`、`rule_application_disclosure`、`missing_link_disclosure`、`uniqueness_disclosure`、`forced_conclusion_type`、`counterfactual_result_disclosure`、`control_role_disclosure`、`authority_bias`、`position_or_naming_bias`、`metadata_leakage`。
2. 为每类泄漏准备直接表达和语义等价表达。
3. 为所有 O10–O33 建立最小正例、负例、泄漏反例、消融例和交换例。
4. 记录当前 validator 对每类夹具的命中和漏检情况。

建议新增测试文件：

```text
tests/test_surface_fact_contract.py
tests/test_generation_context_isolation.py
tests/test_semantic_leak_replay.py
tests/test_operator_counterfactual_controls.py
```

退出条件：现有失败能够在固定夹具中重现，所有预期失败均有明确标签，不使用自由文本代替断言。

### 阶段 1：父题事实解析和上下文净化

目标：阻止父题的问题措辞和答案方向继续进入题面编写上下文。

涉及文件：

```text
semantic_budget.py
question_evolution.py
prompts/operators/base.py
```

实施内容：

1. 将父题拆分为观察事实、原始规则、中性问题意图和禁止传播的结论性措辞。
2. `observable_fact_ledger` 不再保存未解析的完整父题作为单一事实。
3. 对无法可靠拆分的输入采用保守 fallback：保留原题或进入 exploration，不允许自由补写。
4. 为每项事实生成 `fact_id`、`world_id`、`global_fact_key`、`origin_type` 和可验证 `source_locator`；真实规则进入包含版本、适用范围与时效状态的 `rule_ledger`。
5. 保持历史字段不变，新契约放入 `meta_info.question_evolution_metadata`。

测试重点：

- 父题中的“不能直接认定”不进入 surface writer；
- 原始时间、行为和位置事实仍完整保留；
- 原始规则与规则解释被正确分开；
- 历史样本缺少新字段时仍能运行。

退出条件：surface writer 输入快照中不存在参考答案、Rubric、结论性父题问法和隐藏目标错误。

### 阶段 2：隐藏规划与盲题面编写分离

目标：从调用结构上阻止同一模型同时掌握答案结构和最终题面。

涉及文件：

```text
question_evolution.py
prompts/operators/base.py
prompts/operators/new_operator_support.py
```

实施内容：

1. 新增隐藏结构规划步骤，输出事实池、竞争解释、决定性事实和控制关系。
2. 新增题面事实编译步骤，只筛选允许公开的原子事实和原始规则。
3. surface writer 只接收编译后的事实池、中性问题意图和写作要求。
4. 规划器和 surface writer 使用独立调用上下文；禁止通过完整 sample dict 隐式传递隐藏字段。
5. 生成失败写入 `*.failed` 时保持非零退出语义。

测试重点：

- surface writer 的实际请求体不含 hidden control；
- 相同 prompt 的不同 `sample_id` 分别保留；
- 受控假设事实具有明确来源；
- 规划失败和题面编写失败不会产生不完整正式输出。

退出条件：上下文隔离测试通过，运行日志能够分别审计 planner 和 writer 的输入字段白名单。

### 阶段 3：全部算子内容重写

目标：修复 O10–O33 的算子级语义冲突和泄漏倾向。

实施顺序：

1. O10–O18：修复既有算子，O14 转全局 validator；
2. O19–O27：修复实体、事件、路径、观测、规则和跨层算子；
3. O28–O33：修复多跳、身份、主动观测、累积、角色图和跨模态算子；
4. 统一审查公共 `base.py`，确保没有重新注入完整目标链。

每个算子文件必须修改或确认：

- `goal` 只描述隐藏能力目标；
- `required_question_shape` 使用中性任务，不直接询问答案边界；
- `content_transformation` 不要求补足完整链；
- `invariants` 区分正例与负例，不预设结论成立；
- `competition_structure` 在算子需要竞争解释时确保竞争项真实存活；不需要时明确写“不适用”；
- `semantic_economy` 删除答案总结而不是删除必要事实；
- `forbidden_shortcuts` 覆盖命题级泄漏；
- 专属 positive、negative、ablation、swap controls 可执行。

禁止只修改 O27、O28、O31。所有生成算子必须逐个进入审查清单，并在测试中具有独立用例。

退出条件：全部算子通过内容契约测试，O14 不再进入生成路由，任何一个未审查算子都会阻止阶段完成。

### 阶段 4：语义校验器 Shadow 接入

目标：先测量新校验器的召回和误报，再启用硬门禁。

`Shadow` 表示新校验器照常运行并记录“如果启用门禁会如何处置”，但暂时不改变正式候选分流。它用于比较新旧结果、估计误报和成本，不是“低强度拒绝模式”。

涉及文件：

```text
prompts/validation_prompt.py
validate_evolved_question.py
validate_difficulty_gain.py
candidate_selection.py
```

实施内容：

1. 接入信息闭包、语义泄漏、单句直达答案、竞争存活、表面交换和专属负担检查。
2. 新标签先只写入 `validation_result`，不改变正式候选分流。
3. 对人工标注回放集统计每个标签的真阳性、假阳性和漏检。
4. 校准 hard risk 与 soft risk 的边界。
5. 不扩展 difficulty gain validator 的既有 enum；新诊断放入嵌套字段。
6. 适用的语义检查输出 `passed/failed/unresolved`，不适用时输出 `not_applicable`；低风险 unresolved 进入有预算的模型实验，高风险 unresolved 才转人工复核或透传，不得在 shadow 报告中写成通过。

退出条件：硬泄漏夹具召回率达到 100%，人工确认的干净题面误报率不高于 5%，所有误报均能溯源到具体句子和命题。

### 阶段 5：硬门禁、定向重试和候选分流启用

目标：阻止确定性泄漏进入主链，同时保留结构不确定候选的探索机会。

实施内容：

1. 信息闭包失败和硬语义泄漏进入定向重试。
2. 每种错误最多重试一次，每个候选总计最多重试两次，避免多个标签连续触发无限改写。
3. 重试失败的硬风险候选进入 `hard_reject`。
4. 仅有竞争偏弱、显著性偏差、算子轻微重叠、默认数量超出但结构合理或推理负担不确定的候选，优先按预算进入 exploration，通过真实模型实验继续判断。
5. 保持每组最多一个 exploration candidate 和每轮总预算限制。
6. `candidate_selection` 继续兼容历史数据和现有四类分流。

退出条件：主链中硬泄漏数量为 0；weak risk 不被错误全量拒绝；现有 exploration 和 hard risk 覆盖测试全部通过。

### 阶段 6：效果确认和 Memory 写入修正

目标：只把真实目标错误命中记录为算子成功。

涉及文件：

```text
analyze_evolution_effect.py
update_sample_state.py
```

实施内容：

1. `effective_boundary_probe` 增加目标错误证据、可回答性和无泄漏前置条件。
2. 仅有分数下降或关键词命中时，在可选嵌套字段 `effect_analysis.effect_confirmation_status` 写 `ambiguous_effect`，不改变现有主效果枚举。
3. `score_increased` 继续作为负收益写入 failure memory。
4. operator success memory 必须保存目标错误证据摘要，而不是只保存算子 ID 和分数变化。
5. 不修改现有 `score_increased` 终止语义。
6. 每个已完成效果分析的候选生成 `next_round_decision`，供下一轮继续同算子、换算子、返回父题或停止分支。

退出条件：泄漏题、不可答题和格式性降分不能写入 operator success memory；相关回归测试通过。

### 阶段 7：Forced Qualification 和发布

目标：在正式自然路由前确认每个算子的内容质量和真实效果。

`Forced Qualification` 指测试框架显式指定某个算子生成候选，使低召回或尚未进入自然路由的算子也能获得足够测试样本。它只用于资格验证，不允许绕过任务授权、mode gate、事实来源或安全门禁。

每个生成算子至少准备：

- 2 个正常正例；
- 2 个结论不变负例；
- 2 个决定性事实消融例；
- 2 个无关事实消融例；
- 2 个名称或顺序交换例；
- 2 个答案泄漏注入反例；
- 2 个受控假设事实案例。

受控合成资格测试必须由 forced qualification 任务显式授权；授权只在该测试任务范围内生效，不能反向开启自然路由中的合成权限。

`forced qualification` 表示测试框架明确指定某个 operator 生成候选，用于验证它是否合格；`natural routing` 表示 Router 根据真实样本自动选择 operator。强制测试可以覆盖低频边界案例，但测试通过前，该 operator 不能因为某次 forced run 成功就自动进入自然路由。

每个算子至少执行 20 个 forced generation 候选。建议资格门禁：

- 硬泄漏进入主链数量为 0；
- 信息闭包通过率不低于 95%；
- 表面交换一致率为 100%；
- 无关事实消融一致率不低于 95%；
- 决定性事实消融有效率不低于 90%；
- 对声明 `requires_live_competitor=true` 的算子，竞争解释存活率不低于 90%；其他算子记为不适用，不纳入该指标分母；
- 至少两个独立样本经人工复核命中目标错误；
- `score_delta` 中位数小于 0；
- `score_increased` 不计入任何成功指标。

以上百分比全部按一批资格样本统计，不得用于单个候选。例如，竞争存活率90%表示20个资格候选中至少18个通过相应检查，不表示某个候选的语义Judge分数低于0.90就应拒绝。

未通过资格的算子不得进入自然主路由，只能继续 forced qualification 或保持 suspended。

## 14. 测试计划

### 14.1 公共契约测试

- 父题全文不再直接作为 observable fact；
- planner、writer 和 validator 上下文白名单正确；
- 受控假设事实有稳定来源；
- 合成与来源改编在缺少显式任务授权时保持关闭；
- 来源事实具有可验证 locator 与 `global_fact_key`；
- 真实规则缺少版本、适用范围或有效性时不能作为当前规则；
- 每个候选具有 `conclusion_contract`，唯一性要求具有公开事实和规则依据；
- `execution_scope` 能阻止未授权的参考答案、模型回答、Judge 与效果阶段；
- 新字段位于既有嵌套结构；
- 历史数据走 fallback。

### 14.2 泄漏检测测试

每类泄漏至少覆盖：

- 显式表达；
- 谨慎措辞改写；
- 否定式改写；
- 结尾总结；
- 候选解释说明；
- 角色叙述；
- 规则适用结论。

统一泄漏标签表中的每个标签都必须至少具有显式表达、语义等价表达和干净对照；“假设A成立，再分析B为何不成立”必须精确命中 `hypothesis_status_disclosure`。另需覆盖语义 Judge 不一致、超时和无足够证据时输出 `unresolved`：低风险结构项进入预算内实验，高风险来源、规则或答案项进入人工复核或透传，任何一种都不能伪装成通过。

### 14.3 算子专属测试

所有 O10–O33 均需覆盖：

- 正例；
- 结论不变负例；
- 邻近算子反例；
- 决定性事实消融；
- 无关事实消融；
- 表面交换；
- 答案泄漏注入。

### 14.4 流程回归测试

继续运行：

```bash
pytest -q
```

并重点确认：

- `weak_gain` 无 hard risk 时仍可进入 exploration；
- 历史记录中的旧 `needs_manual_review` 若没有来源、规则版本、答案唯一性、隐藏事实或其他高风险证据，由兼容层重新映射为 `exploration_candidate`；
- 新契约产生的 `needs_manual_review` 表示存在不能自动安全继续的高风险不确定项，不得直接进入正式评分；
- hard risk 覆盖 exploration；
- O26 等非竞争型算子的竞争检查为 `not_applicable` 时，其他适用的必做检查通过即可进入主链；
- 低风险 `unresolved` 进入 exploration，不进入主链或 hard reject；
- 同一标签最多重试一次，同一候选总计最多重试两次；
- Validator、Candidate Selection、重试器和 Memory 使用同一风险映射；
- 每组和每轮 exploration 预算仍生效；
- `score_increased` 不进入成功终止态；
- round0 稳定评分语义不变；
- O14 不再作为生成算子；
- O10–O33 均无显式脚手架回归。

## 16. 风险与缓解

### 16.1 生成调用成本增加

风险：planner、writer 和 semantic validator 分离后调用次数增加。

缓解：

- 先做确定性来源和表层检查，只有通过后才调用语义 Judge；
- 缓存父题事实解析结果；
- 同一候选只允许一次同类定向重试；
- 资格未通过的算子不进入自然路由，避免低价值调用。

### 16.2 validator 过严

风险：自然且有探索价值的问题被大量拒绝。

缓解：

- 硬风险与结构弱风险分开；
- 新标签先 shadow；
- `competition_weak`、`salience_imbalance` 不直接 hard reject；
- 保留 exploration 预算。

### 16.3 为避免泄漏而删掉必要事实

风险：题面变得不可回答。

缓解：

- 删除的是派生结论，不是来源事实；
- 清理后重新运行可回答性校验；
- `unanswerable_after_cleanup` 只能补原子事实，不能恢复总结句。

### 16.4 受控假设事实变成外部事实补造

风险：生成器借“假设案例”引入现实规则或专业结论。

缓解：

- 只允许观察级事实；
- 每项假设事实有独立来源标签；
- 规则、阈值必须来自父题或题内明确给定；
- O14 对新增事实逐项审核。

### 16.5 问题换一种表达继续存在

风险：模型避开禁词，用语义等价句继续泄漏。

缓解：

- 校验题面命题与隐藏答案命题的蕴含关系；
- 使用单句直达答案检查；
- 对每类失败维护多种改写夹具；
- 失败重试要求删除命题，不允许只换措辞。

## 17. 回滚策略

1. 新校验器先 shadow，不直接改变历史流程。
2. 通过环境开关分别控制上下文净化、planner/writer 隔离和语义硬门禁。
3. 回滚时恢复旧生成路径，但保留新审计字段，不删除实验记录。
4. 单个算子出现质量下降时只暂停该算子，不回滚其他已资格算子。
5. 不修改历史 JSONL，不重写既有实验目录。

## 18. 完成定义

只有同时满足以下条件，本方案才算完成：

1. 父题事实、问题意图和答案方向已经分离。
2. planner、surface writer 和 validator 的上下文权限通过测试。
3. O10–O33 已全部逐项审查和修改，O14 已接入全局信息闭包校验。
4. 所有算子均有正例、负例、消融、交换和泄漏注入测试。
5. 硬语义泄漏不会进入主链。
6. 结构弱风险仍可在预算内进入 exploration。
7. `score_increased` 保持负收益语义。
8. `effective_boundary_probe` 由目标错误证据支持。
9. 全量 pytest 通过。
10. forced qualification 满足发布门禁，未通过算子不进入自然主路由。
11. 任务授权、样本资格和模式选择已经分离，未授权合成不会发生。
12. 来源事实和真实规则具备可验证追溯、版本与适用范围控制。
13. 每个候选声明结论契约，唯一答案要求有可审计依据。
14. 适用的语义校验使用 `passed/failed/unresolved`，不适用时使用 `not_applicable`，`unresolved` 不会被误当通过。
15. 完整泄漏标签、定向重试映射、统计和回放夹具已同步。
16. `execution_scope` 能阻止越权执行后续模型与评分阶段。
17. 候选选中后的参考答案、Rubric、弱模型回答和评分依赖关系与第 29 号 v2.2 工程方案一致。
18. 正式入口要求 `full_iteration`，缺少完整模型或评分配置时会在启动前明确失败，不会静默降级为离线结构检查。
19. 低风险 `unresolved` 能在预算内自动进入真实模型实验，高风险 `unresolved` 才进入人工复核或透传。
20. 每轮效果分析后都有机器可执行的 `next_round_decision`，可继续、换算子、返回父题或终止当前分支。
21. `main_chain_candidate` 只要求适用的必做检查通过，不适用检查为 `not_applicable`；低风险 unresolved 只进入 exploration。
22. 单候选总重试预算和统一标签风险映射已在 Validator、Candidate Selection、重试器、Memory 与回归测试中保持一致。

本方案的最终判断标准不是题目是否更长、禁词是否更少或表达是否更谨慎，而是回答者是否仍需自行完成目标链条、规则适用、角色绑定和竞争解释比较，并且真实评分能够确认这种推理负担暴露了弱模型的能力边界。
