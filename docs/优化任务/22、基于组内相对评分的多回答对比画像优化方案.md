# 基于组内相对评分的题目行为机制诊断与迁移方案

- 状态：提案，已按当前项目结构重新整理
- 修订日期：2026-07-31
- 读者：负责评分、样本画像、算子路由、题目生成、实验复盘和人工审核的内部工程人员

## 1. 方案定位

当前流水线已经可以完成以下主流程：

```text
题目评分
  -> 样本画像
  -> 选择题目进化算子
  -> 生成新题
  -> 校验新题
  -> 再次评分
  -> 比较父题和子题分数
  -> 记录边界候选和实验结果
```

这个流程能回答"用了哪个算子后分数有没有下降"，但还不能稳定回答：

1. 分数低是模型真的不会，还是题目、参考答案、评分标准或评分模型有问题；
2. 同一道题的多个回答为什么有高有低；
3. 子题降分是算子压中了目标能力，还是引入了歧义、格式负担或不可回答内容；
4. 单题里观察到的失败原因，能否整理成跨题复用的机制。

本方案要补的是一层题目行为机制诊断。它不替代现有评分、画像、路由和题目生成，也不直接改变 `score_rate`、算子选择、搜索状态或正式记忆。它先把多次回答和多次评分的差异整理成可复查证据，再决定哪些证据可以沉淀为跨题复用的机制。

为了避免和全局记忆方案重复，本文把实施拆成两段：

- 诊断证据层：先在本方案中实现，产出题目级旁路诊断文件；
- 机制沉淀层：接入 25 号方案的全局记忆体系，不另建一套长期机制库。

## 2. 实施顺序总览

本方案不应完整排在 25 号方案之后，也不应完整排在 25 号方案之前。推荐顺序如下。

### 2.1 为什么先做 22A

22A 负责回答"这道题内部的回答差异是否可靠"。如果没有这层证据，25 号全局记忆只能主要依赖现有的成功、失败和无效生成记录，容易只知道"发生了什么"，但不知道"为什么发生"。

### 2.2 为什么机制沉淀要接入 25

25 号方案已经定义全局记忆要保存：

```text
场景类型 × 题型结构 × 推理机制或虚高机制 × 算子策略
```

本方案的机制卡本质上就是全局记忆卡的一种来源。因此，本方案不再单独建立长期机制注册表。机制候选、机制效果矩阵和路由旁路建议，都应进入 25 号方案定义的全局记忆发布、快照和审计流程。

## 3. 当前真实数据基础

当前评分产物已经支持多回答和多次评分。每条完成评分的记录通常包含：

- `scoring_result.answer_trials`
- 每个回答试次里有 `candidate_answer`
- 每个回答试次里有 `qwen_judge_results`
- 每个回答试次里有 `qwen_score_rate_mean`
- 可选 `gpt_judge_results`
- 可选 `gpt_score_rate_mean`
- `scoring_result.qwen_score_summary`
- `scoring_result.gpt_score_summary`
- `scoring_result.representative_trial_index`
- `score_rate`

首版必须继承以下边界：

1. `score_rate` 只由 Qwen 决策评分生成；
2. `scoring_result.qwen_score_summary.mean` 是当前主流程的分数来源；
3. GPT 评分只作为实验复评，用于离线对照，不能和 Qwen 分数平均；
4. GPT 评分缺失、失败或仍在等待时，不能阻断已经完成的 Qwen 决策评分；
5. 透传样本 `question_evolved == false` 不应重复生成回答或重新评分；
6. 后续画像、效果分析、状态更新和本地记忆写入，都不得读取 GPT 汇总来做正式决策。

## 4. 核心原则

### 4.1 分数现象不是原因

低分、高低回答分裂、拒答、分数波动，都只是表面现象。它们可能来自不同原因：

```text
模型真的不会
题目/参考答案有歧义或不可回答
评分标准太模糊或覆盖不全
评分模型对边界回答判断不稳定
回答格式负担过重
```

### 4.2 先用规则筛选，再让大模型解释

大模型不能在全量样本上自由解释原因。必须先用确定性规则判断：

1. 回答和评分是否完整；
2. 同一回答的重复评分是否稳定；
3. 不同回答的分数差是否足够明显；
4. 分差能否对应到具体评分标准项；
5. 题目、参考答案和评分标准是否完整。

只有通过这些检查的题，才可以调用单题观察器。

### 4.3 任何旁路诊断不得直接改主流程

在完成独立验证前，本方案产物不得修改：

- `score_rate`；
- `scoring_result`；
- `sample_profile`；
- `overscore_diagnosis`；
- `operator_route.operator_candidates`；
- `evolution_state`；
- `memory/*.jsonl`；
- 已冻结的 `operator_plan` 或搜索状态。

## 5. 组内统计方法

同一道题的多个回答构成一个组。先看每个回答自己的重复评分，再比较不同回答。

### 5.1 回答级统计

对每个回答计算：

- `qwen_score_rate_mean`
- `qwen_score_min`
- `qwen_score_max`
- `qwen_score_range`
- `relative_advantage`
- `relative_class`
- `gpt_score_rate_mean`
- `cross_judge_gap`

其中：

```text
group_mean = mean(所有回答的 qwen_score_rate_mean)
relative_advantage = qwen_score_rate_mean - group_mean
```

`relative_advantage` 只用于排序和描述，不能作为训练奖励，也不能直接进入正式路由。

### 5.2 同一回答的评分差异

同一个回答被多次评分后，如果分数不同，也要分析原因。它回答的问题不是"这个回答比同题其他回答强还是弱"，而是"评分本身是否稳定"。

对每个回答先计算：

- `qwen_score_min` = 同一回答多次 Qwen 评分的最低分
- `qwen_score_max` = 同一回答多次 Qwen 评分的最高分
- `qwen_score_range` = `qwen_score_max` - `qwen_score_min`

如果 `qwen_score_range` 很小，说明评分比较稳定，可以使用 `qwen_score_rate_mean` 代表这个回答。

如果 `qwen_score_range` 超过 `MAX_WITHIN_ANSWER_JUDGE_RANGE`，这道题先标记为 `judge_unstable`，不能继续推出"模型能力机制"。此时应优先检查：

1. 评分标准是否写得太模糊；
2. 参考答案是否只覆盖了一种说法；
3. 回答是否处在"可给分也可扣分"的边界；
4. 扣分项是否被不同评分重复触发得不一致；
5. 评分模型是否对同一段文字判断不稳定。

这类差异可以进入评分治理或人工复核，但不能直接说成模型能力问题。只有同一回答的重复评分稳定后，才比较不同回答之间的高低差异。

### 5.3 首版建议阈值

以下阈值只作为首版默认值。阶段 0 必须用真实实验数据校准，校准后再冻结。

```text
MAX_WITHIN_ANSWER_JUDGE_RANGE = 0.10
MIN_BETWEEN_ANSWER_GAP = 0.15
MIN_TRIALS_PER_ANSWER = 2
```

如果 GPT 结果还没有完成，不能生成强 `cross_judge_disputed` 结论，只能记录 `gpt_incomplete`。

## 6. 评分标准项级统计

只看总分不够。必须知道高低回答到底差在哪条评分标准上。

### 6.1 评分标准对齐

评分标准项必须按标题对齐：

1. 每条评分标准的 `title` 必须非空；
2. 同一套评分标准内 `title` 必须唯一；
3. 评分结果中的每个 `item_scores.title` 必须能对应到原始评分标准；
4. 标题无法对应时，该条评分不能进入强诊断。

### 6.2 正权重项

正权重项表示加分项：

```text
positive_award_ratio = awarded / weight
```

它用于判断某个回答是否稳定命中或稳定漏掉某条要求。

### 6.3 负权重项

负权重项表示扣分项，不能当普通加分项处理：

```text
penalty_activation = abs(awarded) / abs(weight)
```

0 表示没有触发扣分，1 表示完全触发该扣分项。高低回答如果主要差在扣分项上，必须单独标记，不能简单说是能力机制。

### 6.4 零权重项

`weight == 0` 的项只作为观察项，不进入得分率和难度归因。它可以辅助解释，但不能单独支撑机制结论。

## 7. 题目级标签

每道题至少生成一个题目级标签。多个标签可以并存，但必须有优先级。

```text
insufficient_trials
judge_unstable
cross_judge_disputed
rubric_or_question_risk
informative_answer_gap
uniformly_hard
uniformly_easy
near_group
```

优先级建议：

```text
insufficient_trials
  -> judge_unstable
  -> cross_judge_disputed
  -> rubric_or_question_risk
  -> informative_answer_gap / uniformly_hard / uniformly_easy / near_group
```

`uniformly_hard` 不应强行走高低回答对比。它可以进入"稳定失败诊断"，重点看多个低分回答是否稳定漏掉同一类要求。

## 8. 单题观察器

单题观察器的任务是解释：

- 高分回答做对了什么
- 低分回答漏掉了什么
- 这些差异能不能对应到具体评分标准项
- 这是不是能力机制，还是题目、评分标准或评分风险

### 8.1 调用条件

只有满足以下条件时才调用：

1. 题目标签包含 `informative_answer_gap`，或明确进入 `uniformly_hard` 稳定失败诊断；
2. Qwen 重复评分稳定；
3. GPT 完整时没有明显反向分歧；
4. 高低差异能定位到正权重项或扣分项；
5. 当前题目、参考答案、评分标准和评分配置完整；
6. 相同内容指纹和分析版本没有分析过。

每个题目版本最多调用一次。失败、超时或返回格式错误时，只记录失败状态，不发布半成品结论。

### 8.2 输入限制

为了避免大模型复述已有结论，第一次观察只允许读取：

- 当前题目；
- 参考答案；
- 评分标准；
- 选中的高分回答、低分回答和可选近均值回答；
- 统计后的评分标准项得分；
- 回答试次编号、评分标准项编号和回答片段编号。

第一次观察不允许读取：

- `sample_profile`；
- `overscore_diagnosis`；
- 历史算子；
- `expected_qwen_failure`；
- 评分模型的自然语言理由；
- 搜索终态；
- 任何记忆命中。

画像和历史字段只能在观察完成后，用于离线分组和复盘。

### 8.3 输出要求

输出必须是合法 JSON，建议使用新增结构约束文件：

```text
schemas/question_behavior_analysis.schema.json
```

每条输出至少包含：

```json
{
  "analysis_status": "completed",
  "behavior_labels": ["informative_answer_gap"],
  "difference_summary": "",
  "high_answer_strengths": [],
  "low_answer_failures": [],
  "rubric_evidence": [],
  "candidate_mechanisms": [],
  "question_or_rubric_risk": null,
  "confidence": "low"
}
```

每个结论必须引用具体证据：

- 哪个 `trial_index`；
- 哪条评分标准 `title`；
- 哪段回答文本；
- 如果使用扣分项，必须说明对应的扣分项。

没有证据时只能输出 `unknown`。不能用"推理不够深入""理解不充分"这类空话代替证据。

## 9. 旁路文件

旁路文件是独立诊断记录，不直接写回主评分记录。建议文件名：

```text
behavior_analysis.jsonl
```

每条记录至少包含：

```json
{
  "analysis_id": "",
  "root_sample_id": "",
  "node_id": "",
  "prompt_fingerprint": "",
  "rubric_fingerprint": "",
  "evaluation_config_fingerprint": "",
  "source_trial_ids": [],
  "group_statistics": {},
  "behavior_labels": [],
  "observer_result": {},
  "analysis_status": "shadow",
  "analysis_version": "question-behavior-v1",
  "created_at": 0
}
```

### 9.1 内容指纹

内容指纹用于判断旧分析是否还能使用：

```text
prompt_fingerprint
rubric_fingerprint
evaluation_config_fingerprint
```

任一指纹变化，旧旁路记录自动视为 `stale`。

### 9.2 幂等写入

恢复运行时不能重复写同一条分析。建议幂等键：

- `analysis_version`
- `root_sample_id`
- `node_id`
- `prompt_fingerprint`
- `rubric_fingerprint`
- `evaluation_config_fingerprint`

如果使用现有发布工具，应把 `behavior_analysis.jsonl` 登记到清单文件，和现有追踪旁路文件一样校验文件哈希。

### 9.3 父子题边界

父题分析不能直接复制给子题。子题题面、评分标准、参考答案或评分配置只要变化，就必须重新判断。父题诊断最多只能作为人工复盘背景，不能作为子题当前机制证据。

## 10. 机制卡和 25 号方案的关系

机制卡描述"跨多道题都能复现的失败原因"。它不是单题备注，也不是一次大模型解释。

本方案不单独建立长期机制库。机制候选应作为 25 号全局记忆发布流程的输入。对应关系如下：

```text
本方案产出机制候选 -> 25 号方案发布/快照/审计/回放
```

### 10.1 机制卡状态

机制卡状态建议沿用：

```text
proposed -> shadow -> qualified -> production
                 -> rejected
                 -> retired
```

状态含义：

```text
proposed: 刚从单题诊断归纳，尚未跨样本验证
shadow: 已有跨样本证据，但未进入正式路由
qualified: 通过验证集验证，可有限接入路由旁路
production: 稳定收益已确认，正式参与路由
rejected: 证据不足或反例过多，不再使用
retired: 曾经有效但已不再适用
```

### 10.2 发布前校验

机制卡从 `proposed` 升级到 `shadow` 或更高状态前，必须通过：

1. 来自多个不同 `root_sample_id` 的证据；
2. 至少覆盖一个以上场景或题型，除非明确标为局部机制；
3. 人工确认不是题面质量问题；
4. 人工确认不是评分标准固定措辞问题；
5. 人工确认不是评分模型不稳定；
6. 关联算子必须来自当前算子注册表；
7. 记录版本、适用条件、排除条件和反例。

评分标准风险、题面风险、评分模型不稳定，只能发布为风险卡或治理信号，不能发布为能力机制卡。

## 11. 机制效果矩阵

机制效果矩阵回答：

```text
某个机制 × 某个算子 × 某种题型 × 某类场景
到底有没有稳定效果
```

建议维度：

- `mechanism_id`
- `operator_id`
- `question_form`
- `scene_family`
- `version_compatibility_group`

建议指标：

```text
样本数
平均分数变化
稳定降分率
无效生成率
分数升高率
```

样本不足时只能展示统计，不得提升算子优先级。

## 12. 与路由和记忆的接入边界

### 12.1 路由旁路对照

当前路由已经有 `operator_decision_audit`，用于记录选择、排除和不确定原因。机制诊断接入路由时，首版只允许写入审计信息或独立旁路文件。

不得做以下事情：

- 不得把机制建议追加进 `operator_candidates`；
- 不得因为机制建议删除路由器返回的合法候选；
- 不得用机制建议重排已冻结的 `operator_plan`；
- 不得让机制建议绕过算子硬槽位检查；
- 不得让机制建议绕过题目可回答性和质量校验。

### 12.2 记忆写入边界

本地 `memory/*.jsonl` 目前记录的是实验事实，例如有效边界、失败经验和无效生成。22A 阶段不能写正式记忆。

只有满足以下条件后，机制相关结果才可以进入 25 号全局记忆发布流程：

1. 已有旁路诊断证据；
2. 通过机制卡发布校验；
3. 通过人工复核；
4. 与 25 号分类体系对齐；
5. 有固定快照和可回放记录；
6. 不使用来源实验自证上线效果。

## 13. 详细实施阶段

### 13.1 22A-0：离线统计

目标：先回答"当前数据里有多少题真的有可解释的组内差异"。

输入：

- 已完成评分的 JSONL；
- `scoring_result.answer_trials`；
- 当前评分标准；
- 当前评分配置。

产物：

- 离线统计报告；
- 每题题目级标签；
- 阈值校准建议；
- 不进入后续阶段的原因分布。

退出条件：

1. 能统计有效回答试次覆盖率；
2. 能统计 Qwen 重复评分稳定性；
3. 能统计回答间分差；
4. 能统计 Qwen/GPT 分歧；
5. 能统计正权重、负权重和零权重项；
6. 明确 `informative_answer_gap` 的覆盖率；
7. 如果覆盖率过低，停止在离线报告，不进入观察器。

### 13.2 22A-1：旁路诊断和单题观察

目标：对少量合格题生成可复查的单题诊断。

产物：

- `behavior_analysis.jsonl`；
- 观察器调用记录；
- 失败、跳过和过期记录；
- 人工抽检样本。

退出条件：

1. 结构化输出解析成功率达到预先冻结阈值；
2. 中高置信结论大多能定位到回答试次、评分标准和文本证据；
3. 泛化空话比例低；
4. 人工复核认为诊断不是简单复述评分模型理由；
5. 关闭开关后主流程输出完全不变。

### 13.3 25A：全局记忆基础层

目标：建立机制沉淀的公共底座。

本阶段属于 25 号方案，至少需要：

- 分类体系映射；
- 全局记忆卡结构文件；
- 发布候选结构文件；
- 运行时快照；
- 只审计检索；
- 发布报告。

没有 25A，本方案不应实现长期机制库。

### 13.4 22B-2：机制候选归纳

目标：从多个单题诊断中归纳候选机制。

输入：

- 已通过校验的 `behavior_analysis.jsonl`；
- 人工复核结果；
- 25A 的分类体系映射。

产物：

- `proposed` 机制卡候选；
- 反例列表；
- 风险标签；
- 进入 25 号发布流程的候选事实。

退出条件：

1. 每个机制候选都有多个独立样本证据；
2. 不把评分标准风险、题面风险或评分风险误发布为能力机制；
3. 每个机制都有适用条件和排除条件；
4. 每个机制都有可复查证据和反例。

### 13.5 22B-3：机制效果验证

目标：验证机制和算子之间的关系。

实验分两类：

```text
回溯实验：在已有实验数据上回放机制和算子的关系
前向实验：用新题和新样本验证机制是否能指导算子选择
```

必须冻结：

- 题目池；
- 作答模型；
- 作答参数；
- Qwen 评分配置；
- GPT 实验复评配置；
- 评分标准；
- 记忆快照；
- 阈值；
- 人工复核规则。

退出条件：

1. 分数变化超过回答和评分波动；
2. 子题低分命中目标机制；
3. 子题高分回答仍能通过正确推理拿高分；
4. 新失分不是题面歧义、不可回答、格式负担或评分标准漂移；
5. 机制能在独立原始样本上复现。

### 13.6 25B + 22C-4：路由旁路验证和有限接入

目标：只在已有充分证据后，验证机制提示是否能帮助路由。

首版只允许：

- 写入路由审计；
- 写入单独旁路文件；
- 比较机制建议和现有路由结果；
- 在独立验证集上回放验证。

只有满足以下条件后，才可以讨论有限接入：

1. 25 号全局记忆快照稳定；
2. 机制卡至少达到 `qualified`；
3. 独立验证集有稳定收益；
4. 没有增加明显的无效生成和分数升高；
5. 有开关、回滚和人工审核入口。

## 14. 校验规则清单

### 14.1 输入完整性校验

- `scoring_result` 必须存在；
- `decision_evaluation_status` 必须是 `completed`；
- `answer_trials` 必须是非空数组；
- 有效回答数必须达到 `MIN_VALID_TRIALS`；
- 每个回答必须有 `trial_index`、`candidate_answer`、`qwen_judge_results`、`qwen_score_rate_mean`；
- Qwen 分数必须在 0 到 1 之间；
- GPT 结果只在完整且有效时参与分歧观察。

### 14.2 评分稳定性校验

- 每个回答必须先计算 `qwen_score_min`、`qwen_score_max` 和 `qwen_score_range`；
- 同一回答内 Qwen 重复评分分差过大，标记 `judge_unstable`；
- 同一回答内评分差异过大时，必须保留最高分、最低分和对应评分结果，方便人工复查；
- 同一回答内评分差异过大时，优先检查评分标准、参考答案、扣分项和回答边界，不得直接归因为能力机制；
- 高低回答差距不足，标记 `near_group`；
- GPT 完整且方向相反，标记 `cross_judge_disputed`；
- 评分不稳定时，不得输出强机制结论。

### 14.3 评分标准校验

- 评分标准标题必须唯一；
- 评分项必须能对应到评分标准；
- 正权重、负权重、零权重必须分开统计；
- 观察器引用的评分标准项必须真实存在；
- 扣分项触发时必须单独说明。

### 14.4 观察器输出校验

- 输出必须是合法 JSON；
- 必须符合 `question_behavior_analysis.schema.json`；
- 每条结论必须能回查到回答试次、评分标准或回答片段；
- 没证据只能写 `unknown`；
- `confidence` 只能是 `low`、`medium` 或 `high`；
- `medium` 和 `high` 必须有可定位证据。

### 14.5 旁路文件校验

- 必须包含题目身份、节点身份、内容指纹、统计摘要、标签、版本和时间；
- 内容指纹变化后旧记录自动过期；
- 恢复运行不能重复写入；
- 父题记录不能直接当成子题记录；
- 旁路文件如果登记到清单文件，必须通过文件哈希校验。

### 14.6 机制卡校验

- 单题诊断不能直接升级为正式机制；
- 机制必须有跨样本证据；
- 机制必须有反例和排除条件；
- 风险类问题不能发布为能力机制；
- 关联算子必须来自当前算子注册表；
- 状态流转必须可追踪、可回退。

### 14.7 主流程隔离校验

- 不改 `score_rate`；
- 不改 `operator_candidates`；
- 不改 `evolution_state`；
- 不写正式记忆；
- 不改已冻结搜索计划；
- 旁路关闭后，主流程结果必须完全一致。

## 15. 测试要求

首版至少增加以下测试：

1. 回答试次顺序变化不影响组内统计；
2. 同一回答的 `qwen_score_min`、`qwen_score_max` 和 `qwen_score_range` 计算正确；
3. Qwen 重复评分分差过大时生成 `judge_unstable`；
4. `judge_unstable` 题目不会调用观察器生成能力机制结论；
5. 高低回答差距不足时生成 `near_group`；
6. GPT 结果缺失时不生成强 `cross_judge_disputed`；
7. Qwen/GPT 完整且方向相反时生成 `cross_judge_disputed`；
8. 正权重项比例计算正确；
9. 负权重扣分触发计算正确；
10. 零权重项不进入得分率归因；
11. 评分标准标题无法对齐时拒绝强诊断；
12. 未通过资格检查时不调用观察器；
13. 观察器输出证据引用不存在时拒绝发布；
14. 内容指纹变化后旧旁路记录过期；
15. 恢复运行不会重复写旁路记录；
16. 旁路诊断不会修改 `score_rate`、`scoring_result`、`operator_route`、`evolution_state` 或正式记忆；
17. 机制卡不能由单题诊断直接发布为 `qualified`。

## 16. 验收指标

每次实验前必须冻结主指标、样本划分、阈值、排除条件、评分配置和人工复核规则。

建议指标：

1. 有效回答试次覆盖率；
2. `informative_answer_gap` 覆盖率；
3. `judge_unstable` 比例；
4. `cross_judge_disputed` 比例；
5. 可定位评分标准差异比例；
6. 单题观察器 JSON 解析成功率；
7. 中高置信结论的证据可定位率；
8. 泛化空话比例；
9. 人工复核一致率；
10. 跨原始样本机制复现率；
11. 机制到目标错误的命中率；
12. 机制效果矩阵中的稳定降分率；
13. 题面/评分标准风险率；
14. 单个已确认边界成本；
15. 路由旁路建议在独立验证集上的收益。

如果阶段 0 或阶段 1 指标不足，应停止在离线报告和旁路诊断，不继续建设机制卡和路由接入。

## 17. 明确不做

首版不做以下事项：

- 不训练模型；
- 不把相对分数当奖励；
- 不把 `relative_advantage` 写入在线 `score_rate`；
- 不把 GPT 分数并入 Qwen 分数；
- 不把一次大模型解释写入正式记忆；
- 不让观察器全量运行；
- 不让机制归纳器自动发布机制卡；
- 不让机制卡自动创建新算子；
- 不用同一模型的高分回答替代人工或强外部正确性锚点；
- 不因旁路诊断修改候选选择、状态机或正式算子顺序；
- 不绕过 25 号全局记忆的发布、快照和回放验证流程。

## 18. 回滚

阶段 22A 的产物都是旁路数据。关闭开关、忽略 `behavior_analysis.jsonl` 或删除旁路产物，即可恢复当前主流程。

阶段 22B 的机制候选进入 25 号全局记忆发布流程后，回滚方式应沿用 25 号方案：

- 降级机制卡状态；
- 退役有问题的卡；
- 固定旧快照继续恢复旧实验；
- 新实验切回无全局记忆或只审计模式。

阶段 22C 如果进入有限路由实验，必须保留完整回退路径：关闭机制提示、恢复原路由、保留审计记录，并重新比较关闭前后的实验结果。
