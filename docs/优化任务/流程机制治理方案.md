3. 总体目标
机制优化的最高目标是让进化真正有效：系统根据路由选择合适算子，把原题改造成更难但仍合理、可回答、可评分的新题；弱模型在新题上稳定降分时，才认为找到了对应能力边界。
本方案中的来源拆分、题面隔离、校验、参考答案重建和评分版本控制都服务于这个目标。它们不是为了阻碍进化，也不是为了添加越多越好的审核规则。
机制优化要解决五个问题：
1. 信息不足时，系统可以构造题内假设场景、人物、实体、动作、路径、局部参数和竞争解释，用于形成有效难题。
2. 题面编写器不能看到正确答案、旧评分标准、事实角色和预期弱模型错误。
3. 题目变化后，旧参考答案、旧评分标准和旧分数不能继续用于新题。
4. 校验和审核只记录诊断、风险标签、重试建议和人工 review 线索，默认不直接阻断主链。
5. 只有真实回答和重新评分证明弱模型稳定降分且命中目标错误后，才能写成功经验。
4. 总体流程
正式流程调整为：
读取任务授权和执行范围
-> 识别来源事实场景
-> 拆分原始输入
-> 选择进化模式
-> 选择算子
-> 隐藏规划
-> 编译公开事实
-> 盲写题面
-> 独立校验并记录诊断
-> 根据诊断给出重试、探索、复核或透传建议

-> 重建新评分标准
-> 弱模型只看题面回答
-> 使用新评分标准评分

开发、调试和回放可以停在结构检查；正式实验必须跑完整闭环。缺少必要配置时，正式入口应直接报错，不能静默降级为“只做结构检查也算成功”。
校验结果不是天然阻拦条件。正式实验应优先让可修复、可探索、可评分的候选进入后续回答和评分，用真实弱模型得分判断是否有效；校验只负责记录风险和给出处理建议。

7. 阶段三：进化模式选择
7.1 四种模式
- source_faithful：只重组已有事实，不新增来源事实。
- controlled_hypothetical_case：默认允许建立独立题内假设案例，并新增人物、实体、动作、路径、局部参数、竞争解释等观察事实。
- controlled_synthesis：任务授权后，允许把题内假设案例扩展到更完整的训练场景，但仍不能伪造真实规则、真实法规或真实专业阈值。
- hypothetical_adaptation_from_source：任务授权后，允许把来源原则改编成新的假设案例。
- pass_through：无法安全进化时透传原题。
7.2 修改内容
- 新增模式决策器，输入为来源分析、样本资格、任务授权和允许模式。
- 模式决策器必须输出 authorization_checked 和 authorization_id。
- 路由器、经验库、算子资格、槽位完整性都不能绕过模式决策器。
7.3 验收标准
- 抽象题信息不足时，优先选择题内假设构题模式，而不是直接 pass_through。
- 真实案件事实不能被改成假设事实后继续冒充原案件。
- 缺少真实规则或专业阈值时，不能靠合成补齐真实规则；但可以使用题内明示的局部参数测试推理能力。
7.4 全局允许进化方向的流程承接
《全局规则约束》中列出的允许进化方向不是例外路径，也不是默认风险项。只要服务于当前算子的目标能力轴、题面可回答、后续可评分，并且不伪造真实外部事实、真实规则、真实专业阈值或真实案件结论，流程机制必须允许这些方向进入模式决策、路由、隐藏规划、题面编写、校验和真实评分。
本节承接四层参考范围：目标推理复杂度、七类进化方向、具体进化方法、题内假设合成。这些清单是当前认为合理、常见、需要优先保障的进化方向，不是封闭白名单。实现时不能只支持七类方向而遗漏具体方法，也不能只允许假设场景而误拒其他合法进化。
如果后续出现新的进化方向，只要同时满足“服务目标能力轴、题面自包含可回答、可重建参考答案和 Rubric、可被真实回答和评分验证、事实和规则来源可审计、不泄漏答案方向、不伪造真实外部事实或真实规则、不替换原题核心任务”这些全局约束，就应按同一流程接入，而不是因为不在本节表格中就默认拒绝。

8. 阶段四：模式感知路由器
8.1 修改目标
让规则路由器和混合路由器使用同一套准入语义。关键词只能召回候选，不能直接给执行资格。
8.2 路由层级
路由器按以下顺序执行：
任务授权检查
-> 进化模式检查
-> 算子槽位检查
-> 相邻算子消歧
-> 经验库排序
经验库只能参与最后排序，不能补齐真实外部事实、授予真实规则合成权限或覆盖前面门禁。经验库可以建议哪类题内假设结构更容易暴露弱模型能力边界。
8.3 路由治理规则
路由器必须把“找不到合适算子”作为可观测实验状态，而不是静默兜底到某个默认算子。
1. 取消默认 O10 fallback。
  - O10 只在其槽位、模式和样本资格真正满足时参与竞争。
  - 如果所有生成算子都不适用，路由器返回 no_safe_operator，不得自动改写为 O10。
  - no_safe_operator 必须记录分析原因，包括候选算子清单、每个算子的缺失槽位、模式不匹配、授权限制、事实来源限制和经验库排序前后的状态。
  - 该记录用于后验分析“样本为什么没有进入进化生成”，不能被写成有效进化失败，也不能让整轮实验停止。
2. O14 从生成算子退役，转为信息闭包校验。
  - O14 的定位是信息闭包、事实来源、世界一致性和非法规则风险的校验原则，不是生成题面的算子。
  - O14 不进入自然路由、候选生成、fallback 或算子探索队列。
  - O14 不一定马上从代码库彻底删除；可以保留为校验组件、兼容旧产物的解析入口或历史回放标识。
  - O14 输出只进入诊断、风险记录、重试建议和后验分析，不直接决定 skip_answer、skip_scoring 或 stop_pipeline。
3. O17 恢复为普通生成算子。
  - O17 已有明确题型能力和内容契约，不能因为历史上被主动关闭就排除在默认生成之外。
  - 除 O14 这类明确 validation_only 的算子外，所有给定生成算子地位相同，都应进入同一套路由准入检查。
  - O17 只能因与其他算子相同的规则被排除：样本不满足槽位、模式不合规、授权不足、事实来源不足或当前单次调试范围显式排除；这种排除必须记录原因，不能成为默认配置。
  - 不允许使用硬编码 enabled=false、低优先级封印或默认路由黑名单让 O17 永久不参与自然路由；如果 O17 缺少当前样本所需材料，应记录为槽位缺失，而不是算子级关闭。
8.4 修改内容
- 修改 operator_router.py，删除默认 O10 fallback。
- 修改 router_contract.py 和 prompts/router_prompt.py，新增来源分析、任务授权、进化模式、槽位状态和 no_safe_operator 原因记录。
- 在算子注册或路由配置中区分 generation 与 validation_only；O14 永远不进入生成候选，但可以接入校验链。
- 移除 O17 的默认关闭状态，让 O17 与其他生成算子同等参与自然路由。
- 没有安全算子时返回 no_safe_operator，上层记录空选原因、缺失槽位和可改进方向；不能静默兜底到 O10，也不能把路由空选写成内容审核失败。
- 更新 route cache 版本，旧缓存不能复用。
8.5 验收标准
- source_faithful 下，所有必需槽位必须来自来源事实。
- 题内假设构题模式下，可以合成人物、实体、动作、路径、局部参数、竞争解释和相关干扰事实。
- 任何模式下都不能合成真实规则、真实法规、真实专业阈值或冒充现实已发生的案件事实。
- 单个算子不适用时继续检查其他生成算子；全部不适用时记录原因并输出 no_safe_operator，不得默认回退到 O10。
- O14 只作为信息闭包校验运行，不出现在生成候选、fallback 候选或自然路由结果中。
- O17 出现在默认生成算子池中，且只按统一槽位、模式、授权和来源规则被接受或拒绝。
9. 阶段五：隐藏规划与盲写题面
9.1 修改目标
同一次模型调用不能既掌握答案结构又写最终题面。
9.2 修改内容
- 新增 prompts/evolution_planner_prompt.py。
- 隐藏规划器输出事实账本、竞争解释、正确答案轮廓、结论契约、控制计划、预期弱模型错误。
- 公开事实编译器只把允许公开的事实和中性任务交给题面编写器。
- 题面编写器只输出 evolved_prompt、used_fact_ids、surface_notes。
- 隐藏规划写入受限旁路产物，不放进普通下游上下文。
9.3 验收标准
- 题面编写器请求快照不包含旧答案、评分标准、answer_role、target_error、评分器意图。
- 题面编写器生成的每个事实都能在公开事实投影中找到。
- 题面不能出现未登记事实、答案方向或内部事实角色。
10. 阶段六：新校验器
10.1 修改目标
校验器不再只看词面禁词，而是检查事实来源、可答性、答案泄漏、竞争结构和控制测试。校验器的默认职责是记录诊断，不直接阻断主链。
10.2 校验顺序
L0：身份、Schema、旧评分状态
L1：事实来源、规则有效性、世界一致性、模式合规
L2：可答性、事实冲突、题外知识
L3：答案泄漏、单句直达答案
L4：复杂度、竞争存活、信息量平衡
L5：消融、名称交换、顺序交换
L6：预测结构收益
校验结果逐层记录。更贵的检查可以按预算运行，但前一层出现风险不必立刻中断；即使题面存在疑似不可答、泄漏答案、事实矛盾、严重改题或合成风险，也应继续产出完整诊断，便于后续重试和分析。只有 JSON 无法解析、必填字段缺失、题目为空、输出不是可发送给弱模型的问题等确定性技术不可执行问题，才允许停止本候选的下游执行。
10.3 处置规则
- 无来源事实、世界混合、编造真实规则、不可答、事实矛盾：记录为高风险诊断，候选选择阶段优先定向重试或转人工复核；如果候选技术上仍可发送、可重建评分材料，则继续进入真实回答和评分，并在后验分析中标记风险影响。
- 规则应用泄漏、角色绑定泄漏、链条总结、答案方向泄漏：记录泄漏标签和证据片段，定向重试一次；重试后仍有泄漏风险的候选继续作为高风险样本运行，不能仅凭泄漏诊断退出主链。
- 竞争偏弱、难度收益不确定、轻微信息量偏差：记录为探索风险，默认进入预算内探索。
- 来源、规则版本、答案唯一性、隐藏事实使用无法确认：记录为人工 review 线索；不直接作为全局阻拦。
- 不适用的检查写 not_applicable，不能当作失败。
10.4 验收标准
- 新校验器始终输出结构化诊断、风险标签、证据片段和建议动作。
- 即使切到正式生效，校验器也不直接删除候选；正式主链由 candidate_selection.py根据诊断、预算和实验目标决定重试、探索、复核或透传。
- candidate_selection.py 优先读取 validation_disposition.status，但不能只看顶层 passed=false，也不能把所有 unresolved 自动阻断。

11.4 验收标准

- 弱竞争不会被全量阻断，应进入预算内探索或记录为低效变难原因。
- 无安全进化方式时，输出 no_safe_operator或透传当前样本并记录原因，不把整轮实验停住。
12. 阶段八：参考答案与评分标准重建
12.1 修改目标

12.2 默认顺序

12.3 修改内容

13. 阶段九：效果确认、经验库和下一轮
13.1 有效进化条件
只有同时满足以下条件，才能写成功经验：
1. 弱模型多次回答后稳定降分。
2. 错误命中当前算子的目标能力。
3. 新参考答案或强模型答案正确。
4. 评分器评分稳定。
5. 题面没有会破坏实验有效性的答案泄漏、不可答或事实冲突问题；普通审核风险已经记录并可追溯。
6. 降分不是由格式复杂、任务堆叠或评分标准污染造成。
13.2 修改内容

- 修改 update_sample_state.py，只有确认或准确认效果才写 success memory。
- score_increased 继续写失败经验，不能写成功经验。
- 经验库只记录具体失败形态或成功证据，不能授予模式权限或补齐事实。
- 每个完成效果分析的候选输出 next_round_decision。
- 当前暂不开启纵向算子叠加。稳定降分且目标错误命中的候选只保留为边界样本并停止当前分支，不自动继续同算子加一级难度。

- 弱模型请求体只有最终题面。
- score_increased 只写 failure memory。
- next_round_decision 可以被下一轮直接消费。
17. 发布顺序
1. 先合入评分材料隔离，阻断旧答案污染。
2. 合入来源拆分、任务授权和模式决策器，先影子记录。
3. 合入模式感知路由器，取消默认 O10 fallback，设置 O14 为 validation_only，恢复 O17 自然路由，并保持旧结果对照报告。
4. 合入隐藏规划器与盲写题面，上下文隔离测试必须通过。
5. 合入新校验器，先影子运行并产出诊断报告。
6. 校准后开启定向重试和候选分流；校验器仍只记录结果，候选选择负责执行建议动作。
7. 合入参考答案与评分标准重建，调整 run loop 顺序。
8. 合入效果确认、经验库和下一轮决策。
9. 对除 O14 这类 validation_only 组件外的所有生成算子开放自然路由；强制资格测试只作为诊断和回归修复依据，不作为默认关闭某个生成算子的发布门槛。
18. 完成标准
满足以下条件后，机制优化可以进入正式实验：
- 真实外部事实、真实规则、专业阈值和真实案件结论不会被伪造成题内事实；题内假设构题默认允许并受账本约束。
- O14 不会进入路由器生成候选。
- O17 作为普通生成算子参与默认路由，不再被静态关闭。
- 除 O14 这类 validation_only 组件外，所有给定生成算子都按同一套路由准入规则参与选择。
- 找不到合适算子时记录 no_safe_operator、缺失槽位和分析原因，不默认 fallback 到 O10。
- 题面编写器上下文中隐藏字段数量为 0。
- 答案泄漏、不可答题、事实矛盾和严重改题会被记录、重试或复核；只要技术可执行且评分材料可生成，就继续进入弱模型回答和正式评分。
- 新题评分前都有已核验的新参考答案和新评分标准。
- 弱模型只看最终题面。
- score_increased 不写 success memory。
- 每个完成效果分析的候选都有可执行的 next_round_decision。
- 正式 full_iteration 能完整跑到效果归因和下一轮决策。
