## 1. 方案摘要

当前横向多算子搜索的行为是：对一个已经准入的父题，通过 LLM 路由和规则约束得到候选算子列表；每个候选算子形成一个分支，并完成题目进化、原有校验、候选模型回答、参考答案、Rubric、Score Prompt 和 Judge 评分闭环。父题的候选算子耗尽，或该层达到边界候选配额后，该父题不再展开。

本方案在此基础上增加一次纵向扩展。若根题的某条分支通过原有校验，且相对直接父题得分下降，则该子题成为 frontier。frontier 节点重新生成画像、重新执行 LLM 路由和规则约束，形成自己的候选算子列表；这些算子分别生成深度 3 的分支并完成同一评测闭环。

第一阶段只允许两个算子连续作用：

```text
depth = 1：root
depth = 2：root -> O1                 单算子结果
depth = 3：root -> O1 -> O2           两算子叠加结果
```

`depth` 3 的节点只记录评测结果，永不继续扩展。

```text
root
  ├─ O1 -> 降分 -> 单算子 boundary_candidate + frontier
  │           ├─ O2 -> 继续降分 -> 叠加 boundary_candidate，停止
  │           └─ O3 -> 不降分     -> 普通终态，停止
  ├─ O4 -> 不降分 -> 普通终态，停止
  └─ O5 -> 降分 -> 单算子 boundary_candidate + frontier
```

在线搜索只记录降分证据，不自动确认题目进化"最终有效"。人工审核在实验结束后判断边界候选是否真实反映目标能力边界。

## 2. 目标与非目标

### 2.1 目标

- 在原题核心能力轴附近，发现单个算子难以产生的两算子组合边界；
- 保留有序路径，区分 `O10 -> O15` 与 `O15 -> O10`；
- 复用既有题目生成、校验、回答、Rubric、Score Prompt、Judge 和 Memory 契约；
- 分别统计单算子边界与两算子叠加边界；
- 在严格的深度、配额、去重、预算和恢复约束下执行实验。

### 2.2 非目标

- 不探索第三个或更多连续算子；
- 不枚举全部算子排列或组合；
- 不新增语义相似度模型或自动判定"降分是否合理"的规则；
- 不把自动评分结果或 `review_status` 当作人工审核结论；
- 不改变候选模型回答、参考答案、Rubric、Score Prompt、Judge 或原有校验逻辑；
- 不因路径深度改变题目权重、得分规则或 Memory 业务准入；
- 不在第一阶段并行同一样本的多个 frontier 节点。

## 3. 核心定义

### 3.1 根节点、当前父节点与直接父子比较

根节点是完成基线评分且通过原始画像与候选准入的输入题。当前父节点可以是根节点，也可以是深度 2 的 frontier 节点。

每次扩展只比较直接父子题：

`edge_delta_score_rate = child_score_rate - parent_score_rate`

仅当 `edge_delta_score_rate` < 0 时，该边为在线降分证据。相对根节点的变化同时记录：

`root_delta_score_rate = child_score_rate - root_score_rate`

`root_delta_score_rate` 只用于分析，不参与是否进入 frontier 的判断。

### 3.2 边界候选与 frontier

一个节点满足以下条件时标记为 `boundary_candidate`：

1. 候选题通过原有校验；
2. 已完成完整评测闭环；
3. `child_score_rate` < `direct_parent_score_rate`。

`boundary_candidate` 是待人工审核的降分证据，不是最终有效边界。只有深度 2 的 `boundary_candidate` 可同时成为 `frontier_node`；深度 3 的降分节点只保留为叠加边界候选。

### 3.3 有序算子路径

每条路径使用有序 `operator_stack` 表示：

```json
{
  "operator_stack": ["O10_evidence_sufficiency_ladder", "O15_counterfactual_threshold_shift"],
  "depth": 3
}
```

可另行记录排序后的 `operator_set` 用于聚合统计，但不得用它替代执行、节点 ID、恢复键或直接父子关系。

## 4. 分层配额与终止规则

每个原始样本使用以下分层配额：

```json
{
  "single_operator_boundary_target": 5,
  "stacked_operator_boundary_target": 5,
  "total_boundary_hard_cap": 10,
  "max_depth": 3,
  "allow_operator_repeat_in_path": false
}
```

配额含义如下：

- 单算子边界候选是深度 2 节点，最多记录 5 个；
- 叠加边界候选是深度 3 节点，最多记录 5 个；
- 两类合计不得超过 10 个；
- 单算子配额达到 5 后，停止调度根节点尚未尝试的算子，但已生成的深度 2 frontier 仍可进入纵向扩展；
- 叠加配额达到 5 后，停止调度新的深度 3 分支；
- 某一层的算子耗尽时，保留该层实际数量，不用另一层补足。

正常终止原因为：

- `operator_space_exhausted`：根节点和全部允许扩展的 frontier 节点的算子计划均已完成；
- `single_operator_boundary_target_reached`：根节点停止继续展开，但仍需完成已登记 frontier 的深度 3 调度；
- `stacked_operator_boundary_target_reached`：叠加边界达到 5，样本完成；
- `total_boundary_hard_cap_reached`：总边界候选达到 10，样本完成。

前两类层级配额是调度限制，不是人工审核结论。

## 5. 总体流程

```text
已评分输入
  |
  v
根节点执行原有画像、候选准入、LLM 路由和规则约束
  |
  v
根节点横向分支：每个路由候选算子执行完整闭环
  |
  +-- 校验失败、重复耗尽、不适用、分数不变或上升 --> 当前分支停止
  |
  +-- 相对根节点降分 --> 记录深度 2 单算子 boundary_candidate
                              |
                              v
                    收集全部已调度 frontier
                              |
                              v
              对每个 frontier 按稳定顺序重新画像和重新路由
                              |
                              v
                   frontier 横向分支：每个候选算子执行完整闭环
                              |
                              +-- 相对直接父节点降分
                              |      --> 记录深度 3 叠加 boundary_candidate
                              |
                              +-- 分数不变或上升 --> 当前分支停止
                              |
                              v
                         深度 3 一律不再扩展
```

根节点使用原有"是否值得进化"的准入逻辑。frontier 节点不重复执行该硬准入否决：它已经因"通过原有校验且相对直接父题降分"取得继续探索资格。

## 6. frontier 重画像与重路由

深度 2 frontier 必须使用当前题面重新生成画像，并基于新题面、新参考答案、新 Rubric、新 Score Prompt、候选模型回答和评分结果重新执行 LLM 路由与规则约束。不得继承根节点的 `operator_plan`。

路由层应接受明确的 `frontier_route` 上下文。该上下文的作用是：

- 要求使用当前节点的新画像和现有评分证据建立新的候选算子列表；
- 绕过仅适用于原始样本的"是否值得进入进化流程"硬停止；
- 不绕过算子启用状态、运行时规则约束、`not_applicable`、路径去重和预算保护；
- 记录该节点用于路由的画像版本、路由版本、Memory 快照和候选计划。

候选算子列表以现有 LLM 路由和规则约束的最终结果为唯一来源。纵向模式不额外枚举所有已启用算子，也不继承根节点列表。

同一路径默认禁止重复算子：

```text
允许：O10 -> O15
禁止：O10 -> O10
```

未来若研究连续强化，可单独开启 `allow_operator_repeat_in_path=true` 并与默认实验分开统计。

若深度 3 节点相对根题仍然较低、但相对深度 2 父题回升，它是 `score_increased`，不是叠加边界候选。深度 2 的已有降分边仍可作为其单算子边界路径保留。

## 8. 去重、重试与路径约束

继续使用精确重复，不引入语义相似度模型。比较前仅执行：

1. 去除首尾空白；
2. 将连续空格、换行和制表符合并为一个空格。

重复检查范围覆盖整个原始样本树：

- 当前直接父节点；
- 当前路径的所有祖先；
- 当前父节点下已接受的兄弟节点；
- 同一样本中已登记的其他纵向节点。

同一"父节点 + 算子"首次生成精确重复时，允许使用同一算子重试一次；第二次仍重复则标记为 `duplicate_exhausted`。重复重试不消耗原有复杂度或可回答性校验重试次数，也不进入后续答案、Rubric 和评分闭环。

## 9. 并发与调度

不同原始样本可并行，继续受全局请求、评分和 API 限流预算约束。

同一样本必须保留层级屏障：先完成根节点已调度的横向分支，收集深度 2 frontier，再按稳定顺序展开 frontier。不得同时处理不同深度的节点。

同一父节点内部直接复用既有横向分支的窗口、阶段 worker 和端点并发策略；本方案不额外引入新的横向并行模型。候选计划的领取顺序、重复登记和边界配额登记必须保持确定性。

第一阶段中，同一样本的不同 frontier 节点按生成顺序串行处理。只有实现原子化的全样本题目哈希登记、分层配额登记和可恢复账本后，才能并行多个 frontier 节点。

## 11. Memory、恢复与系统保护

纵向搜索不改变 Memory 的业务准入、字段或写入时机。每个完成原有闭环的节点继续按原有机制处理 Memory，且不得使用 `review_status` 或路径深度改变业务判断。

恢复时使用 `node_id` + `memory_type` 作为技术幂等键，避免中断恢复时重复追加。每次节点路由必须记录节点执行顺序、算子计划、Memory 快照和搜索配置，避免 Memory 对后续路由的顺序效应不可追溯。

恢复顺序应验证：

1. 搜索状态和 manifest；
2. 节点、边和算子尝试记录；
3. 完成节点的完整评测产物；
4. Memory 幂等提交；
5. 未完成 frontier 的下一可执行阶段。

以下系统保护独立终止样本，不得伪装为算子耗尽：

- `request_budget_exhausted`；
- `evaluation_budget_exhausted`；
- `timeout`；
- `fatal_error`；
- `state_recovery_failed`。

## 12. 指标与人工审核

样本级指标：

- 输入样本数、进入纵向搜索样本数；
- 平均完成深度、评分节点数和 frontier 数；
- 单算子边界候选数、叠加边界候选数和总边界候选数；
- 正常终止与系统保护终止分布；
- 请求数、评分次数、运行时间和每条边界路径成本。

算子与组合指标：

- 单算子调用数、校验通过率、评分完成率和边界命中率；
- 有序二元组合出现次数与边界命中率；
- 同一无序组合的反向顺序对比；
- `no_score_change`、`score_increased`、`not_applicable`、`duplicate_exhausted` 比例；
- 平均 `edge_delta_score_rate` 与平均 `root_delta_score_rate`。

人工审核验证题目是否保持原始能力轴、参考答案与 Rubric 是否稳定、Score Prompt 与 Judge 是否可信，以及候选模型失分是否真实体现目标能力边界。

## 13. 兼容与实施顺序

`single_branch` 和 `multi_operator_branch` 的数据语义及输出保持不变。纵向字段放入独立结构，例如 `vertical_search_state`、`operator_stack`、`frontier_status` 和 `boundary_path`。

建议实施顺序：

1. 定义纵向状态、节点、边、路径、分层配额和稳定恢复键；
2. 支持 `multi_operator_vertical_stack` 模式；
3. 实现根节点横向搜索结果到深度 2 frontier 的转换；
4. 实现 frontier 重画像和 `frontier_route`，确保不重复原始准入否决；
5. 实现路径内算子过滤、全树精确去重和一次重复重试；
6. 实现深度 3 横向分支与直接父子比较；
7. 实现分层配额、总硬上限、摘要与人工审核产物；
8. 接入节点级 Memory 幂等、断点恢复和系统保护；
9. 增加三种搜索模式的兼容回归测试；
10. 先用 `max_depth=2` 验证根节点兼容、ID、去重和恢复，再用 `max_depth=3` 执行正式两算子实验。

## 14. 验收标准

1. 纵向模式可独立开启，且不改变单分支和横向多分支行为；
2. 只有通过原始准入的根节点进入纵向搜索；
3. 深度 2 frontier 会重新画像并重新路由，不继承根节点 `operator_plan`；
4. frontier 不会因重复原始样本准入否决而被错误透传；
5. 路径内默认不重复使用同一算子；
6. 每个通过原有校验的候选都完成原有评测闭环；
7. 所有边只按直接父子分数判定，根累计分数只用于分析；
8. 深度 2 降分节点可扩展，深度 3 节点永不扩展；
9. 单算子和叠加边界各自最多 5 个，总数最多 10 个；
10. 分数不变、上升、校验失败、重复耗尽、不适用和错误分支不进入 frontier；
11. 全树精确重复检查、一次重试、稳定 ID、Memory 幂等和断点恢复均可验证；
12. 搜索摘要可区分层级配额终止、算子耗尽和系统保护终止；
13. 单算子、两算子有序路径及其完整评测证据可供人工审核。

## 16. 最终原则

纵向算子叠加只改变搜索形态，不改变评测契约。在线阶段以"通过原有校验且相对直接父题降分"作为继续探索的证据；人工审核才决定候选边界是否最终有效。第一阶段用两算子、三层树、分层配额和稳定调度建立可控、可恢复、可审计的组合边界实验数据。
