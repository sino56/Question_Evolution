# 四大场景算子不足与扩展方向分析

## 1. 分析范围与结论摘要

本文结合以下两份资料，并对当前 O10--O18 的 Prompt 合约和路由实现进行了交叉核对：

- `data/四大场景测试样本.jsonl`
- `data/四类视频研判场景下的算子与问题进化评估报告.md`

核心结论是：当前瓶颈不是“算子数量不够”，而是算子边界重叠、适用性判断缺失、路由偏置和效果归因不稳定。现阶段应先修正这些基础问题，再优先补充多跳证据图、实体同一性、时序因果、累积证据、协同关系和跨模态结论上限等能力。

## 2. 两份资料的口径差异

两份资料并不是同一批样本：

- `四大场景测试样本.jsonl` 包含 27 条题目。
- 评估报告分析的是 19 条“拉车门盗窃、涉黄网络直播与居民楼窝点、电动车盗窃、笑气线索研判”样本。
- 两边只有样本 `3564` 重合，其余 26 条和 18 条样本互不重合。

因此，报告中的分数不能直接视为 27 条原始题目的测试结果。更合理的使用方式是：

- 将 19 条实验集用于判断已有算子实际产生了什么效果。
- 将 27 条原始题用于观察更广泛的视频研判任务还需要哪些能力。

此外，当前 `四大场景测试样本.jsonl` 使用中文弯引号，并不是严格的标准 JSONL，项目中的标准 JSON 解析器无法直接读取。如果后续需要正式接入流水线，应先将其规范化为合法 JSONL。

## 3. 实验结果反映出的总体问题

57 次真正完成重新评分的进化中：

- `effective_boundary_probe`：5 次，占 8.8%。
- `score_increased`：25 次，占 43.9%。
- `needs_manual_review`：13 次，占 22.8%。
- `no_clear_effect`：11 次，占 19.3%。
- `full_score_no_drop`：3 次，占 5.3%。

这说明当前算子最常见的失败不是“生成不出来”，而是把题目改得更明确、更窄、更容易回答。真正产生初步有效信号的只有：

- O10：2 个单样本信号。
- O13：2 个单样本信号。
- O16：1 个单样本信号。

这些信号仍然只是自动或中置信度证据，不能视为稳定验收结果。19 条样本中最终只有 5 条停在 `effective_boundary_sample`，其余 14 条达到最大轮数仍未收敛。

## 4. 当前算子的主要不足

### 4.1 O10 语义过宽，实际上成为通用兜底

O10 将实体同一性、轨迹连续性、证据充分性和结论层级都装入“近似判断竞争”。Round 1 的 17 次实际进化全部使用 O10，但 21 次重新评分的平均得分变化只有 -0.009，其中还有 8 次升分。

问题不在于 O10 完全无效，而在于它实际上包含了至少三个不同能力：

1. 两段镜头中的人、车、物是否为同一实体。
2. 人、物、车、动作和路线是否形成连续链。
3. 已有可见事实最多能支持到什么结论层级。

这三类任务需要不同的事实槽位、反事实方式和验收条件，不能继续共用一个通用兜底 Prompt。当前 `operator_router.py` 在无法匹配诊断词时仍默认选择 O10，这会持续掩盖真正的路由效果。

### 4.2 算子体系过度依赖“单事实翻转”

O10、O13、O15 都倾向于改变、替换或删除一个事实。但四类场景中的很多真实难点是多个弱证据共同闭合，例如：

- 人、物、车、路线之间的多跳关系。
- 多次出现形成的稳定模式。
- 同步、等待、观察、汇合共同支持协同关系。
- 准备、交付、销售、成分等多个相邻命题之间的边界。

这类任务不是寻找一个“决定性事实”，而是判断证据图是否连通、不同证据边是否独立，以及缺少某条边后具体哪个子结论失效。当前单变量算子难以稳定表达这种推理结构。

### 4.3 缺少明确、机器可读的结论阶梯

视频研判通常存在如下结论层级：

```text
观察到行为
-> 存在时空关联
-> 存在稳定关系
-> 支持某种意图或角色
-> 支持违法性质或身份定性
```

当前算子虽然频繁使用“层级”“门槛”等描述，但没有稳定传递以下结构化信息：

```text
target_claim
current_claim_level
max_supported_claim
forbidden_claim_upgrade
fact_to_subclaim_edges
```

因此，生成题容易把“可见搬运”上推为“物品所有权”，把“共同出现”上推为“同伙分工”，或者把“气瓶外观”上推为“笑气成分”。

### 4.4 路由依据是诊断关键词，不是事实适用条件

当前 router 主要根据“盲区、基线、处置、正常解释、反事实”等诊断文字命中算子，无法保证题面真正具有对应算子所需的事实条件：

- O11 需要进入端点、离开端点、历史通行时长和可比较的未出现事实。
- O17 需要真实、明确的业务规则或处置阈值。
- O18 需要两个同域、口径明确的统计基线以及一个可比较观测。

实验中 126 条候选有 41 条为 `not_applicable`，占 32.5%，说明适用性判断发生得太晚，而且未适用候选仍然消耗了候选席位。

### 4.5 O14 的职责仍然混乱

评估报告已经判断 O14 应当是所有候选共用的信息闭包 lint，而不是独立出题算子。但当前代码仍然：

- 将 O14 注册在生成算子集合中。
- 允许 router 将 O14 选为 primary 或 backup。
- 为 O14 定义独立的题目生成形态。

这会混淆“生成成功、透传、未适用、闭包校验通过”四种不同状态。O14 更适合移动到候选生成后、候选选择前，统一检查题外补设、事实越界和信息闭包问题。

### 4.6 当前代码与报告描述的实验 Prompt 存在漂移

报告描述的生成策略是不向生成模型暴露候选答案、原 rubric、诊断文字和路由理由。但当前 `prompts/operators/base.py` 实际传入了：

- `sample_profile`
- `overscore_diagnosis`
- `operator_route`
- `candidate_answer`
- 原始 `rubric`

当前 Prompt 还要求：如果 operator 不适合样本，仍要强行在该 operator 范围内收窄问题。这与报告中大量 `not_applicable` 的实验合约不一致。

因此，报告结果未必能由当前代码直接复现。后续实验前需要统一实际运行 Prompt、报告描述和代码版本，避免将不同 Prompt 合约下的结果混在一起解释。

### 4.7 候选校验只检查形式，没有验证目标推理负荷

现有校验可以拒绝题目过长、多任务、多反事实、重复题型和题外知识，但无法判断候选是否真的迫使模型完成算子声称的推理。

67 条真正生成的候选中只有 4 条被形式规则拒绝，但 57 条被选中并重新评分的题目中有 25 条升分。这说明“格式合法”与“能力轴有效”之间存在明显断层。

候选选择至少需要增加以下离线资格诊断：

- 关键事实删除后，目标结论是否变为不可唯一确定。
- 反事实前后的答案是否一致翻转或按预期降级。
- 干扰项是否在主体、时段、行为和表面长度上平衡。
- 强模型是否仍可基于题面事实稳定回答。
- 固定回答在新旧 rubric 下是否具有可解释的区分度。

### 4.8 得分变化不能完全归因给算子

题目进化后会重新生成参考答案、rubric、候选回答并重新评分，因此一次 score drop 可能来自：

- 题目确实压中了目标能力边界。
- 新 rubric 更严格。
- 回答采样波动。
- judge 波动。
- 题目发生了任务漂移。

正向 operator memory 不应只依赖一次自动 effect。至少应要求重复回答、双 judge 或人工复核一致。失败 memory 也应区分：

```text
not_applicable
generation_violation
no_gain
score_increased
scoring_unreliable
task_drift
```

## 5. 结合 27 条原始题看到的能力缺口

### 5.1 跨镜头实体连续性

原始题中包含断点后同一人确认、换装后的身份连续性、车辆与人员关联、随身物品变化等任务。这些任务需要同时处理：

- 支持同一性的证据。
- 支持不同实体的冲突证据。
- 替代候选是否被排除。
- 即便不能确认同一实体，仍能保留什么较低层关系结论。

这不是当前 O10 的普通结论强弱比较。

### 5.2 盲区与时序异常

27 条数据中存在适合 O11 的专门样本，包括：

- 老人进入盲区后正常穿过还是发生意外。
- 车辆进入盲区长时间停留后返回主路。
- 老人正常外出未归还是在住所内发生意外。

因此，O11 不应删除。报告中 O11 全部不适用，主要说明那 19 条实验样本没有真正满足其前置条件，而不是 O11 所代表的能力没有价值。

### 5.3 竞争行为机制与因果归因

原始数据大量涉及：

- 攻击还是防卫。
- 破坏进入还是利用未拔钥匙。
- 主动放弃还是受干扰逃离。
- 意外脱缰还是故意放任。
- 正常撤离还是收钱后的条件性撤离。

这类任务的关键不是单事实反转，而是比较两个竞争机制在“触发事件、动作节奏、中间状态、结果”上的不同预测。当前 O13 和 O15 只能局部覆盖。

### 5.4 协同关系与偶然共现

接力丢弃、船只等待、同伙伴随、扒窃配合、暗中接应等问题，都要求区分：

- 同时出现。
- 时间同步。
- 行为响应。
- 路线汇合或分离。
- 重复模式。
- 是否存在可替代的偶然解释。

单独删除一条关系边往往不足以完成判断，需要分析多条弱边是否共同形成协同结构。

### 5.5 技术操作类样本与业务研判算子不完全同域

27 条数据还包含坐标测量、人像标志点与标志线等技术操作题。这类题更偏操作规范、测量误差和步骤完整性，与 O10--O18 的“视频事实到业务结论边界”并不完全同域。

如果后续仍要覆盖此类样本，应单独建立技术流程类算子池，例如：

- 操作步骤依赖关系。
- 测量误差传播。
- 关键步骤遗漏诊断。
- 现场记录与软件输入一致性。

不宜将其强行路由到证据层级或反事实判断算子。

## 6. 建议新增或拆分的算子方向

### 6.1 P1：多跳链路闭合

建议作为 O19 方向。

能力目标：判断人、物、车、动作、时间、镜头和路线等多条候选边能否共同闭合，以及删除某条关键边后具体哪个子结论失效。

适用样本包括 `23904`、`17815`、`34455`，以及原始题中的接力丢弃、视频关联取证和跨点位追踪任务。

必要验收条件：

- 题面至少包含两跳关系。
- 删除关键边后目标结论不可唯一确定。
- 不能从可见转运直接上推所有权、违法性质或身份。

### 6.2 P1：实体同一性冲突消解

建议作为 O20 方向，并将“排他性候选消除”纳入该算子，而不是再单独增加一个算子。

能力目标：围绕两段或多段镜头中的人、车、物，同时提供支持同一与支持不同的近强度事实，要求判断能否合并实体，以及当前证据最多支持到什么结论。

适用样本包括 `28996`、`30155`、`34176`，以及原始题中的监控断点、换装、随身物品变化和车辆伴随关系。

需要防止：

- 将外貌相似、颜色相同或单一携带物直接视为同一性确认。
- 只列支持同一的事实，不提供真实可行的替代候选。
- 将“高概率同一”改写成绝对身份确认。

### 6.3 P1：时序因果机制竞争

这是 27 条原始数据额外揭示出的高优先级方向，可作为 O25 候选。

能力目标：给出两个都能解释表面结果的竞争机制，通过触发事件、动作顺序、反应延迟、中间状态和退出方式判断哪个机制得到更强支持，以及哪些结论仍不可确定。

适用任务包括：

- 攻击与防卫。
- 破坏进入与利用未拔钥匙。
- 主动放弃与受干扰逃离。
- 意外脱缰与故意放任。
- 偶然撤离与条件性撤离。

它与 O15 的区别是：O15 只改变一个变量观察结论迁移；该算子比较的是两个机制对完整时序的不同预测。

### 6.4 P1：观测可靠度与累积证据

建议作为 O22 方向。

能力目标：保持事件本身不变，只调整可见度、遮挡、重复次数、时间同步误差或证据来源独立性，判断结论可以达到的层级。

适用样本包括 `18436`、`30470`、`21725`，以及原始题中的盲区时长、低清画面、连续动作和重复观察任务。

该算子不能伪造业务统计阈值，而应比较：

- 单次观察与重复观察。
- 同源重复与独立来源印证。
- 清晰连续与遮挡断续。
- 时间严格同步与仅大致相邻。

### 6.5 P2：角色与协同关系图

建议作为 O23 方向，同时包含“角色最小边”和“协同与偶然共现”两个受控子模式。

能力目标：针对组织、协助、望风、接应、普通出现等角色，明确哪些关系边只支持共现，哪些支持同步响应，哪些才能支持角色或分工判断。

适用样本包括 `24804`、`35211`，以及原始题中的接力丢弃、扒窃配合、车辆伴随、船只等待和赎金交付接应任务。

如果后续实验发现“角色边删除”和“多信号累积协同”表现差异很大，再考虑拆成两个独立算子；初期不宜过度细分。

### 6.6 P2：多假设判别观测

建议作为 O21 方向。

能力目标：保持两个或三个合理解释同时可行，要求选择一个最能减少不确定性的新观测，而不是直接要求模型定性。

适用样本包括 `27965`、`35211`、`32575`，以及普通往返与补货、社会车辆偶然同路与同伙伴随等任务。

该算子应成为 O16 的上位补充：O16 预设一个正常解释，O21 不预设正常或异常方向，而是比较观测的判别力。

### 6.7 P2：跨模态结论上限

建议作为 O24 方向。

能力目标：显式标注视频、信号、时间、物品外观和外部记录的来源，判断单源与融合后分别能支持的最大结论，并处理不同来源之间的冲突。

适用样本包括 `32575`、笑气物品识别类样本，以及原始题中的车辆、通信、卡口和现场视频联合研判任务。

需要重点防止：

- 将多源融合自动等同于高层定性成立。
- 用物品外观确认具体成分。
- 用信号范围直接确认具体人员角色。
- 用时空接近直接确认因果或同伙关系。

### 6.8 专项池：保留 O17 与 O18，但限制数据入口

O17 和 O18 不应删除，但不适合当前四类视频事实发现集：

- O17 需要真实业务规则、处置规则或明确阈值。
- O18 需要有口径、样本量、纳入条件和范围说明的统计基线。

没有这些字段时，两者不应进入 primary、backup 或覆盖率统计。应分别迁入规则型数据池和统计基线型数据池做专项资格测试。

## 7. 建议的改造顺序

### 第一阶段：先修基础能力，不增加算子数量

1. 为每个算子定义机器可读的适用条件和事实槽位。
2. 将 O14 移为全局信息闭包 lint。
3. 去掉 O10 的通用 fallback，将其拆成实体、链路和结论上限三个路由方向。
4. 统一报告、实际运行 Prompt 和代码中的算子合约。
5. 将生成、透传、未适用、校验失败、无增益、升分和评分不可靠定义为互斥状态。
6. 给候选增加关键事实消融、反事实一致性和任务漂移诊断。

### 第二阶段：开展离线资格测试

优先测试：

1. 多跳链路闭合。
2. 实体同一性冲突消解。
3. 时序因果机制竞争。
4. 观测可靠度与累积证据。

每个算子应使用 8--12 条真正满足前置条件的样本，并采用：

- 父题与子题成对比较。
- 每题生成多个候选。
- 多次回答采样。
- 双 judge 或人工复核。
- 固定能力轴和可审计的关键事实消融。

需要分别报告：

```text
applicability_rate
generation_valid_rate
effective_boundary_rate
score_increased_rate
manual_confirmation_rate
answer_variance
judge_variance
task_drift_rate
```

### 第三阶段：资格通过后再进入主 router

不要一次性将 O19--O25 全部注册到线上 router。只有满足以下条件的算子才应进入主流程：

- 适用条件可以由结构化字段判断。
- 在适用样本上具有稳定生成成功率。
- 升分率得到控制。
- 自动命中经过人工或双 judge 确认。
- 失败可以归因到具体表层形态，而不是粗粒度惩罚整个算子。

## 8. 最终判断

本轮实验是有价值的发现实验，但不是算子有效性验收。它说明现有体系能够在少数连续绑定、最小推翻和相近解释样本上压出模型错误，同时也暴露出四个更根本的问题：

1. 数据与算子前置条件不匹配。
2. O10 路由过度集中。
3. 候选有效性主要停留在形式校验。
4. 自动 effect 尚不足以稳定归因和写入 memory。

下一步不应优先扩写通用的“让题更难”Prompt，而应先完成适用性预检、状态分类、O10 语义拆分、O14 职责迁移以及 O13/O16 的受控资格测试。在此基础上，再用多跳链路、实体解析、时序因果、多假设判别、观测可靠度、关系图和跨模态算子补齐视频研判场景真正缺失的能力。
